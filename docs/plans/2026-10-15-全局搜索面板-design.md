# 全局搜索面板（⌘K）设计方案

> 日期：2026-10-15 ｜ 状态：已实施
> 关联：`docs/plans/2026-10-14-settings-modal-design.md`（全局 Modal + store 单点开合的架构模板）、`src/store/vehicleStore.ts`（`pendingAnnounceNoFilter` 一次性跳转信号先例）、`src/components/ParameterWorkbench/AssetPool/useAssetPoolHotkeys.ts`（⌘K 现占用处）
> 领域术语见 `CONTEXT.md`（资产 / 公告记录 / 法规标准）。

## 1. 背景与问题

应用有 8 个顶级页面、三类核心数据（车型资产、公告记录、法规标准），各页自带筛选/搜索，但都只在自己页面内生效。用户在任意页面想查一条数据（某个公告号、某个标准号、某台车），必须先知道它在哪个页面、切过去、再在那个页面的搜索框里输入——入口分散、心智负担高。

需要一个全局统一入口：任意页面按 ⌘K 唤起搜索面板，跨域查询，选中后跳到目标页面并预填该页的既有搜索逻辑。

## 2. 目标与非目标

### 目标

1. ⌘K / Ctrl+K 在任意页面唤起全局搜索面板，Esc 关闭，↑↓ 选择，Enter 确认
2. 覆盖三域：车型资产、公告记录、法规标准
3. 选中结果 → 跳转目标页面 + 预填该页搜索框，由页面既有列表逻辑呈现全部命中
4. 空查询显示三域数量统计；某域未配置/未加载时降级为灰字提示，不阻塞其他域

### 非目标

- 拼音/首字母检索
- 参数行级全文检索（资产参数值、公告参数集内容）
- 面板内预览或直达实体详情
- 页面导航模式（空查询列出页面项）——后续可低成本扩展
- Rust 侧新增搜索 command 或建立索引（三域数据为数百级，前端内存线性过滤足够）
- Web Worker 化

## 3. 设计

### 3.1 决策记录

| 问题 | 决定 | 理由 |
|---|---|---|
| ⌘K 与资产池已有绑定（聚焦池内搜索框）冲突 | 面板独占 ⌘K，删除池内该绑定 | 与 Spotlight / VS Code 心智一致；池内聚焦搜索仍可由全局 ⌘F 覆盖 |
| 数据域范围 | 资产 + 公告 + 法规三域 | 用户点名；词表/操作入口留待后续按需扩展 |
| 选中行为 | 跳页 + 预填目标页搜索框 | 改动最小、行为可预期，复用 pending 信号先例 |

### 3.2 交互与入口

- **全局 ⌘K / Ctrl+K** 唤起居中面板；资产池内原「⌘K 聚焦搜索框」绑定删除（MainLayout 已有全局 ⌘F 找搜索框逻辑，聚焦能力不丢失）
- 面板：AntD Modal（`centered`，无 footer，宽度约 640px）+ 顶部输入框 + 分组结果列表，风格对齐设置面板
- 键盘：↑↓ 移动选中项、Enter 确认、Esc 关闭；鼠标可点选
- **空查询**：显示提示「输入关键字搜索资产 / 公告 / 法规」+ 各域当前数量（如「车型资产 312 · 公告记录 89 · 法规标准 76」）
- **有查询**：结果按域分组（车型资产 / 公告记录 / 法规标准），每组最多 5 条 + 组尾「在 XX 中查看全部 N 条」项（Enter 该项同样跳页+预填，由目标页既有列表呈现全部命中）

### 3.3 数据与匹配

新增 `src/utils/globalSearch.ts`：三域 provider 纯函数 + 统一打分，输入领域数据数组与关键字，输出带分数的命中列表。放 utils 便于直测。

| 域 | 检索字段 | 数据来源（面板打开时才拉取） |
|---|---|---|
| 车型资产 | 组名/文件名、产品名、别名、标签、公告号、主机厂 | `useAssetLibrarySnapshot` 快照（复用既有缓存，未缓存则触发一次扫描） |
| 公告记录 | 公告号、车型名、批次 | `announcementStore.loadFor(资产库路径)`（同路径复用缓存） |
| 法规标准 | 标准号、名称、主题域 | `regulationStore`（触发一次 `scan_regulations`） |

- 匹配：小写 substring；打分 = 精确命中 100 > 前缀命中 60 > 包含命中 30，同分按更新时间（资产）/ 公告号（公告）/ 标准号（法规）排序
- 公告号/标准号匹配前做归一化（去空白、大写）——与公告中心既有 `normalizeAnnounceNo` 同口径
- 面板打开才拉数据、关闭不拉；输入防抖 150ms；结果行 React.memo，避免每键全列表重渲

### 3.4 跳转信号

复用 `vehicleStore.pendingAnnounceNoFilter` 的一次性信号模式，泛化为通用跳转信号 `pendingGlobalSearch: { tab, keyword } | null`：

1. 面板选中项写入 `pendingGlobalSearch` 并关闭面板
2. App 层 effect 消费：`handleTabChange(tab)` + 把 keyword 递给目标页
3. 目标页用小 effect 接收并写入自己的搜索框状态，消费后清空信号

三处落点：

- **资产池**：预填 `searchKeyword`（AssetFilterBar 受控值）
- **公告中心**：预填公告号查询输入框
- **法规标准**：预填法规搜索框

### 3.5 文件与结构

新增逻辑全部独立文件，不堆热点文件（AGENTS.md 纪律）：

```
src/components/GlobalSearch/GlobalSearchModal.tsx        # 面板 UI（常驻挂载 MainLayout，对齐 SettingsModal 模式）
src/components/GlobalSearch/useGlobalSearchHotkey.ts     # ⌘K 监听（照 useSettingsHotkey 体例）
src/store/globalSearchStore.ts                           # isOpen / query，不持久化
src/utils/globalSearch.ts                                 # 三域 provider + 打分（纯函数）
src/utils/__tests__/globalSearch.test.ts
src/components/GlobalSearch/__tests__/GlobalSearchModal.test.tsx
```

改动文件：`MainLayout.tsx`（挂载面板）、`useAssetPoolHotkeys.ts`（删除 ⌘K 绑定及速查表对应条目）、`vehicleStore.ts`（pending 信号）、三个目标页各加一个「接收预填」的小 effect、`App.tsx`（消费信号）。

### 3.6 边界与错误处理

- 法规库未设路径 / 资产库未设：对应组显示「法规库未配置」/「资产库未配置」灰字，不阻塞其他域
- 三域加载独立进行，单域失败不影响整体（各自 catch 降级）
- 面板打开时输入框自动聚焦；再按 ⌘K 不重复叠加
