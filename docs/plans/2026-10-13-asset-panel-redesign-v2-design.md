## 1. 背景与问题

### 1.1 用户反馈

V1 布局（2026-10-01 实施）解决了「整页滚动」「右栏购物车被卷走」「操作埋太深」等结构问题，但用户试用后仍反馈：

- **找车费劲**：筛选区、视图切换、标签、按钮太多，一眼找不到重点
- **挑进工作集不顺**：点选/激活/聚焦几个状态容易混，选中后不够明显
- **操作埋得深**：高频操作要右键或进检查器
- **界面太丑**：视觉不够精致，缺少现代工具的细腻感

### 1.2 根因分析

V1 的核心问题是**「功能优先，体验其次」**：

1. **信息层级混乱**：筛选区（facet/公告号/标签/搜索）+ 视图切换 + 状态开关全堆在顶部，视觉负担重
2. **主任务路径不清晰**：用户最高频任务是「挑几台车去对比/填报」，但 V1 把治理功能（标签管理/版本链/命名检查）和挑选功能混在同层级
3. **选中态弱**：已选行只靠 3px 左色条（`edge-success`），在长列表里不够显眼
4. **视觉粗糙**：沿用早期深色主题，缺乏现代工具（Notion/Linear）的细腻阴影、微动效、清晰层级

### 1.3 用户画像与主任务

**用户画像**（2026-10-13 brainstorming 确认）：
- 主任务 = **挑几台车去对比/填报**（短链路）
- 找车方式 = **按主机厂/族群顺藤摸瓜** + **直接搜名字**
- 视图使用 = **经常切换**（车型/主机厂/族群/平铺 4 种都会用）
- 治理场景 = 快速筛选关键车型、命名问题、版本问题、待补全等**某一类车**

**关键洞察**：
- 挑选场景 vs 治理场景是**两种不同心智模型**：前者是「找特定某台车」，后者是「找某一类车」
- 现有设计把两种场景混在一起，导致界面复杂
- 需要**分层**：快速导航（找特定车）vs 治理视角（找某类车）

## 2. 设计目标

1. **主任务路径最短**：挑车 → 激活 → 去对比，三步内完成
2. **找车效率高**：主机厂/族群导航 + 搜索框触手可及，facet 精筛不挡路
3. **选中态清晰**：已选车辆一眼可辨，不与焦点态混淆
4. **视觉现代化**：浅色极简风格，细节精致（微动效、柔和阴影、清晰层级）
5. **治理场景便捷**：一键切入「关键车型」「命名问题」「版本问题」等预置筛选

### 3.2 三栏职责

| 栏 | 宽度 | 职责 | 内容 |
|---|---|---|---|
| 左栏 | 240px 固定 | 导航与预置筛选 | 快速导航（主机厂/族群树）+ 治理视角（关键车型/命名问题等）+ 工具入口 |
| 中间主区 | 弹性 | 浏览与挑选 | 顶部筛选条（搜索+facet）+ 车型卡片列表 |
| 右栏 | 300px 固定 | 工作集管理 | 已选车辆列表（购物车）+ 去对比 CTA |

### 3.3 与 V1 的关键差异

| 维度 | V1（2026-10-01） | V2（本方案） |
|---|---|---|
| 骨架 | 两栏（左列表 + 右摘要卡+购物车） | 三栏（左导航 + 中列表 + 右购物车） |
| 筛选位置 | 顶部折叠面板（facet+公告号+标签） | 顶部横条（搜索+facet chip）+ 左栏导航/治理视角 |
| 视图模式 | 4 种视图切换（车型/主机厂/族群/平铺） | 废弃视图切换，改为左栏导航树（主机厂/族群并列展开） |
| 摘要卡 | 右栏上段（点选刷新） | 移除（点卡片只改选中态，不刷新摘要卡） |
| 选中态 | 3px 左色条（`edge-success`） | 左侧 3px 蓝条 + 整卡浅蓝背景 |
| 治理入口 | 顶部工具栏（体检按钮）+ 提醒条 | 左栏「治理视角」预置筛选（关键车型/命名问题/版本问题/待补全/历史/废弃） |
| 视觉风格 | 深色（曜蓝 Obsidian Blue） | 浅色极简（Notion/Linear 风格） |

## 4. 各区块规格

### 4.1 左栏（240px）

**结构**（自上而下）：

1. **快速导航**
   - 主机厂（可展开/折叠）：显示所有主机厂，带计数
   - 车型族群（可展开/折叠）：显示所有族群，带计数
   - 点击某个主机厂/族群 = 应用该筛选条件（等价于在顶部 facet 勾选）

2. **治理视角**（预置筛选）
   - ⭐ 关键车型（筛选带 `关键车型` 标签的资产）
   - ⚠️ 命名问题（筛选命名不规范的资产）
   - 🔀 版本问题（筛选版本链未收敛的车型组）
   - 📝 待补全（筛选受控属性缺失的资产）
   - 🕘 历史版本（筛选 `status=superseded` 的资产）
   - 🚫 已废弃（筛选 `status=deprecated` 的资产）
   - 每项带计数，点击 = 一键应用对应筛选

3. **工具**
   - 📁 导入（打开文件管理器导入资产）
   - 🔄 刷新（强制刷新资产库扫描）
   - 📋 治理体检（打开治理体检弹窗）
   - ⚙️ 设置（更换资产库目录等）

**交互**：
- 点击导航项/治理视角项 = 应用筛选，该项高亮（浅蓝底 + 左侧 3px 蓝条）
- 再点一次 = 取消筛选
- 展开/折叠状态存 localStorage

**视觉**：
- 导航项 hover 时浅灰底
- 激活项浅蓝底 + 左侧 3px 蓝条 + 蓝色文字
- 计数用小号灰字，激活时变蓝色

### 4.2 中间主区

#### 4.2.1 顶部筛选条

**布局**：一行排列，横向滚动（如果空间不够）

```
[🔍 搜索框（flex-1）] [电量 ▾] [准入公告 ▾] [电池品牌 ▾] [标签 ▾] [状态 ▾] [清空]
```

**组件**：
- **搜索框**：占剩余宽度，placeholder = "搜名字/公告号/标签..."，支持文件名/产品名/公告号/标签模糊匹配
- **facet chip**：每个维度一个 chip，点击下拉显示可选值（复选）
  - 电量（数值区间：≥/≤ 双输入）
  - 准入公告（公告号列表，可多选）
  - 电池品牌（词表值列表，可多选）
  - 标签（自由标签列表，可多选）
  - 状态（最新版/历史/废弃/驳回，可多选）
- **清空按钮**：一键清除所有筛选条件

**交互**：
- chip 未激活时：灰底灰字
- chip 激活时（有选中值）：浅蓝底蓝字，显示选中数量（如 "电量 (2)"）
- 下拉面板：点击 chip 弹出，显示可选值列表（带计数），支持多选
- 筛选状态只活在会话内，重启清空（沿用现有约定）

#### 4.2.2 列表头

```
共 25 个资产 · 已选 2     [将筛选结果加入工作区 →]
```

- 左侧显示当前筛选结果的资产数与已选数
- 右侧「将筛选结果加入工作区」链接（沿用现有功能）：点击 = 把当前筛选结果全部激活进购物车

#### 4.2.3 列表头视图切换

```
共 25 个资产 · 已选 2     [车型分组 ▾] [将筛选结果加入工作区 →]
```

- 左侧显示当前筛选结果的资产数与已选数
- 中间「车型分组 ▾」切换：车型分组（按车型组折叠）/ 平铺（所有资产平铺）
- 右侧「将筛选结果加入工作区」链接

#### 4.2.4 车型卡片列表

**卡片结构**：

```
┌─────────────────────────────────────────────────────────┐
│ ▎帝豪EV 450                              [最新版] [⭐关键] [✓] │
│ ▎📊 完成率 92%  ⚠️ 缺必填 2              更新于 2024-03-15   │
└─────────────────────────────────────────────────────────┘
```

**元素**：
- **左侧 3px 蓝条**（选中态才有）：竖条，表示已选中
- **车型名**：加粗，14px
- **徽章**：
  - 最新版（蓝底白字）
  - ⭐ 关键（灰底灰字，带星号图标）
  - ⚠️ 命名不规范（黄底深黄字）
  - 历史（灰底灰字）
  - 废弃（灰底灰字）
  - 驳回（红底白字）
- **激活按钮**（右侧圆形按钮）：
  - 未激活：`+`，灰边灰字，hover 变蓝
  - 已激活：`✓`，蓝底白字
- **元信息行**：
  - 📊 完成率 92%（图标 + 百分比）
  - ⚠️ 缺必填 2（红色，仅在有缺失时显示）
  - 更新于 2024-03-15（右对齐，灰色小字）

**交互**（用户已确认）：
- **点卡片 = 选中**（切换选中态，右侧购物车不变化）
- **点激活按钮 = 激活/移出购物车**（切换激活状态）
- 双击卡片 = 打开资产检查器（沿用现有）
- 右键卡片 = 打开右键菜单（沿用现有，6 项封顶）

**选中态**（用户已确认）：
- 左侧 3px 蓝条
- 整卡浅蓝背景（`--brand-weak`）
- 边框变蓝

**视觉**：
- 卡片默认白底、1px 灰边框、圆角 8px
- hover 时边框变蓝、阴影加深、上浮 1px
- 选中时浅蓝底 + 左侧 3px 蓝条 + 蓝色边框

## 5. 交互流程

### 5.1 主任务：挑几台车去对比

1. **找车**：
   - 方式 A：左栏快速导航 → 点某个主机厂/族群
   - 方式 B：顶部搜索框输入关键词
   - 方式 C：顶部 facet chip 精筛（电量/准入公告等）

2. **浏览**：
   - 中间列表显示筛选结果
   - 卡片上直接看到完成率、缺必填、徽章（最新版/关键/命名问题）

3. **激活**：
   - 点卡片上的 `+` 按钮，车卡变 `✓`，右栏购物车多一张卡
   - 或点「将筛选结果加入工作区」批量激活

4. **去对比**：
   - 点右栏底部 "去对比 →" 按钮
   - 跳转到对比 tab，已选车辆自动填入

### 5.2 治理任务：批量处理命名问题车

1. **筛选**：
   - 点左栏「治理视角」→ "⚠️ 命名问题"
   - 中间列表只显示命名不规范的资产

2. **批量处理**：
   - 长按某张卡进入批量模式（沿用现有）
   - 勾选要处理的车
   - 批量打标签/重命名/标记状态

3. **返回**：
   - 再点一次 "⚠️ 命名问题" 取消筛选
   - 或点顶部 "清空" 按钮

### 5.3 查看某台车详情

1. **找到车**：搜索/导航/筛选
2. **双击卡片**：打开资产检查器抽屉（沿用现有）
3. **查看参数/完成度/必填缺失**：抽屉内分区块展示
4. **操作**：抽屉内可重命名/打标签/标记状态/删除等

## 8. 数据流

### 8.1 筛选状态

- **筛选状态**（searchKeyword + facetSelection + 治理视角选中项）放在 `AssetPoolLayout` 的 state
- 左栏导航/治理视角点击 → 更新筛选状态 → 中间列表重新渲染
- 顶部搜索框/facet chip 变化 → 更新筛选状态 → 中间列表重新渲染
- 筛选状态只活在会话内，不写 localStorage

### 8.2 选中态 vs 激活态

- **选中态**（focusedFile）：点卡片切换，只影响视觉（左侧蓝条 + 浅蓝底），不进 store
- **激活态**（activeAssets）：点激活按钮切换，写 `vehicleStore.activeAssets`，右栏购物车同步更新

### 8.3 治理视角筛选

治理视角是**预置筛选条件**，点击后转化为对应的筛选状态：

| 治理视角 | 转化的筛选条件 |
|---|---|
| 关键车型 | `tags.includes('关键车型')` |
| 命名问题 | `!validateAssetName(fileName, announceNos).valid` |
| 版本问题 | `governanceReport.unconvergedCars` 包含该车型组 |
| 待补全 | `fileFacets.get(fileName)` 有任一 facet 为 null |
| 历史版本 | `assetMeta[fileName]?.status === 'superseded'` |
| 已废弃 | `assetMeta[fileName]?.status === 'deprecated'` |

## 11. 评审提示

以下是从已定决策推导的补充，评审时重点看一下：

1. **视图维度切换的承载方式**：废弃 Segmented 控件（车型/主机厂/族群/平铺 4 选 1），维度切换能力不丢——「按主机厂/按族群」由左栏导航树承担（用户实测高频切换的正是这两个维度），「车型分组/平铺」由顶部列表头切换。理由是用户说"经常切换"指的是维度，而导航树比 Segmented 更直接（少一次点击）。
2. **移除摘要卡**：V1 的右栏上段摘要卡（点选刷新）移除，点卡片只改选中态（左侧蓝条 + 浅蓝底），不再刷新右栏。理由：选中态足够清晰，不需要额外摘要卡；右栏专注于购物车。
3. **治理视角预置筛选**：把 V1 的「只看关键车型」「显示废弃」开关 + 治理提醒条（版本链未收敛/命名不规范）全部收纳到左栏「治理视角」预置筛选，一键切入。
4. **浅色极简风格**：从深色（曜蓝）切到浅色（Notion/Linear 风格），理由是用户反馈"界面太丑"，浅色更符合现代工具审美。
