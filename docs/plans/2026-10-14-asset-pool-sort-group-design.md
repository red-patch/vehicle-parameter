# 资产池迭代 3：排序与同车型聚拢 — 设计方案

> 日期：2026-10-14 ｜ 状态：**待实施**
> 来源：迭代 2 真机试用后的反馈——「多列卡片下资产筛选是不是要支持排序？不然车型不好找」。
> 前置文档：`2026-10-13-asset-pool-redesign-v2-design.md`（V2 三栏）、`2026-10-13-asset-pool-fluid-iter-design.md`（迭代 2 流体布局，已实施）。
> 视觉基准：曜蓝 v4.1（`docs/design-v4-obsidian-blue/`）。

## 1. 背景与问题

迭代 2 的多列流体网格上线后，用户反馈「车型还是不好找」。截图对照后坐实**两层根因**：

### 1.1 无显式排序

列表默认按「更新时间倒序」（V1 遗留口径），但：
- 界面**不显示**当前排序维度（用户不知道这个隐藏规则）；
- **无法更改**——想按名称找车、按完成率挑参数最全的，都做不到。

### 1.2 同车型版本被打散（主因，多列放大）

截图实例：`远程V6E` 出现在第 2、3、4…多张卡，`远程V8E`、`H8E`、`VE21` 同样散落。**多列网格按行优先阅读**（左→右→换行），同一车型的多个版本因此散落在不同行不同列——要找一个车型得把整屏扫一遍。

**结论**：多列把"平铺排序"的缺陷放大了。"车型不好找"的主因不是排序维度缺失，而是**同车型不聚拢**。

## 2. 目标形态

```
列表头：
共 83 个资产 · 已选 5          [排序：名称 ▾] [聚拢 ▾ 开]   将筛选结果加入工作区 →

聚拢开启时（默认）：
┌─远程V6E────────┐ ┌─远程V6E────────┐ ┌─远程V8E────────┐
│ 2026/9/21      │ │ 2026/6/29      │ │ 2026/9/21      │
└────────────────┘ └────────────────┘ └────────────────┘
   ← 同车型所有版本相邻 →            ← 下一个车型 →
┌─远程V8E────────┐ ┌─H8E───────────┐ ┌─H8E───────────┐
└────────────────┘ └────────────────┘ └────────────────┘
```

一句话：**同车型版本聚拢相邻（默认开），组间与组内按用户选的维度排；排序维度显式可见可改。**

## 3. 详细设计

### 3.1 排序维度（4 个，用户已确认）

列表头新增「排序」下拉（`Popover`，与筛选 chip 同款），4 个维度：

| 维度 | 排序依据 | 默认方向 | 用途 |
|---|---|---|---|
| **名称（拼音）** | 车型显示名的拼音序（`localeCompare('zh-Hans-CN')`） | 升序 | 知道名字时定位 |
| **完成率** | `filledParams / totalParams` | 降序（高的在前） | 找参数最全的 |
| **参数数 / 缺必填** | 参数总数（次判据：缺必填数升序） | 降序 | 找信息最全的 |
| **时间** | `updatedAt` | 降序（新的在前） | 现状默认 |

- 每个维度可切换升/降序（下拉里点维度即选，再点切方向；或维度行内置 ⬆⬇ 图标）。
- **默认维度 = 时间倒序**（保持 V1/V2 现状，用户无感迁移）。
- 持久化 `localStorage['asset-pool-sort']`（形如 `{"dim":"updatedAt","dir":"desc"}`）。

### 3.2 同车型聚拢（默认开）

- **分组键**：复用 `resolveVehicleGroupKey(info, meta, brandNames)`（治理报告同款口径，与"车型组"概念一致）。
- **聚拢逻辑**：
  1. 先按分组键把 `filteredInfos` 分桶；
  2. 桶之间按选定维度排序（桶的代表值 = 桶内最优，如完成率取桶内最高）；
  3. 桶内按选定维度排序（同维度，保证组内也符合预期）。
- **组内视觉分隔**：聚拢开启时，同组卡片之间**不额外加分隔标记**（保持简洁）；组与组之间靠排序自然断开即可。**可选增强**（不在本轮）：组首卡片加车型组名小标题。
- **开关键**：列表头「聚拢」开关（`Segmented` 或 Tag 开关风格），持久化 `localStorage['asset-pool-group-adjacent']`，默认 `'1'`。
- **关闭时**：回到纯平铺排序（当前行为）。

### 3.3 与筛选/治理视角的关系

- 排序与聚拢**只作用于筛选后的结果**（`filteredInfos` 的排序阶段），不影响筛选逻辑。
- 与「治理视角」不冲突：治理视角是筛选（选哪些车），排序/聚拢是组织方式（怎么排）。

### 3.4 与左栏导航的关系

左栏「主机厂/族群」是**筛选**（选出一个子集），不参与排序——不复制导航语义到排序里。

## 4. 决策一览

| # | 决策 | 要点 |
|---|---|---|
| 1 | 排序维度 4 个 | 名称（拼音）/ 完成率 / 参数数·缺必填 / 时间；默认时间倒序 |
| 2 | 同车型聚拢 | 默认开；复用 `resolveVehicleGroupKey`；桶间 + 桶内两级排序 |
| 3 | 显式可见 | 排序维度 + 聚拢开关都在列表头，进 localStorage 记忆 |
| 4 | 只作用于结果 | 排序/聚拢在筛选之后，不改筛选逻辑，不改左栏导航 |

## 5. 实施顺序

> M1/M2 是纯函数（无 UI 依赖），可并行；M3 依赖两者。
> 每步跑 `npm run lint` + `npm run typecheck` + `npm run test` + `npm run build`。

- **M1 排序纯函数**：`src/utils/assetSort.ts`——`sortAssetInfos(infos, {dim, dir}, ctx)`（ctx 含 displayName 解析器、完成率、分组键）+ 单测。
  验收：4 维度 × 升降序正确；稳定排序（同值不乱序）。
- **M2 聚拢纯函数**：`groupAdjacentSort(infos, sort, ctx)`——先分桶、桶间排、桶内排；关闭时退化为纯排序。+ 单测（真实文件名 fixture，含 V6E 多版本）。
  验收：同车型相邻；组间距随排序维度正确；关闭=平铺。
- **M3 列表头 UI**：排序下拉 + 聚拢开关；接 localStorage；接进 `filteredInfos` 派生链。
  验收：切换维度/方向/聚拢即时生效并记忆。
- **M4 回归**：四条验证命令全绿；真机截图核对（V6E 聚拢、名称排序定位）。

## 6. 约束与注意

- **排序稳定性**：所有比较器末尾补文件名字典序兜底，保证确定性（同值不乱跳）。
- **不给筛选加负担**：排序/聚拢是 `filteredInfos` 之后的独立阶段，不并进 `filteredInfos` 的 `useMemo` 依赖（避免筛选逻辑变复杂）。
- **displayName 口径**：名称排序用 `cardDisplayName`（别名解析后），与卡片显示一致（别名字母序，不是文件名）。
- **曜蓝 v4.1**：下拉沿用筛选 chip 的 Popover 样式；不引入新色/新字号。
- **性能**：分桶 + 排序是 O(n log n)，几百资产无压力；不引入虚拟化。

## 7. 评审提示

1. **聚拢的组内顺序**：默认与桶间同维度（如按完成率降序时，组内也按完成率）。若用户觉得"组内应该固定按版本新旧"，可改为组内固定时间序——实施后看反馈。
2. **桶代表值**：桶间排序时"这个车型排多前"取桶内最优值（如完成率最高那张）。若用户预期"按最新版排"，可调整。
3. **名称拼音序**：`localeCompare('zh-Hans-CN')` 对中文按拼音、对含拉丁字母的混排（如 `VE21`）按拉丁序——混排顺序可能与直觉略偏，实测后可微调。
4. **可选增强**：组首小标题（车型组名）能进一步强化聚拢的视觉分组，但会增加卡片高度；本轮不做，留待实测。

## 8. 明确挂起

| 挂起项 | 原因 / 去向 |
|---|---|
| 组首车型组名小标题 | 视觉增强，看聚拢实测效果再定 |
| 多级排序（主维度 + 次维度） | 单维度够用；有需要再扩 |
| 排序维度自定义（拖拽排序规则） | 4 个维度固定枚举即可，不做规则编排 |
| 暗色模式走查 | 沿用迭代 2 挂起项，单独立项 |
