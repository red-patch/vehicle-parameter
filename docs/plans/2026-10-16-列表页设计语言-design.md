# 列表页设计语言（布局与工具条规范）— 设计方案

> 日期：2026-10-16 ｜ 状态：**待实施**
> 来源：2026-10-16 grilling 会话（Q1–Q18 四轮，用户逐项确认「都按推荐来」）。
> 关联：`2026-10-15-ui-构件规范-design.md`（第一、二次同构）、`2026-10-16-表格行规范-design.md`（第三次同构）
> 前置事实：全仓表格渲染点盘点（26 个渲染点，详见 §8）

## 1. 背景：同一个根因的第四次出现

用户连续三轮指出「每个页面都不一样」，每次我都在更深的层次找到同一个根因：

| 轮次 | 领域 | 归因 |
|---|---|---|
| 1 | 搜索栏 | 都用了 `FilterBar`，但它只封容器、不封控件 |
| 2 | 工具条 | `FilterBar` 与 `Card+extra` 双轨做同一件事 |
| 3 | 表格行 | 都用了 `DataTable`，但它只封分页/滚动，不封「行里放什么」 |
| **4** | **布局语言** | **槽位未定义 → 每页自行决定「几行、每行放什么、谁在哪」** |

本轮用户把问题提到最高层：「**这个系统如何设计和布局的语言能够一致性**」。

**结论（第四次确认）：根本原因从来不是「开发者不守规范」，而是「规范没做成结构性约束」。**
依赖注入式的共享组件（`FilterBar` / `DataTable` 都属此类）只固定了**装东西的壳**，
没固定**该装什么、装在哪**；于是每个页面都能「用了公共组件」却长得不一样。

### 2.1 两个不能误判为「不一致」的现象

盘点中发现两处看似不一致、实为语义差异，**规范不应强改**：

1. **「刷新」只有 3 个页面有**——因为多数页面的数据是「当前会话导入」的，
   本来就不存在「从磁盘重读」这个动作。不是缺功能，是语义不同。
   **规范只要求**：凡有刷新，形态统一为「图标按钮 + Tooltip」（公告归档那种）。
2. **弹窗内的表格没有工具条**——Modal/Drawer 已有自身标题与关闭，
   再塞一套槽位是重复（见 §4.2）。

## 3. 目标：一致性 = 同一套语法，不是同一份内容

**Q1 裁定 B：固定「槽位」与每个槽位的唯一控件形态，内容随页面不同。**

理由：数据体检与法规标准的筛选**内容**本就不同，强求元素个数相同只会造就空占位。
真正让人不适的不是「元素不同」，而是**同一种元素在不同页面长得不同**（搜索框 3 种、
chips 4 种）——那是语法问题。

## 4. 槽位规格

### 4.1 列表页工具条 = 固定 3 段

```
┌──────────────────────────────────────────────────────────────┐
│ ① 标题 + 计数                          [操作按钮…]            │
├──────────────────────────────────────────────────────────────┤
│ ② 筛选：视图切换 · 快捷 chips · 搜索                          │
├──────────────────────────────────────────────────────────────┤
│ ③ 显示选项：隐藏无值字段 · 按字段名合并                        │
├──────────────────────────────────────────────────────────────┤
│                      内容区（表格 / 卡片列表）                 │
└──────────────────────────────────────────────────────────────┘
```

**为什么是 3 段**（Q5 裁定 B）：第 ③ 段与第 ② 段**语义不同**——筛选改「数据集合」，
显示选项只改「呈现方式」。版本对比把这两个 Checkbox 混在筛选行里，是最明显的语义混淆，
也是它「看起来最乱」的原因。分开后每个元素有唯一归属。

- 段 ①、③ 可整段省略；段 ② 省略则整条退化为筛选带。
- **段序固定**，不得调换。

### 4.2 覆盖边界（Q2 / Q9）

| 场景 | 是否遵守 |
|---|---|
| 列表页整页（含页面骨架） | ✅ 全套 3 段 |
| 弹窗 / 抽屉内的表格 | ⚠️ **只遵守「表格内部」**：行高契约、单元格纪律、控件形态；**不要求**有标题行/导出区 |
| 非列表页（表单页、画布页） | ❌ 不在本期；但控件形态（搜索框/chips）同样适用 |

理由：弹窗空间约束不同，且 Modal/Drawer 自身已有标题，硬套会重复。

### 4.3 容器规则（Q10 裁定 A）

- **列表页外壳用 `ListToolbar`**（自带 `surface-container` + 圆角 + 边框），**不再额外套 `Card`**。
- **`Card` 留给「一块内容」**（如属性去重的分组卡），不用于列表页外壳。
- 依据：已实测踩过坑——`ListToolbar` 塞进 `Card` 得到盒中盒。

| 意图 | 唯一构件 / 形态 | 禁用 |

### 5.1 操作按钮分级与承载（Q6 / Q8 / Q19）

- **段 ① 右端最多 1 个 primary**，其余 default / text。
- **数量自适应**：≤2 个平铺；≥3 个收进 `⋯` 或 `Dropdown`。
- **同一动作在一屏内只出现一次**（版本对比的「导出报告」出现两次是缺陷）。

#### Q19：primary 给谁——「产出动作」而非「过程动作」

「最多 1 个」是**上限**，不是「必须有」。判定标准（补于批次 2 复盘）：

> **primary 只给这个页面的「产出 / 终点动作」——即用户来这个页面要拿到的东西。
> 导入、迁移、刷新这类过程性动作一律 default，不得抢 primary。**

| 页面 | 产出动作（primary） | 过程动作（default） |
|---|---|---|
| 智能填报 | 车上云系统模板导出 | 复制/下载 CSV、导入需求列表 |
| 公告归档 | **无**（主任务是浏览与治理已归档记录，「导入」只是补充手段） | 导入公告 PDF、批量导入、从资产库迁移、刷新 |
| 法规标准 | 无（同公告归档：浏览为主） | 选择目录、刷新、保存、设置 |
| 数据体检 | 保存 / 覆盖原资产（本页的终点是把改好的数据落盘） | 手动新增参数、视同参考差异 |

**判据的可操作形式**：问「用户做完哪一步就可以离开这个页面了？」——
那个动作才是 primary。答不上来就说明该页没有产出动作，标题行不该有 primary。

**注意**：一个页面**可以没有 primary**，这是合法状态，不是缺陷。
此条源于批次 2：公告归档原本无 primary，改造时我误把「导入」提为 primary，
属于把过程动作当产出动作——该页的主任务（浏览/治理）并不产出新东西。

### 5.2 文案规范（Q7 / Q15）

- 两段式：**`<动作> <格式>`**。动作限 `导出 / 复制 / 下载 / 导入`；格式限 `CSV / Excel / PDF`。
- 现状 → 规范：

| 现状 | 规范后 |
|---|---|
| `导出CSV` / `导出 Excel` / `下载 CSV` | `导出 CSV` / `导出 Excel` |
| `复制CSV` / `复制填报结果 (CSV)` | `复制 CSV` |
| `清空` / `清空内容` / `清除` / `清除修正` | `清空`（整块）/ `清除`（仅标记） |
| `车上云系统模板导出` | **例外保留**（回答了「导给谁用」） |

## 6. 护栏（Q11 裁定 C）

**只定零误报项。** 有误报的护栏会被绕过，比没有更糟——这一点已实测两次
（禁 `flex-col`、禁 `<Switch>` 都会误伤页面级布局与侧栏面板）。

| 规则 | 判据 | 依据 |
|---|---|---|
| R7 | 文件里出现 `<Table` / `<DataTable` 就必须出现 `ListToolbar` | 结构可判、无误报 |

**明确放入文档、不进护栏的语义项**（靠 review）：
- 段 ① 是否只有一个 primary
- 该不该用 chips 而非 Select
- 文案是否符合两段式

理由：文本级扫描分不清单元格内外、分不清筛选与显示选项——这正是前三次修正的教训。
