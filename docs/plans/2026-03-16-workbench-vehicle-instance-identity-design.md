# 工作台车型实例身份设计

**背景**

当前工作台把 `productName` 当成全局唯一键。两个不同 Excel 文件如果解析出相同车型名，会在车型选择、待分析工作区、对比数据读取阶段被合并为同一个对象，导致 UI 只显示一条车型卡片，且参数数据发生串桶。

**问题根因**

- 工作台汇总列表按 `productName` 聚合。
- 车型参数索引按 `productName` 建桶。
- 选中状态、对比状态、净化状态也都只存车型名，无法区分同名但不同来源的实例。

**目标**

让工作台内部以“车型实例”而不是“车型名”作为主身份。两个文件中的同名车型应被视为两个独立实例，并在工作台、车型选择、对比入口中分别显示与读取数据。

**方案**

采用实例键 `source::fileName::productName` 作为工作台内部唯一身份。

- Excel 来源实例键示例：`excel::确认版本V6E-整车配置清单.xlsx::V6E小卡车-20260206`
- 资产来源实例键示例：`asset::foo.json::V6E小卡车-20260206`

显示层继续展示原始 `productName`，必要时附带来源文件名做辅助说明；状态层、查询层和索引层全部切换为实例键。

**数据结构调整**

- 为 `VehicleParameter` 增加可选 `instanceKey`，在索引和筛选时优先使用。
- 新增实例标识工具函数，统一生成/解析实例键，避免组件手写拼接。
- `selectedProductNames` 暂不强行重命名，实际承载内容改为实例键，后续按兼容成本决定是否再统一更名。

**影响范围**

- 工作台车型列表
- 左侧车型选择
- 参数选择器与按车型取数逻辑
- 对比/净化/智能填报的当前选择状态

**兼容策略**

- UI 标签继续展示车型名，尽量不改变用户感知。
- 已持久化的旧状态可能仍是纯车型名；本次优先保证新上传数据不再合并，旧状态兼容通过“如果 key 不存在则回退为空选择”处理。

**验证标准**

- 上传两个不同文件，且两者解析出的 `productName` 相同，车型选择应显示两项。
- 待分析车型工作区应显示两张独立卡片。
- 读取任一车型实例参数时，不包含另一个文件的参数。
