## 1. 背景与问题

### 1.1 用户诉求

> 设置页面需要补充快捷键管理功能。

### 1.2 现状缺口（实测）

快捷键**没有单一事实源**：11 处绑定散落在 6 个 handler 站点，每处各写各的 `if (mod && e.key === …)`：

| 站点 | 文件 | 覆盖的键 |
|---|---|---|
| 全局（MainLayout） | `Layout/MainLayout.tsx:87` | ⌘S→点保存按钮、⌘F→聚焦搜索、⌘W→关弹层 |
| 设置面板 | `Settings/useSettingsHotkey.ts` | ⌘, |
| 全局搜索 | `GlobalSearch/useGlobalSearchHotkey.ts` | ⌘K |
| 资产池 | `AssetPool/useAssetPoolHotkeys.ts` | ⌘⇧S、⌘B、⌘1/2/3、⌘⇧A、⌘⇧C、⌘R、⌘/、⌘Enter、方向键、Enter、Space、Esc |
| 资产池原生通道 | `AssetPool/useSaveViewMenuEvent.ts` | ⌘S（macOS 菜单转发） |
| 整车设计 | `VehicleDesigner/VehicleDesigner.tsx:152` | 1/2/3、⌘Z、⌘⇧Z |

由此产生的三类问题：

**① 快查列表与真实绑定脱节（已经发生）**

`AssetHotkeyCheatsheet.tsx` 手写 12 行文案，与源码不联动，已经错了：

| 速查表说 | 真实绑定 | 断言 |
|---|---|---|
| `⌘K` 聚焦搜索框 | ⌘K 已被**全局搜索面板**独占（`useGlobalSearchHotkey`） | 速查表此行错误 |
| `⌘S` 隐藏/显示左侧导航 | 已改为 **⌘B**；⌘S 现在是「保存当前视图」 | 速查表此行错误 |
| 缺 ⌘,、⌘F、⌘W、⌘Z、⌘⇧Z | 均存在 | 速查表漏列 |

副作用：`AssetSidebar.tsx:37/149`、`AssetPoolLayout.tsx:1159` 的 tooltip 仍写「⌘S」，与实际绑定（⌘B）不符——**同一处文案在三个文件里各写一遍，改一处必漏两处**，这正是「注册表」要消灭的现象。

**② 跨作用域键位冲突（已发生，跨平台差异）**

同一次按键被两个 handler 各自消费，双方都没有 `stopPropagation`：

| 键 | 站点 A | 站点 B | 平台差异 |
|---|---|---|---|
| **⌘W** | MainLayout「关最顶层弹层」 | macOS 系统菜单「文件 > 关闭窗口」（`lib.rs`） | macOS 上系统菜单优先，页内有无 Modal 决定关的是弹层还是整个窗口 |
| **⌘S** | MainLayout「点第一个 primary 保存按钮」 | 资产池「保存当前视图」（macOS 经原生菜单转发，Windows 经 ⌘⇧S） | 双触发：macOS 上按 ⌘S 同时保存视图 + 点保存按钮 |

⌘S 的 macOS 路径已被并行会话用原生菜单占位（`lib.rs SAVE_VIEW_MENU_ID`）——说明这问题已有人踩到，但只在 macOS 处理了；Windows 的 MainLayout ⌘S 仍与资产池语义并存。

**③ 无入口、无文档**

设置面板四分类（外观/路径/手机查看/数据）中没有快捷键；⌘/ 只在资产池作用域内可用，出了资产池就查不到。

### 1.3 目标

1. **单一事实源**：全部快捷键收进一张注册表，速查/设置页/冲突检测都从它读，杜绝手写列表漂移。
2. **可发现性**：设置面板新增「快捷键」分类，全量列出并按作用域分组；⌘/ 全局可用，开同一处。
3. **冲突可见**：跨作用域同键位冲突在设置页显式标红（含上表两例），并在代码层修掉真正有害的那部分。

### 1.4 非目标

- **不做用户自定义重绑**（用户已确认）：改键涉及捕获 UI、永续、迁移与 6 处代码的就地接线，收益不抵复杂度。注册表先把事实源与冲突检测做出来。
- **不做按键的运行时拦截/分发改造**：本次不引入统一 dispatcher。6 处 handler 各自的 `if` 链**保留原样**（它们已工作、有各自的作用域守卫），注册表是**描述性**的（人类可读的真值），不是**执行性**的。
  - 理由：执行性 dispatcher 要接管所有 `preventDefault` 语义与 antd 弹层 Esc 协调，风险远大于收益；本次先解决「事实源 + 可见性 + 冲突检测」。
  - 代价：注册表与实现有**两处真相**——由 §4.1 的**审计测试**兜底，锁死二者一致，漂移即 `npm run test` 变红。

### 1.5 目标与非目标边界（防扩散）

设置页只**展示与诊断**，不提供「点这里改键」。冲突处置在本设计内只做**一处**代码修复（§5 的 ⌘S/⌘W 分诊），其余冲突**如实列出、标注成因**，留给后续独立设计。

## 3. 注册表设计（`src/constants/shortcuts.ts`）

```ts
/** 快捷键归属的界面作用域。顺序即设置页的分组顺序。 */
export type ShortcutScope = 'global' | 'assetPool' | 'vehicleDesigner' | 'settings';

export interface ShortcutEntry {
    /** 稳定 id（测试与冲突检测的锚点；改文案不改它） */
    id: string;
    scope: ShortcutScope;
    /** 按键的规范化形式，如 'mod+s'、'mod+shift+a'、'mod+,'、'1' */
    combo: string;
    /** 面向用户的按键显示（⌘ 由 scope/平台渲染，此处存语义 combo） */
    label: string;
    /** 中文说明（一句） */
    description: string;
    /** 实现该键位的源码落点，供审计测试核对 */
    source: { file: string; /** 在该文件里的可 grep 锚点 */ marker: string };
}

export const SHORTCUTS: readonly ShortcutEntry[] = [ /* … */ ];
```

**规范化的 `combo` 语法**：`mod` = ⌘（macOS）/ Ctrl（Windows）；大写字母、`shift`、`enter`、`space`、`escape`、`arrowup`… 小写；逗号写作 `mod+,`。

**显示渲染**：`formatShortcut(combo)` 把 `mod+shift+a` 渲染成 `⌘ ⇧ A`（macOS）或 `Ctrl Shift A`（Windows）；平台判定沿用 `AssetHotkeyCheatsheet` 的 `/(Mac|iPhone|iPad)/` 正则，抽到 `src/utils/platform.ts` 或就近放进 `shortcuts.ts`。

## 4. 设置页「快捷键」分类

### 4.1 内容

新增 `SettingsSection` 联合成员 `'shortcuts'` + `sections.tsx` 一行 + `ShortcutsSection.tsx`。

界面结构：

1. **冲突横幅**（仅当检测到冲突时出现，`Alert type="warning"`）：一句话点出「N 组按键被多个功能占用」+ 逐条列出。
2. **搜索过滤**：用 `common/SearchInput`（`uiConsistency` 护栏 R1/R2 要求，禁手搓）。
3. **按作用域分组**：全局 / 资产池 / 整车设计 / 设置。每条 = 说明 + 按键 `kbd`。冲突条目标「冲突」Tag 并列出占用它的作用域。

### 4.2 展示来源

全部从 `SHORTCUTS` 渲染，**不手写任何一行按键**。

### 4.3 冲突检测（纯函数，可单测）

`src/utils/shortcutConflicts.ts`：

```ts
/** 返回按 combo 归一后的冲突组：同一个 combo 出现在 ≥2 个 scope 即冲突。 */
export function findShortcutConflicts(entries: readonly ShortcutEntry[]): ConflictGroup[];
```

**同一 scope 内同 combo 不算冲突**（如资产池里 ⌘S 的「切换侧栏」与「保存视图」历史上曾并存，属作用域内优先级，另行判定）；**跨 scope 同 combo 才是真冲突**（两个 handler 互不知情，都会响应）。这与实际 bug 机理一致——§1.2 两例都是跨 scope。

### 4.4 已知冲突的呈现

注册表落地后，首屏应如实显示：

| combo | 作用域 | 出处的现状 |
|---|---|---|
| `mod+w` | global（关弹层） + 系统（关窗） | 见 §5.1 分诊结论 |
| `mod+s` | global（点保存按钮） + assetPool（保存视图） | 见 §5.2 分诊结论 |

注册表**如实登记两处现状**，随后按 §5 修其中一处；修完冲突消失，横幅自动不再显示（检测是算出来的，不是写死的）。

## 5. 代码层修复（本次实做）

### 5.1 ⌘S 双触发 → 移除 MainLayout 的模糊「点保存按钮」

**现状**：`MainLayout.tsx:91` 的 ⌘S 用 `querySelector('button.ant-btn-primary…')` 点页面上第一个主按钮，语义模糊（点中哪个按钮看 DOM 顺序），且与资产池「保存视图」跨作用域双触发。

**处置**：删除 MainLayout 的 ⌘S 分支。逐功能考证该分支的**意图**：
- 资产池：⌘S/⌘⇧S = 保存视图，已有专属实现；
- 其余各页的「保存」语义**无一依赖此分支**（待 §7 冒烟确认；若有，改为该页显式绑定，而非全局模糊兜底）。

**理由**：全局「点第一个主按钮」是不可能猜对意图的实现（页面有多个 primary 时点谁？），且它正是 ⌘S 冲突的 A 端。删掉即消除冲突，且不损失任何确定性功能。

### 5.2 ⌘W 关弹层 vs 系统关窗 → 保留，登记为「已知平台差异」

**现状**：macOS 系统菜单「文件 > 关闭窗口」绑 ⌘W（`lib.rs`）。前端 `MainLayout` 也监听 ⌘W 想「关最顶层弹层」。

**分诊**：macOS 上系统菜单快捷键**优先于** webview keydown，所以前端监听在 macOS 基本收不到（拦截不了系统关窗）；在 Windows 无应用菜单，前端监听生效、行为正确。**结论：不加 `stopPropagation` 硬改**（改不动系统菜单优先级），如实登记为平台差异，设置页标注「macOS 上 ⌘W 由系统关闭窗口」。

### 5.3 清除陈旧标签

`AssetSidebar.tsx:37/149`、`AssetPoolLayout.tsx:1159` 的「⌘S」tooltip 改为读注册表（⌘B），消灭三处各自手写。
