# 资产池迭代 4：按维度分组（飞书式分组依据）— 设计方案

> 日期：2026-10-14 ｜ 状态：**待实施**
> 来源：用户参考飞书多维表格「分组依据」提出——按某维度把资产切成带计数的可折叠分组。
> 前置文档：`2026-10-14-asset-pool-sort-group-design.md`（迭代 3 排序与同车型聚拢，已实施）、`2026-09-29-asset-grouped-view-design.md`（早期车型分组视图，V2 已停用但组件仍在）。
> 视觉基准：曜蓝 v4.1。

## 1. 背景与问题

迭代 3 的「聚拢」只解决了一个维度（按车型相邻），且是无组头的轻量相邻。用户看到飞书「分组依据」后希望**通用化**：任选维度（状态/主机厂/族群/准入等级…）都能把列表切成带计数的分组 section。

### 1.1 现状盘点（三个半成品，需收敛）

| 机制 | 位置 | 能力 | 缺口 |
|---|---|---|---|
| 左栏导航（主机厂/族群） | 左栏 | 点一个值 = **筛选**成子集 | 是筛选不是分组——一次只看一个值 |
| 聚拢（迭代 3） | 列表头开关 | 按车型**相邻** | 单维度、无组头、无计数、不可折叠 |
| `AssetGroupedView`（2026-09-29） | 已停用组件 | 车型→文件两级折叠 + 组头计数 | 单维度（只车型）、与 V2/迭代 2 卡片体系不兼容 |

**结论**：需要**一个通用分组机制**，取代「聚拢」并吸收旧 `AssetGroupedView` 的组头/计数/折叠能力，维度可换。

### 1.2 与飞书的对应

飞书：「分组依据」下拉选维度（状态/产品等级/车型族群/…）→ 每个值一个分组头（带计数）+ 组内卡片 + 可折叠。本项目维度天然已有（facet），直接复用。

## 2. 目标形态

```
列表头：
共 83 个资产 · 已选 5   [分组：主机厂 ▾] [排序：时间 ↓]      将筛选结果加入工作区 →

分组开启时：
┌ 主机厂 · 上汽大通 (12)  ▾ ─────────────────────────────┐
│  ┌──────┐ ┌──────┐ ┌──────┐                          │
│  │ 车卡 │ │ 车卡 │ │ 车卡 │   ← 组内仍用流体多列网格    │
│  └──────┘ └──────┘ └──────┘                          │
├ 主机厂 · 吉利 (8)  ▾ ──────────────────────────────────┤
│  ┌──────┐ ┌──────┐                                    │
│  └──────┘ └──────┘                                    │
└────────────────────────────────────────────────────────┘
```

一句话：**「分组」取代「聚拢」——下拉选维度（不分组/车型/主机厂/族群/准入等级/电池品牌/状态），每个值一个带计数的可折叠 section，组内仍是流体多列卡片 + 现有排序。**

## 3. 详细设计

### 3.1 分组维度（下拉枚举）

| 维度 | 取值来源 | 组头显示 | 备注 |
|---|---|---|---|
| **不分组** | — | 无 | 平铺（迭代 3 的关闭聚拢态） |
| **车型** | `resolveVehicleGroupKey`（= 迭代 3 聚拢键） | 车型组别名（`pickGroupAlias`） | **默认**，等价于现「聚拢」 |
| **主机厂** | `fileFacets.manufacturer` | 主机厂规范名 | 缺值归「（无）」 |
| **车型族群** | `fileFacets.vehicleFamily` | 族群名 | 缺值归「（无）」 |
| **准入等级** | `fileFacets.admissionLevel` | 等级（Ⅰ/Ⅱ/Ⅲ…） | 按等级序排，字典序兜底 |
| **电池品牌** | `fileFacets.batteryBrand` | 品牌名 | 缺值归「（无）」 |
| **状态** | 治理状态派生 | 最新版 / 历史 / 废弃 / 驳回 | **飞书"红绿灯"的对应物**：一个资产可命中多状态时按优先级归组（废弃 > 历史 > 驳回 > 最新版） |

**电量维度不做分组**：电量是连续值，分组成"每个电量一个组"无意义（几乎每组一行）；如需按电量段分组，属后续增强（§8 挂起）。

### 3.2 分组机制

- **分组键**：`groupKeyOf(info, dim, ctx)` 纯函数——按维度取该资产的组键（字符串；缺值用哨兵 `'__none__'` 归「（无）」）。
- **组序**：
  - 车型/主机厂/族群/电池品牌：按组内资产数降序，同数按名称 `localeCompare('zh-Hans-CN')`，`'__none__'` 垫底。
  - 准入等级：按等级序号（Ⅰ<Ⅱ<Ⅲ<Ⅲ1…<Ⅳ），非等级值垫底。
  - 状态：按固定优先级（最新版→驳回→历史→废弃）。
- **组内**：沿用现有排序（`sortAssetRows`）+ 流体多列网格（与迭代 2 一致）。
- **折叠**：组头可折叠；展开态存 `localStorage['asset-pool-expanded-groups-<dim>']`（按维度分别记忆，避免换维度时错乱）。
- **搜索联动**：有筛选/搜索时命中组自动展开（沿用旧 `AssetGroupedView` 的 `filtersActive` 行为）。

### 3.3 组头规格（曜蓝 v4.1）

```
┌ 主机厂 · 上汽大通  (12)  ▾ ─────────────────────────────────────┐
```
- 折叠箭头（`CaretRightOutlined`/`CaretDownOutlined`）+ 维度标签（弱化）+ 组名（text-title）+ 计数（caption，`tabular-nums`）+ 一条向右延伸的分隔线（`--border-default`）。
- **组头操作**（仅车型维度）：沿用旧 `AssetGroupedView` 的组头能力——⚡ 激活组内最新版、右键「重命名车型」（`asset-promo-1-14` 已在用组重命名）。
- 组头 hover 时浅底（`surface-inset`）。

### 3.4 与左栏导航的分工（关键决策）

左栏「主机厂/族群」**保持筛选**语义（点值 = 收敛子集），**不**改成分组——因为：
- 左栏是"缩小范围"的入口（找特定厂的车），分组是"并列展开"的组织方式（横向比较各厂）；
- 二者互补：先用左栏筛到几个厂，再用分组按车型/等级横向摊开。

### 3.5 「聚拢」开关的下场

**「聚拢」开关被「分组」下拉取代**：
- 选「车型」= 原聚拢的加强版（带组头计数、可折叠）；
- 选「不分组」= 平铺（原聚拢关闭态）。
- 迁移：`asset-pool-group-adjacent` localStorage 键废弃；`asset-pool-sort`（排序）保留不变。
- 迭代 3 的 `sortAssetRowsGrouped` 保留复用（分组内部仍需要"同组相邻"的排序）。

## 4. 决策一览

| # | 决策 | 要点 |
|---|---|---|
| 1 | 通用分组 | 下拉选维度：不分组/车型/主机厂/族群/准入等级/电池品牌/状态 |
| 2 | 取代聚拢 | 「分组」下拉吸收「聚拢」开关；选车型=加强版，选不分组=平铺 |
| 3 | 组头能力 | 折叠 + 计数 + （车型维度）⚡激活最新版 + 重命名车型 |
| 4 | 左栏保持筛选 | 导航树不做分组，与分组互补 |
| 5 | 组内不变 | 组内仍用流体多列卡片 + 现有排序（迭代 2/3 成果全保留） |
| 6 | 按维度记折叠 | `asset-pool-expanded-groups-<dim>` |

## 5. 实施顺序

> 每步跑 lint + typecheck + test + build。

- **M1 分组纯函数**：`src/utils/assetGrouping.ts`——`groupKeyOf` / `groupOrder` / `buildAssetGroups(rows, dim, ctx)`（返回 `{ key, label, count, rows }[]`，含组序与缺值归组）+ 单测（各维度、缺值、状态优先级）。
  验收：7 维度分组键正确；组序规则正确；（无）垫底。
- **M2 组头组件**：`AssetGroupHeader.tsx`（折叠箭头 + 维度标签 + 组名 + 计数 + 分隔线；车型维度挂 ⚡/重命名）。
- **M3 列表体**：把「列表头排序/聚拢」改为「分组下拉 + 排序下拉」；渲染分 section（组头 + 组内网格）；折叠态 + 按维度记忆；搜索自动展开。
  验收：切维度即时重组；折叠记忆正确；空分组不渲染。
- **M4 清理与回归**：移除「聚拢」开关及其 localStorage 键；保留 `sortAssetRowsGrouped`；四条验证命令全绿；真机截图核对。

## 6. 约束与注意

- **曜蓝 v4.1**：组头不引入新色；分隔线用 `--border-default`；折叠箭头 `text-3`。
- **性能**：分组 = 一次分桶 O(n)，组内排序 O(m log m)；几百资产无压力。组头不参与卡片 memo 契约。
- **与排序正交**：分组定"怎么切"，排序定"组内怎么排"——两个下拉互不干扰。
- **旧组件处置**：`AssetGroupedView.tsx` / `AssetFacetSections.tsx` 仍是 `DataSourcePanel.tsx` 的依赖（后者 V2 后虽被 PoolPane 弃用，但文件未删）→ **本次不删**，待 `DataSourcePanel` 一并退役时再清理（已核实：除 DataSourcePanel 外零引用）。
- **空组**：某维度值无资产则不渲染该组（不显示空组头）。
- **`displayInfos` 派生链**：分组作用于 `filteredInfos` 之后，与迭代 3 的排序阶段合并为一条派生链。

## 7. 评审提示

1. **状态维度的多命中归组**：一个资产可能既是「最新版」又是「关键车型」——状态维度按优先级单选归组（废弃>历史>驳回>最新版），不做"一资产多组"。若用户要"多组投影"，属后续增强。
2. **主机厂/族群的组序**：默认按组内数量降序（大厂在前）。若用户预期按名称序，可改——与左栏导航的排序口径需一致（左栏现在是数量降序）。
3. **组头操作范围**：⚡/重命名只在「车型」维度出现（其他维度无"组"的业务实体）。若后续要在主机厂维度也做操作（如批量打标），再扩。
4. **与旧 AssetGroupedView 的差异**：旧组视图是"行式紧凑列表"，新分组是"卡片网格"——视觉沿用 V2/迭代 2 卡片，不复用旧的紧凑行。

## 8. 明确挂起

| 挂起项 | 原因 / 去向 |
|---|---|
| 电量分段分组 | 连续值需先定义分段（如 0-50/50-80/80+），观察是否需要 |
| 多维度分组（两级分组） | 飞书支持二级分组；先做单级，看是否需要 |
| 分组预设保存 | 排序/分组状态已进 localStorage；"命名预设方案"暂不做 |
| 组内自定义排序 | 组内沿用全局排序维度；独立设置暂不做 |
| 暗色模式走查 | 沿用挂起项，单独立项 |
