# 公告中心批量导入 — 目录扫描 + 公告 PDF 自动识别 — 设计方案

> 日期：2026-10-01 ｜ 状态：P1–P3 已实施（同日落码；Rust 5 单测 + 前端 12 单测过；真实 Downloads 嗅探端到端验证通过。实施备注见 §7）
> 前置文档：`2026-10-01-announcement-center-design.md`（公告中心本体，已实施）。
> 新增术语：`CONTEXT.md` 公告域「公告候选」。

## 1. 背景与目标

历史公告 PDF 散落各处（Downloads/桌面/微信下载等），文件名不规范且多副本重复（实测 Downloads 已有同内容双副本）。目标：
1. 「导入公告 PDF」支持**指定目录 + 子目录递归扫描**；
2. **自动识别**工信部公告参数页，预填命名三要素（车型名/公告号/批次）；
3. 内容哈希**去重**（对已归档 + 扫描内部）；
4. **人工确认制**：识别只负责预填与排序，勾选确认才入库，永不自动归档。

## 2. 已验证事实（设计依据）

- 样本 PDF 带完整中文文本层：可提取 产品型号名称（含公告号 `DNC5037XXYBEVP1`）、批次 `407`、生效日期、企业名称、产品商标；特征词稳定（汽车产品技术参数/产品型号名称/车辆识别代号/企业名称/产品商标…）。
- PDF 提取引擎选型（Q8，用户裁定**轻量、性能优先**）：`pdf-extract` 0.12（纯 Rust、零分发成本）+ `catch_unwind` 按文件隔离，失败降级文件名启发式；pdfium（+7MB/平台）与 mupdf（AGPL）排除；Windows WinRT 无文本提取 API。
- `walkdir` 2.5 已在依赖树，递归扫描零新增成本；`scan_asset_library` 非递归，互不影响。
- 性能硬指标：只提取前 1–2 页文本、命中特征词即提前退出、多文件并行提取。

## 3. 功能设计

### 3.1 入口（Q1）

公告中心工具栏新增「批量导入 PDF」独立弹窗：选目录 → 扫描进度（可取消）→ 候选表格（分组/勾选/行内编辑）→ 批量归档。现有单文件导入弹窗保留不动。

### 3.2 扫描（Q6）

Rust 新命令 `scan_pdf_candidates(root, max_depth)`：
- walkdir 递归，深度 ≤6；跳过 `.` 开头隐藏目录、`Library`、`node_modules`、`$Recycle.Bin` 等噪声目录；
- 扫描根内若含 `公告PDF/` 归档目录**自动跳过**（防止把已归档的扫进来）；
- 收集 `*.pdf`：大小 / mtime / **内容哈希**（整文件，公告 PDF 约 170KB 很便宜）；
- 文本嗅探前 1–2 页（pdf-extract），命中特征词即提前退出；`catch_unwind` 按文件隔离，单文件失败不崩、降级；
- 多线程并行提取；候选 >2000 提示收窄范围；进度上报（已扫文件数/当前目录）+ 可取消（原子标志）。

### 3.3 识别与置信（Q2 + 默认值1）

- **高置信（announcement）**：文本含 ≥2 特征词；提取 公告号（标题「DNC…型…」模式 / 产品型号名称字段）、批次、企业名称、产品商标；
- **疑似（suspect）**：仅文件名像 `queryCpParamPage*`、或仅 1 个特征词、或内容提取失败（标注「无法读内容，请人工确认」）；
- **非公告（other）**：0 特征且文件名不像 → 折叠组，可展开捞回（防识别器漏判）。
- **边界裁定（Q2）**：嗅探只服务「归档+命名+关联」，**参数数据源永远来自书签链路**，不做 PDF 参数表提取（不推翻公告中心 Q4 裁定）。

### 3.4 命名三要素补全链（Q3）

① PDF 提取公告号+批次 → ② 公告号**反查资产库**（announceNos ∪ vehicleModel 命中 → 借其车型组名做 vehicleName，如 DNC5037XXYBEVP1 → 远程V8E）→ ③ 未命中用 商标+型号名称 兜底（如「远程牌 纯电动厢式运输车」）→ ④ 留空人工填。候选表格三列（车型名/公告号/批次）**行内编辑**（Q10，沿用资产批量打标表格交互）。

### 3.5 去重与冲突（Q4/Q9）

- 候选哈希 = **已归档**任一 PDF → 组「已归档过」，默认不勾；
- 候选**内部**同哈希多副本 → 只归一份，其余标「重复副本」默认不勾；
- 同公告号+批次但内容不同 → **mtime 最新胜出**按替换处理（沿用公告中心 Q12），旧版标「旧版本」默认不勾，可手动改选（Q9）。

### 3.6 归档执行（Q5 + 默认值3）

一次确认 → 带进度逐份落盘：写记录 JSON（`parameters: []`，PDF-only 是合法状态）+ 复制 PDF（复用 `writeAnnouncementRecord`/`importPdfToArchive`/命名清洗）→ 该份复制**成功后**才执行其原件清理（全局勾选「归档后把原件移入废纸篓」，默认关，走 `moveToTrash`）→ 结束汇总「归档 N / 跳过 M / 失败 K」+ 刷新公告 store。

### 3.7 入口记忆（Q11）

localStorage 记住上次扫描目录；提供 Downloads / 桌面 两个快捷按钮。

## 4. 模块改动清单

**Rust（src-tauri）**
- `Cargo.toml`：`pdf-extract = "0.12"`（lopdf 走传递依赖，已在树）。
- `src-tauri/src/pdf_sniff.rs`（新）：walkdir 扫描 + 哈希 + 嗅探 + 并行 + 进度/取消；命令 `scan_pdf_candidates`、`cancel_pdf_scan`；进度经 Tauri event `pdf-scan-progress` 推送。
- 特征词/公告号/批次提取正则做 Rust 单测（fixture 用样本 PDF 文本片段）。

**前端**
- `src/utils/announcementScan.ts`（新，纯函数优先）：候选类型、invoke 封装、置信度判定、命名补全链（反查资产库）、内部去重与 mtime 裁决——全部可测。
- `src/components/AnnouncementQuery/AnnouncementBatchImportModal.tsx`（新）：目录选择/进度/候选表格（分组+行内编辑+勾选）/批量执行。
- `AnnouncementArchiveList` 工具栏加「批量导入 PDF」按钮。
- 单测：置信度判定、命名链、去重裁决。

## 5. 非目标

- 不做 PDF 参数表提取（书签链路不变）；
- 不做自动归档（永远人工勾选确认）；
- 不做 PDF 全文索引/搜索；
- 加密/扫描版（无文本层）PDF 不做内容识别，降级进疑似组。

## 7. 实施备注（2026-10-01 落码发现）

1. **pdf-extract 对真实工信部 PDF 直接 panic**（样本 `queryCpParamPage.pdf` 等 100% 触发，stderr 报 `unsupported encoding UniGB-UCS2-H`）——调研预警的脆弱性为真。已加 **lopdf 兜底提取**（同为 pdf-extract 传递依赖，零重复编译），真实样本全部经兜底成功：8 个特征词命中、公告号/批次正确提取（407/396 与迁移 dry-run 数据互证）。改名件（文件名无 queryCpParamPage 字样）靠纯内容识别成功。
2. **批次提取双轨**：主正则接「批次 407 / 批次:407」；lopdf 拆行文本里标签后跟的是 8 位生效日期，批次值以**独立 3 位数字行**出现——兜底用「批次号域 300–599」约束过滤目录序号（138/100 等杂数实测全在域外）。
3. **高置信判定收紧**：仅 ≥2 特征词会误收产品介绍类文档（实测「无人车产品价值及亮点」靠 整备质量+额定载质量 凑 2 分）——追加「须提取到公告号或型号标题」身份条件后归为疑似。
4. **商标字段偶发抓到地址行**（标签值 jumble 伪影）：命名链加地址样守卫（含行政区划字样+数字且 ≥8 字符不当商标）；有公告号时走资产反查，商标只影响无命中时的兜底命名。
5. 火车票/招股书等无关 PDF 两个引擎都失败 → 稳定落疑似组并标注原因，`catch_unwind` 隔离全程无崩溃。
6. **iCloud 占位修复（用户反馈慢+报错后追加）**：实测资料文件夹 138 个文件是 `st_blocks==0` 数据占位，旧实现 open 即触发系统整份下载（这就是慢与读取失败的根因；首次扫描顺带把 228 个 PDF 全下载了）。修复：默认**不 open 未落地文件**（零网络副作用），以 `confidence: 'notDownloaded'` 独立分组（rank 紧随新公告），仅从文件名反解 公告号/批次/车型名 预填、默认不勾选；弹窗勾选项「仅扫描已下载到本地的文件」（默认开），关掉才全文嗅探（触发下载）。
7. **引擎策略定稿「强则单、弱则双、字段合并」**：lopdf 先提（单次解析），已提出**公告号**+特征≥2 即免二次解析；否则给 pdf-extract 第二机会并 `merge_meta` 字段级合并（实测 lopdf 擅长批次/商标行、pdf-extract 擅长标题公告号，单靠任一侧各丢约 1 个真实公告）；性能护栏：lopdf 有文本但**特征=0** 的文件跳过第二遍（无关文档是大头，特征≥1 即给机会——降到 ≥2 会误杀「吉利商用车产品介绍202101」这种 lopdf 侧特征=1 的真实公告页）。
8. **命令健壮性**：`scan_pdf_candidates` 外层 `catch_unwind` 把残余 panic 转成带原因的「扫描内部错误: …」，不再是裸 JoinError。
9. **结果区 UI 追加（用户中途需求）**：Segmented 分类筛选（全部/新公告/疑似/未下载/旧版本/重复/已归档，带计数；分类只管展示、勾选跨分类保持）+ 每行「打开」（默认应用，核查内容后回来手填）与「定位」（Finder 中定位）；未下载行的打开会先自动下载（Tooltip 已标注）。
10. **页数门槛（用户抓出的误判后追加，2026-10-02）**：公告参数页**恒为 1 页**（用户域知识；实测正常档 50-170KB/1 页），而误判样本是 98 页产品册/17 页规格书——特征词+公告号身份都"通过"了。修复：`lopdf_probe` 顺带取页数（load 成功即可得，文本失败也有），`MAX_ANNOUNCEMENT_PAGES=2`，超页数**永不判公告**、降级疑似并在 ⚠ Tooltip 标注「多页文档（N 页）——公告参数页通常为 1 页」。定点验证（/tmp 拷贝三样本）：98 页与 17 页降级、1 页公告不受影响。**已误归档的两条记录（天然气压缩垃圾车是_CGJ5182ZYSDN6NG_300 / 远程V8E_DNC5037XXYBEVGR5）需用户在公告中心手动删除**（UI 一键删 JSON+PDF 对）。
11. **轻量模式定稿（用户裁定，2026-10-02）**：Q1-Q3 落地——① **pdf-extract 彻底移除**（Cargo 依赖删掉；探针实测 344ms/文件且对工信部 PDF 100% panic，占旧流程 70%+ 耗时，换来的召回约 1/200，落折叠组可手动捞）；② **页数前置**：`load_mem` 出页数即拦截，>2 页不提文本直接降级（名带「公告/queryCpParamPage」进疑似、其余折叠），省掉大文档提取；③ **文件名信号**：hint=名含「公告」或 queryCpParamPage 前缀（只保底进疑似，不参与否决）；公告号按形状识别（大写字母开头+含数字 5-25 位 token，**不锁 17 位**——17 位是车架号 VIN，公告号实测 13-16 位）；④ **单次读内存**：fs::read 一次，sha256 与 lopdf `load_mem` 共用。附带修正：classify 的 `!text_readable` 不再触发疑似（多页主动跳过≠不确定，曾把 78 个无关多页文档抬进疑似组）；大小门 20MB→**5MB**（公告页实测最大 172KB）。**验证**：17 条公告召回不变，疑似 81/折叠 130，单线程用户态 151-248s→**98s**，应用 8 workers ≈ 7-15 秒/228 文件。**Q4 后台化经评估不做**（秒级动作用不上，避免架构复杂化；现有进度+取消+5000 上限兜底）。
12. **增量扫描缓存 + 回应检查（2026-10-02，用户场景「重复扫描下载夹=纯浪费」驱动）**：
    - **缓存**：识别结果按「路径|大小|mtime」键存应用缓存目录（`announcement-scan-cache.json`，上限 20000 条、超限只留当次；条目超 1000 时卫生修剪——清掉源文件已不存在的旧条目，防止扫过的临时目录删掉后残留累积），重扫 stat 命中即复用、未命中才解析；notDownloaded 结果不入缓存（占位/落地两状态防糊）。**实测**：228 文件首遍全解析 33.7s → 二遍全缓存命中 **794µs**（约 4 万倍），结果断言一致。
    - **回应检查**：`probe_downloads` 命令——只列下载目录**顶层** PDF，缓存命中复用、新文件仅当**文件名像公告**（filename_plausible）才嗅探并入缓存，其余不缓存不打扰；占位文件直接跳过（不为检查触发下载）；只上浮 announcement/suspect。前端 `tauri://focus` 监听 + 15s 去抖，过滤「已忽略名单（localStorage 上限 200）+ 已归档（公告号|批次）」后 antd notification 提示，「立即归档」走单文件导入弹窗（新增 `initialPdfPath` prop 跳过文件选择），「忽略」写入名单。
    - process_pdf 的 filename_hint 统一为 `filename_plausible`（名含「公告」/queryCpParamPage 前缀/公告号形状 token）——改名公告文件（内容不可读）从折叠组升进疑似组，可见性更好。
    - 重新计时的真实基线：轻量模式单线程全解析 228 文件 = **33.7s（148ms/文件）**，应用 8 workers ≈ 4-5s。
