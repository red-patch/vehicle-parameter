# 车上云导出：字段组定输出、映射定取数、格式定出文件 — 设计方案

> 日期：2026-10-19 ｜ 状态：**已实施**
> 来源：用户用「车上云系统模板导出」上传后被逐条拒绝（「列不属于该模版」「取值[…]有误」）；随后两次修正了建模方向。
> 数据依据：
> - 导出样本 `车上云系统导入_远程V8E 宁德66.67_20261019.xlsx`（437 行）
> - 公司模板 `产品准入导入模版20261013.xlsx`（441 项）
> - 属性池枚举 `docs/字段数据/商品中心_产品中心_属性池.xlsx`（686 字段）
> 关联：`2026-10-12-bid-batch-automatch-design.md`（同一套唯一匹配判据）、`2026-10-15-ui-构件规范-design.md`

## 1. 问题的实证

| 检查 | 结果 |
|---|---|
| 437 个字段名 | **逐字全部命中** 441 项模板 |
| 报错行号 | **12/12 等于导出文件的行号** |
| 同义双写 | **12 对**「裸名 + `出厂` 名」，值完全相同；被拒的恰好是裸名 |
| 枚举 | 353 个非空值中，15 个真越界（含 `侧门帘=右侧滑门`） |

结论：车上云**按字段名认**、按所选类别模板校验；我们的导出没有模板概念，把资产里的两套命名一并倒出。

## 2. 三层职责（本设计的核心）

| 层 | 存在哪 | 回答什么 | 谁维护 |
|---|---|---|---|
| **字段组** | `custom_fields.json` 的 `groups` | 这次输出哪些字段名、什么顺序 | 「字段与词表 · 核心字段配置」（已有功能） |
| **映射** | 字段组的 `sources` | 每个字段取资产里的哪个字段 | 同上；智能填报里也能改，改完回写 |
| **枚举字典** | `custom_enums.json` | 该字段允许填哪些值 | 「字段与词表 · 枚举字典配置」（已有功能） |
| **导出格式** | `custom_fields.json` 的 `exportFormats` | sheet 名、文件名、引用哪个字段组 | 「字段与词表 · 导出格式」（新增） |

**格式不存字段**：字段永远来自字段组，避免两处维护后不一致。

## 3. 映射是 1 对 N（不是 1 对 1）

```jsonc
"sources": {
  // 备选名：A 车叫「颜色」、B 车叫「车颜色」，按顺序取第一个存在的
  "车型颜色": { "candidates": ["颜色", "车颜色"] },

  // 组合：多个来源同时命中时按模板拼接（与「多车取数」同一套规则结构）
  "外扩尺寸": { "candidates": ["外形尺寸长", "外形尺寸宽", "外形尺寸高"], "template": "{0}×{1}×{2}" }
}
```

**解析顺序**（`src/utils/fieldMapping.ts:resolveGroupFields`）：

1. 人工配置的候选规则 → 按顺序取第一个在当前车型存在的字段；
   - **有 `template`** 才拼接全部命中项；**没有** 只取第一个
   - （否则「一车两名叫法」会被拼成 `白色×白色`）
2. 候选全不在或未配置 → `findUniqueMatch`（完全同名 / 去单位归一 / 同义词组唯一）
3. 仍无 → `findBestMatch` 模糊结果，**只作建议**（标黄待确认），不静默采用

## 4. 字段状态

| 状态 | 判定 | 表现 |
|---|---|---|
| `unmapped` | 找不到资产字段 | 红 |
| `enum_invalid` | 有词表、值非空、不在词表内 | 红 |
| `low_confidence` | 来源是未确认的模糊建议 | 黄 |
| `empty` | 有来源但值为空 | 黄（允许留空导出） |
| `no_enum` | 词表未收录该字段 | 不判错，只说明 |
| `ok` | 其余 | — |

值比较是 **trim 后精确比较**：`270` 与 `270°` 在属性池里是两个不同枚举值，弱比较会洗掉真错误。

## 5. UI

### 5.1 核心字段配置（扩展既有页）

- 表格新增「取值来源」列：显示解析结果，点开是候选编辑器（多候选 + 组合模板 + 恢复自动）
- 工具条新增「从 Excel 更新」：打开预览弹窗（不是点一下就覆盖）
  - 列出文件内字段总数、新增 / 移除 / 保留，逐项可筛选
  - 两种应用方式：**覆盖**（换清单，移除字段的来源映射一并清除）/ **合并**（只追加新字段）
  - 「应用并保存」一次完成，不需要再点「保存并应用」
- 面板副标题显示「已确定来源 / 未匹配 / 待确认 / 必填 / 必填未填」
- **必填**：表格里每行一个勾选框；工具条「批量设必填」支持粘贴字段名批量设为/取消必填
- 必填存在字段组的 `required: string[]` 里，**与 `fields` 独立**：
  从 Excel 覆盖导入只改字段清单，必填按字段名原样保留；字段被移除时其必填标记才一起消失

### 5.2 导出格式（新增 Tab）

- 一个格式 = 名称 + 字段组 + sheet 名 + 文件名模板（`{车型} {日期} {格式}`）
- 列表里直接预览渲染后的文件名；字段组被删时该行标红

### 5.3 智能填报 · 单车填报

- 需求区已有「字段配置组」下拉；旁边新增「导出格式」下拉，选格式自动切到它绑定的字段组
- 选了字段组后：表格 = 组内全量字段；「匹配库参数」列变为**来源下拉**，选完写回字段组并落盘
- 导出按钮变为「按格式导出 · <格式名>」
- 字段组模式下新增「必填」筛选：全部 / 仅必填 / 仅选填 / 必填未填；行内必填字段名前显示 `*`

### 5.4 多车型：修正值按车型留存 + 视同

**修正值按车型存**：`smartFillManualByProduct: { 车型: { 字段名: 值 } }`（store，persist）。
切车型时 `matchResults` 会重建，修正值若只存在行上就会丢；这也是「修完 A 切到 B」的成果基础。

**视同**（复用体检页 `2026-10-15-体检参考车型视同更新-design.md` 的语义）：

- 筛选行选「视同参考」车型 → 自动算出差异（参考车型最终值非空且与当前不同）
- 行内「视同」按钮采纳单字段；标题行「视同参考差异（N）」一次全部写入
- 判据比体检页更窄：**只比值**，不比字段名/分组——字段名是模板规定的，不该被另一个车型改写
- 参考值为空永不算差异（不把空覆盖进来）

## 8. 验收

1. 核心字段配置导入 441 项模板 → 字段数 441，来源自动解析
2. 「车型颜色」配两个候选 → 换车型仍能命中
3. 「外扩尺寸」配模板 `{0}×{1}×{2}` → 导出值为 `5495×1830×1980`
4. 枚举越界（`侧门帘=右侧滑门`）在来源列可见
5. 不选字段组时，原有需求匹配 + 全字段导出行为不变

## 9. 边界

- 类别模板拿不到时只导入手上有的那份；不做类别推断
- 属性池对 243/353 个字段无词表 → 只能报「无法判断」
- 同一资产字段可被多个输出字段引用（允许）
- 字段在填报页改了来源会立即落盘（同组其他车型复用）
