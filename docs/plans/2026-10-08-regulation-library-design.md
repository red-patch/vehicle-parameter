## 1. 背景与问题

用户长期手动维护一个 iCloud 法规标准文档库：

```
👨个人知识库/【02】Areas/无人车/20-研究/行业情报/法规标准/
├── 01_智能驾驶-国标/          12 份（GB/GB-T 智能驾驶）
├── 02_智能驾驶-ISO与国际/      10 份（ISO/SAE/UNECE/JAMA/AVSC）
├── 03_整车准入-国标/          16 份（整车、制动、照明、尺寸）
├── 04_行标与政策文件/           3 份
├── 05_团体标准/                3 份
├── 06_地标与团标项目/          19 份（正式标准 + 项目过程文件混放）
├── 07_研究报告/                1 份
├── 08_标准知识卡/              1 份（人工整理的 ISO 26262 解读）
└── 自动驾驶6层模型/            论文翻译项目（含 .alma-snapshots）
```

**语料实测**（本次会话探测，46 份标准 PDF / 2211 页）：

| 事实 | 数值 |
|---|---|
| 文件名规范度 | 高——多数为 `<类型>-<标准号>-<年份>_<中文名>.pdf` |
| 有文本层 | 38 份（PyMuPDF 判定） |
| 纯扫描件/图像 | 16 份，占磁盘约 390 MB |
| 可检索正文总量 | 2.22M 字符（≈5–10 MB 内存；对照资产库全量 519 资产 = 121 MB） |
| 磁盘大小与可检索性相关性 | **几乎为零**——116 MB 的 ISO 21434、77 MB 的 GB/T 41798 全是扫描件 |

痛点：**知道手里有这些标准，但不知道哪版现行、谁替代了谁、哪份讲了我需要的条款。** 现在靠文件名和记忆找。

关键教训（与内存计划 §1.1「决定内存的是单元格数，不是文件大小」同构）：**按文件大小判断"能不能搜"会完全判错方向。**

## 2. 目标形态

新增独立顶栏 Tab **「法规标准」**，与「公告中心」并列。它是**独立记录域**（自有权威来源，不参与资产治理/标注/筛选），与 `CONTEXT.md` 中「公告记录」同性质。

```
法规标准（Card 全宽）
┌────────────────────────────────────────────────────────────────┐
│ [搜索: 标准号/名称/正文]   chips: 全部|现行|即将实施|已替代|无文本层  │
│ [facet: 标准层级 ▾] [facet: 主题域 ▾]        [扫描] [刷新] [登记]  │
│ ⚠ 发现 3 个未登记文件，点击查看                                  │
│ ────────────────────────────────────────────────────────────── │
│ 标准号        名称                    层级  主题域   状态    实施日期  │
│ GB 44495     汽车整车信息安全技术要求   国标  智能驾驶·信息安全  即将实施 2026-01-01 │
│ GB 1589      汽车、挂车及汽车列车外廓…  国标  整车安全        现行   2017-01-01 │
│ GB/T 18386.1 电动汽车能量消耗量和续驶…  国标  电动车·专用车    现行   2022-05-01 │
│ ISO 26262    （无文件·仅知识卡）        国际  功能安全        现行   2019-12-01 │
│ ────────────────────────────────────────────────────────────── │
│ ▸ 未识别（4）— 解析不出标准号的文件，不干扰正式列表              │
└────────────────────────────────────────────────────────────────┘
```

**详情抽屉**：基本信息 + 版本链/替代关系（旧版可展开，永不删除）+ 未下载/无文本层标注 + 知识卡（0..N 张）+ 打开原件。

### 3.1 全文引擎的实测依据（Q22 推荐的撤回）

纯 Rust 方案在本语料上**不可用**，实测对账（54 份，lopdf 0.42 vs PyMuPDF）：

| 类别 | 份数 | 说明 |
|---|---|---|
| 两者都能抽 | 29 | — |
| **lopdf 静默返回空文本** | **7** | PyMuPDF 有正文：GB 4785（63k 字）、ISO 22737、GB/T 12673、GB/T 18386.1/.2、GB 29753、GB/T 40429 |
| **lopdf 加载失败** | **2** | **GB 1589 外廓尺寸**、**GB 7258 运行安全技术条件**（`invalid file trailer`，但 PyMuPDF 正常） |
| 真扫描件（两者一致） | 16 | 确实无文本层 |

**在有文本层的 38 份中，纯 Rust 失败 9 份 = 24%，其中 7 份为静默失败**，且包含最常被引用的 GB 1589 与 GB 7258。

`pdf-extract` 0.12 复用同一 lopdf 底层，实测更差：同样 2 份加载失败 + **5 份 panic**（GB 4785、ISO 22737、GB/T 12673、GB/T 18386.1、GB/T 40429）——这正是它当年被移出依赖的原因。

许可约束：poppler 为 GPL、MuPDF 为 AGPL，均不可用；**pdfium 为 BSD-3，是唯一干净选择**。

## 4. 数据设计

### 4.1 旁路文件 `{法规库根}/_regulations.json`

沿用资产库「旁路文件与数据同行」成例（`_asset_tags.json`）。`_` 前缀天然被资产库扫描规则 `!name.starts_with('_') && !name.starts_with("custom_")` 排除，两者互不污染；iCloud 同步使跨机器自带元数据。

```jsonc
{
  "version": "1.0",
  "rootPath": "…/法规标准",            // 仅记录用，扫描时以用户所选路径为准
  "vocab": {
    "levels": ["国标", "行标", "团标", "地标", "国际", "政策"],
    "domains": [ /* 见 §4.3 种子词表，可增补 */ ]
  },
  "records": [ /* RegulationRecord[] */ ]
}
```

### 4.2 `RegulationRecord`（身份与版本）

```ts
interface RegulationRecord {
  version: string;                 // "1.0"
  /** 身份键：规范化标准号（含部分号）—— "GB 44495"、"GB/T 18386.1"、"ISO 26262" */
  standardNo: string;
  /** 版本：发布年份；无年份（框架文件/白皮书）为 null */
  year: string | null;
  /** 标准全称 */
  title: string;
  /** 受控属性①：标准层级（单值，可由标准号前缀自动判定） */
  level: string;
  /** 受控属性②：主题域（多值，人工选） */
  domains: string[];
  publishedAt: string | null;      // YYYY-MM-DD
  effectiveAt: string | null;      // YYYY-MM-DD
  /** 状态：现行 / 即将实施 / 已被替代 / 废止 / 草案 */
  status: string;
  /** true = status 被人工覆盖，不再随日期自动推导 */
  statusOverridden: boolean;
  replaces: string[];              // 本记录替代的标准号（"代替 GB1589—2004"）
  /** 引用：相对法规库根的文件名；null = 无 PDF（合法） */
  fileName: string | null;
  fileSize: number | null;
  /** 引用失效：文件被移走/改名。扫描时比对得出 */
  fileMissing: boolean;
  /** iCloud 未下载占位文件（blocks==0），不打开 */
  notDownloaded: boolean;
  /** 文本层：has / none / unknown（未探测） */
  textLayer: 'has' | 'none' | 'unknown';
  /** 知识卡：相对文件名（0..N） */
  knowledgeCards: string[];
  /** 解析不出标准号文件的原因，供「未识别」区展示 */
  unparsedReason?: string;
  note: string;
  updatedAt: string;
}
```

**身份与版本语义**（对齐 `CONTEXT.md` 身份键原则）：

- `GB 44495` 与 `GB 44495-2024` 是**同一条记录**，年份是版本字段。
- `GB/T 18386.1` 与 `.2` 是**不同记录**（部分号属标准号本身）。
- `GB 44495 / 44496 / 44497` 是**三条独立记录**。
- **旧版永不删除**：`GB 21670-2008 → GB 21670-2025` 是同记录的两个版本；旧版本标为"已被替代"并降权展示，不静默覆盖。版本链由 `[同 standardNo, 不同 year]` 的集合构成。

| 主题域 | 主要归属 |
|---|---|
| 智能驾驶 | GB 47955、GB 44721、GB/T 40429、SAE J3016、JAMA/UNECE/AVSC 框架 |

### 4.4 标准层级自动判定

由标准号前缀判定，无需人填：`GB`→国标 · `DB4403`→地标 · `T/`→团标 · `ISO`/`SAE`/`UNECE`/`JAMA`/`AVSC`→国际 · 无标准号政策文件→政策。

## 5. 实现要点

### 5.1 Rust 单源解析（Q18）

**刻意的架构偏离**：公告中心把同一套命名解析在 Rust（`parse_base_name`，`announcements.rs:51-80`）与 TS（`parseAnnouncementBaseName`）各写一遍、靠注释维持"同口径"，记录 schema 更是 Rust 两份 + TS 一份。法规标准**不再复制这个模式**。

扫描本就在 Rust（借用 `pdf_sniff.rs` 的 `walkdir` 基础设施），文件名解析就近完成并批量返回，前端只消费，永不重新解析。旁路文件读写仍沿用前端 `plugin-fs` 既有惯例，不下沉。

> 本偏离必须在本文档留痕，否则下一个实施者会"照抄公告"把双实现漂移带回来。

### 5.2 可直接复用的既有设施（`pdf_sniff.rs` / `announcements.rs`）

领域无关、可直接借用：

| 设施 | 位置（`src-tauri/src/`） |
|---|---|
| `walkdir` 递归 + 噪声目录过滤（`NOISE_DIRS`/点目录） | `pdf_sniff.rs:87-89, 192-222` |
| iCloud 未下载占位识别（`md.blocks()==0`，不打开文件） | `pdf_sniff.rs:405-416` |
| `path\|size\|mtime` 增量缓存（`app_cache_dir`，版本化 + 条目上限 + 溢出裁剪） | `pdf_sniff.rs:110-190` |
| 8 线程并行 + 每文件 `catch_unwind` + 进度事件 | `pdf_sniff.rs:588-612` |
| 记录 JSON 校验与自愈读 | `announcementRecord.ts:119-134, 190-205` |
| 「扫描→候选→勾选才入库」批量确认交互 | `AnnouncementBatchImportModal.tsx` |
| `move_to_trash` / `copy_files_to_clipboard`（已泛化，直接复用） | `announcements.rs:181, 195` |

**须新写**：标记词表与提取正则（工信部专属，不可复用）；法规记录的身份/命名规则；「未识别」判定。

### 5.3 存储纪律（须遵守内存计划的既有规则）

- **缓存有界**：沿用 `pdf_sniff` 的 `path|size|mtime` 磁盘缓存纪律，不引入无界内存缓存。
- **不跨周期长期缓存**：正文文本若缓存，须随功能开关释放，不常驻。
- **写后失效**：任何改写旁路文件的操作必须使扫描缓存失效。
- **新逻辑放新文件**：不得堆入 `DataSourcePanel.tsx`、`ConfigManagerView.tsx`、`FileManager.tsx`、`AssetGroupedView.tsx` 等超阈值热点文件。

### 5.4 权威数据源与快捷查询（Q24–Q27）

两级入口，**诚实区分"能给跳转"与"能给回填"**：

| 级别 | 覆盖 | 机制 |
|---|---|---|
| **跳转** | 全部层级（国标/行标/地标/团标/国际） | 按站点模板拼 URL，交系统浏览器打开。**零网络请求**，不受 403 影响 |
| **核验** | **仅国标** | Rust 调 SAMR JSON 端点 → 回填状态/日期/替代关系 → **人工确认**才写 |

**站点模板**（内置默认 + 旁路文件 `sites` 覆盖，Q26）：每条含站点名、适用层级、URL 模板（带占位符）、`supportsVerify` 标志。站点改版不必等发版。

**查询算法**（实测得出，见 §6）——三步，任一步失败即降级为纯跳转：

1. **用不带年份的标准号查询**（带年份对带点部分号会失配，见 §6 坑 2）
2. **客户端按身份键精确匹配**（规范化去空格后逐字比对），过滤掉同前缀的其它部分号
3. **按年份锁定版本**；年份未知时按 `现行 > 即将实施 > 草案 > 废止` 取

**回填口径**（Q25）：只更新本条记录；**顺带提示链上缺失的版本**（如"GB 1589 有 2026 新版未收录"），**不自动建档**。

**网络层**（Q27）：Rust `reqwest`（纯 Rust + rustls，无原生依赖）。理由——SAMR 返回的 `C_STD_CODE` 带 `<sacinfo>` 标签需清洗、需按身份键过滤，放前端等于把解析拆回两处，违反 §5.1 的单源约定。Rust 侧统一限流与失败降级。

**边界**：网络为**可选增强**。无网/请求失败/站点改版时，工具必须完全退化为 P0 的离线形态，不阻塞任何既有能力。

## 6. 权威站点实测与查询规律（2026-10-08/09 真实请求）

### 6.1 站点可达性

| 站点 | 覆盖 | URL 规律 | curl 可达 |
|---|---|---|---|
| **`std.samr.gov.cn`** 全国标准信息公共服务平台 | 国标 GB/GB-T | **JSON 端点，可自动查询回填** | ✅ 200，无密钥 |
| `hbba.sacinfo.org.cn` | 行标 | 搜索跳 `uac.sacinfo.org.cn/login` | ⚠️ 认证墙 |
| `dbba.sacinfo.org.cn` | 地标 | 同上（`system016-dbba`） | ⚠️ 认证墙 |
| `www.ttbz.org.cn` | 团标 | 需 JS，无稳定 URL 规律 | ⚠️ |
| `www.iso.org` | ISO | `/standard/<数字ID>.html`——**数字 ID 不可从标准号推导** | ❌ 403 |
| `unece.org` | UNECE 法规 | `/transport/vehicle-regulations-wp29/...`，R 编号可推导 | ❌ 403（规律已知，浏览器可开） |
| `www.sae.org` | SAE | `/standards/content/<小写代号>/`——**可推导**（`J3016_202104`） | ✅ 200 |

**只有国标能自动回填**；其余层级只能跳转。

### 6.2 SAMR 查询端点

```
GET https://std.samr.gov.cn/gb/search/gbQueryPage?searchText=GB%201589
→ {"total":7,"rows":[
     {"id":"5A13DAFA3A28AB2AE06397BE0A0ABC6B",
      "C_STD_CODE":"<sacinfo>GB</sacinfo> <sacinfo>1589</sacinfo>-2026",
      "C_C_NAME":"汽车、挂车及汽车列车外廓尺寸、轴荷及质量限值",
      "STATE":"即将实施","ACT_DATE":"2027-07-01","ISSUE_DATE":"2026-08-27",
      "STD_NATURE":"强制性","PROJECT_ID":1023090}, …]}
```

- 详情页 `gbDetailed?id=<row.id>`；**`id` 为不透明 32 位键，无法从标准号推导** → 必须"先查再拼"
- 人类可用搜索页：`gbIndexPage`
- 限流头：`Burst-Capacity: 200`、`Replenish-Rate: 80`——配额宽松但**有限额**，故核验仅手工触发（Q24）
- 详情页另有：全部代替标准、被代替、标准计划号、中国标准分类号、归口单位、起草单位、相近标准

**命中率实测：26/27 = 96%**（未命中的 `GA 802` 是行标，本就不在此端点）。

### 6.3 两个必须防的坑

1. **结果不按版本排序**——查 `GB 1589` 首条返回 **1989 废止版**；查 `GB 7258` 首条是 1997 版。**取第一条必错。**
2. **文本搜索会串部分号**——查 `GB/T 34590.1` 返回 `.10/.11/.12`。**必须客户端精确匹配**（实测规范化后精确匹配 5/5 正确）。

### 6.4 过期体检的实证价值

核验能力直接回答了 P0 无法回答的问题——**"我手里的版本过期了吗"**。实测两例：

| 记录 | 库内状态 | 权威结果 | 结论 |
|---|---|---|---|
| `GB 1589` | 2016 版 | **2026 版已发布**，2027-07-01 实施 | 库内版本将被替代 |
| `GB/T 34590.1` | **征求意见稿** | 已正式发布 **2022 版** | 库内是草案，非正式版 |

对比 §5.2 的 PDF 首页正则：覆盖仅 76%（扫描件全瞎），且**根本不产出"已废止"这个状态**。**权威端点显著优于正文提取**——这也降低了 Q16 预填的重要性（它是无网时的兜底，不是主路径）。

## 7. 分期

### P0 — 元数据索引（**先落，不依赖全文引擎**）

- 法规库独立路径选择与记忆；库根 `_regulations.json` 读写
- Rust 单源扫描：文件名解析 → 标准号/版本/名称/层级 + 「发布/实施日期」「代替 XXX」首页正则预填
- 人工确认入库表（勾选/行内编辑；解析失败者进「未识别」折叠区）
- 列表 + facet 筛选（层级 × 主题域 × 状态）+ 搜索
- 详情抽屉：版本链/替代关系、无文本层标注、未下载标注
- 进 Tab 自动比对文件清单，提示"未登记文件 N 个"→ 人工确认
- 状态由日期推导 + 人工覆盖位

### P1 — 全文检索 + 权威核验

**全文检索**（引擎见下）：
- 全文提取 + 增量后台跑 + 进度事件
- 搜索框：元数据 ∩ 全文合并，结果按标准聚合，展开正文档内片段
- 失败必须**显性标注**——"解析失败·不可检索"必须出现在列表与详情

**权威核验**（§5.4；仅国标）：
- 「权威查询」跳转链接（全层级）+ 「核验」按钮（国标）
- Rust `reqwest` 调 SAMR，按 §5.4 三步算法取数，**人工确认**后写回
- 回填状态/日期/替代关系；提示链上缺失版本
- 失败降级：无网/改版一律退回 P0 离线形态

**全文引擎升级路径（已验证方向，未实施）**：引入 **pdfium**（BSD-3）。代价是首个原生依赖：Windows + macOS 各带约 10 MB 动态库、CI 需加下载步骤（现 `.github/workflows/build.yml` 只构建 `nsis` 与 `dmg` 两平台）、`bundle.resources` 配置、运行期路径解析（macOS .app 内 / Windows exe 旁）、失败降级。
**若继续用纯 Rust 方案，必须接受 24% 失败且 7 份静默——不建议。**

> 全文与核验同属 P1 但**互相独立**：核验不依赖 pdfium（SAMR 返回 JSON，不经 PDF），可先落。

### P2 — 知识卡与扩展位

- `08_标准知识卡/` **只读扫描**，挂为标准的附属解读（0..N）
- **过期体检**：批量核验 + 列表显性标注（Q24 的 (c)，本期）
- 条款级合规基线的 **schema 预留位**（只留位，不实现）

## 8. 非目标（写进文档以防后来者"顺手补上"）

- **OCR**——为 26% 的扫描件引入中文 OCR（约 100 MB 模型 + 分钟级处理）不成比例；诚实做法是**告诉用户哪些搜不到**，而非假装搜得到
- 条款级参数化/合规基线**实现**（仅留位）
- 交叉引用（"引用谁"）——成本高、准确率低
- 与资产/参数的**一切**关联（关联键未选定，见 §9）
- `06` 过程文件的**制修订项目跟踪**（属项目协作，非本功能）
- **收编模式**（复制 PDF 入库）
- 顶栏全局搜索（跨模块）
- 自动核验（P2 才做）；**行标/地标/团标的自动回填**——站点有认证墙，只给跳转

**落地文件**

| 层 | 文件 | 说明 |
|---|---|---|

| 接线 | `MainLayout.tsx` + `App.tsx` | 顶栏「法规标准」Tab |

**与设计的两处偏离，各有理由**

1. **IO 层不做 JS 回退**（公告中心的 `announcementRecord.ts` 有）。理由：公告只读目录不解析命名，回退无风险；法规的**文件名解析是 Rust 单源**（Q18），在浏览器里重写一遍等于把双实现漂移带回来——正是本设计要消灭的东西。非桌面环境明确报错，不给行为不同的第二实现。
2. **`replaces` 存的是规范化标准号**（如 `GB/T 34590.1-2017`），不存整句。设计只说「提取」，未定形态；存标准号才能被身份键与版本链复用。

**真机验证（可重跑）**

`cargo test --lib probe_real_library -- --ignored --nocapture` → 真实库 55 个文件，**39 个解析出标准号**，标准号/年份/层级/名称逐条正确；未识别 16 个**恰是设计要排除的集合**（7 个项目过程文件、政策/白皮书/研究报告、无编号框架文档）。

`cargo test --lib probe_real_hints -- --ignored --nocapture` → 真实 PDF 首页预填：
- `GB 44495` → 文本层 has / 发布 2024-08-23 / 实施 2026-01-01 ✓
- `GB 44721` → 文本层 has / 发布 2026-07-30 / 实施 2027-07-01 / 代替 GB/T 44721-2024 ✓
- `GB/T 34590.1` → 文本层 has / 草案标记 + 代替 GB/T 34590.1-2017、ISO 26262 ✓
- `GB 1589` / `GB 7258` / `GB/T 41798` → **读不出**，`textLayer` 保持 `unknown`

**真机探针逼出的三个防御性修正**（合成测试没覆盖到）

1. **破折号变体**：`GB 44721` 的日期用的是 U+2043 HYPHEN BULLET（`2026 ⁃ 07 ⁃ 30`），不是常见连字符。现已覆盖 `- — – － − ⁃ ‐ ‑ ‒ .` 全部变体。
2. **压缩空白的假相邻**：lopdf 对部分 PDF 逐字符换行输出，压平后 `…23日实施日期：…` 会与前一字段假相邻；已用「前缀式需冒号、后缀式排除 `(日期)`」双向消歧。
3. **「读不出」≠「扫描件」**：首页探测分三态——有正文 / 打开但无文本（真扫描件 → `none`）/ 打不开（→ 保持 `unknown`）。前两者附带的 `textLayer` 是 P0「无文本层标注」的数据来源；把「读不出」错报成扫描件就是假阴性（`GB 1589` 恰好属于此类：读不出，但确有文本层）。

## 13. 风险

| 风险 | 应对 |
|---|---|
| 文件名解析覆盖不全（`（无标准号·扫描件）`、`征求意见稿`、`中英对照`） | 解析失败进「未识别」区，**不猜**；人工兜底 |
| 首页日期正则误抓 | 仅作**预填**，人工确认才入库；兼容 `—`/`-` 与"部分代替" |
| 引用失效（用户移动/改名 iCloud 文件） | 每次扫描比对，列表显性标"文件缺失" |
| Rust/TS 双实现漂移复发 | §5.1 单源约定 + 本文档留痕 |
| 并行会话污染工作树 | 本文档以**未跟踪文件**落盘；实现前重读目标文件现状（AGENTS.md 纪律） |
| **权威站点改版/限流** | 模板可配（Q26）；核验仅手工触发、可整体降级为跳转；**网络失败永不阻塞离线能力** |
| **SAMR 返回结构变动** | 客户端严格校验 `rows` 形状，字段缺失即降级为"仅跳转"，不写入半成品数据 |
| 网络出站与 ADR-0004 的关系 | ADR-0004 管**入站**只读面，不禁止出站；本设计的出站请求不含任何资产/参数数据，只带标准号 |
