# 上传回执修正 — 设计方案

> 日期：2026-10-20 ｜ 状态：**已实施**
> 来源：用户上传车上云后被拒，截图里 7 条报错要逐条回到 441 行里找字段手动改。
> 关联：[2026-10-19-车上云模板导出-design.md](./2026-10-19-车上云模板导出-design.md)、[2026-10-19-车上云导出预校验-design.md](./2026-10-19-车上云导出预校验-design.md)

## 1. 回执的形态（实测）

```
第[285]行  商品属性[前装易流温度监测设备]不存在
第[288]行  属性[燃料类型]的取值[/]有误
第[309]行  属性[尾板类型]必填
第[315]行  属性[尾门帘]的取值[对开门]有误
```

三类，与导出预检的分档一一对应：

| 回执措辞 | 含义 | 本地对应 |
|---|---|---|
| 商品属性[…]不存在 | 字段名不在车上云所选模板里 | 字段组与该次上传的类别模板不一致 |
| 属性[…]的取值[…]有误 | 枚举越界 | `enum_invalid` |
| 属性[…]必填 | 必填为空 | `required` + 空值 |

**关键事实**：回执行号 = 导出文件行号（表头为第 1 行），所以第 N 行恒等于字段组第 N−2 个字段。不必让用户自己数。

## 2. 设计

### 2.1 解析（`src/utils/uploadFeedback.ts`，纯函数）

- 只认 `第[N]行` 与 `属性[...]` / `商品属性[...]` 两类锚点；前面的序号列、空行、表头行自动跳过
- 行号解析用**严格括号** `/第\s*\[\s*(\d+)\s*\]\s*行/`，避免把 `[285]` 当成字段名
- 三类判定按措辞分支，值从 `取值[...]` 里单独取

### 2.2 字段定位（两级）

1. **按字段名**（回执自带名字，最可靠）
2. 对不上再用**行号**反查 `fields[N-2]`

两级都失败 → 保留回执原字段名，标为「无法识别」，交人工判断，不猜。

### 2.3 修正（就地，不跳页）

弹窗内每行一个「修正为」：

- 该字段有词表 → **下拉选合法值**（直接消除 `取值有误`）
- 无词表 → 文本框输入（用于 `必填未填`、字段不存在时的替代值）
- 单行「应用」或底部「应用全部修正（N）」

写入走与表格编辑同一条路径：`updateManualValue` + `setProductManualValue`（按车型留存）。

### 2.4 定位

行内「定位」按钮把字段名填进搜索框 —— 字段名在字段组内唯一，比滚动可靠。

## 3. 边界

- **不做**：从回执反推「应该导入哪份模板」。`商品属性不存在` 时只提示「确认字段组与所选类别模板一致」，因为本地拿不到车上云的模板清单。
- **不做**：自动重新上传。导出后仍由人工上传。
- 回执与当前字段组不同源（比如中途换过模板）时，行号会错位；字段名优先匹配正是为了兜住这种情况。

## 4. 测试

`src/utils/__tests__/uploadFeedback.test.ts`（12 例）：三类措辞解析、序号/空行/表头跳过、全角括号、无行号容错、行号反查、名字/行号都失败时的降级、分类计数。

## 5. 入口

字段组模式下，匹配结果工具条新增 **「上传回执修正」**。非字段组模式不出现——回执解析依赖「字段组顺序 = 导出顺序」这一前提。
