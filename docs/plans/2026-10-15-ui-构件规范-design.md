# UI 构件规范：把一致性做成结构性约束 — 设计方案

> 日期：2026-10-15 ｜ 状态：**已实施**
> 来源：2026-10-15 用户提问「两个页面的顶部搜索栏每个页面都不一样，想建立规范，根本原因是什么？」
> 视觉基准：曜蓝 v4.1（`docs/design-v4-obsidian-blue/`）
> 关联：`2026-10-01-asset-panel-layout-redesign.md`、`2026-10-08-regulation-library-design.md`、`2026-10-02-announcement-archive-grouped-view-design.md`

## 1. 问题：同一个意图，N 种写法

用户举例的两个页面（数据体检 / 智能填报）顶部工具条，**外层用的是同一个共享组件** `common/FilterBar` + `FilterItem`，但内容各写各的：

| 自由度 | 数据体检 `DataPurifyView` | 智能填报 `MatchResultTable` |
|---|---|---|
| 搜索控件 | `<Input>` | `<Input.TextArea autoSize>` |
| 宽度 | `style={{ width: 240 }}` | `style={{ width: 320 }}` |
| 图标 | `prefix={<SearchOutlined className="text-3" />}` | 无 |
| 标签 | `label="搜索:"` | `label="搜索:"` |

全仓实测（2026-10-15）：

**「搜索框」三种写法**

| 写法 | 处数 |
|---|---|
| 裸 `<Input>` + `prefix={<SearchOutlined /`} | 18（15 个文件） |
| `<Input.Search>` | 2 |
| `<Input.TextArea>` 当搜索框 | 1（智能填报） |

**「枚举/快捷筛选」四种编码**（同一个「从一组值里选」的意图）

| 写法 | 出现在 |
|---|---|
| 主按钮 `type={x === 'a' ? 'primary' : 'default'}` | 数据体检、智能填报 |
| `Tag.CheckableTag` | 公告归档 |
| `Checkbox.Group` | 法规标准 |
| facet chip + `Popover` | 资产池 |

**标签标点也在散**：`label="状态"`（无冒号）与 `label="搜索:"`（带冒号）混用——冒号由调用方自己拼。

## 2. 根本原因（分层归因）

| 层 | 内容 |
|---|---|
| **现象** | 每个页面顶部工具条都不一样 |
| **结构（要害）** | `FilterItem` 的签名是 `{ label, children }`——它抽象了**装控件的行**，把**用什么控件**完全下放给调用方。**抽象粒度选错**：规范的是标点怎么排，不是该用什么词。封容器不封控件，所以「用了公共组件」与「长得一样」是两件不相干的事 |
| **机制** | 半吊子抽象制造「已经规范过了」的错觉。开发者/AI 看到自己用了 `FilterBar` 即认为合规，不再追问控件形态。**半吊子抽象比完全没有抽象更危险——它关闭了继续治理的念头** |
| **元（根本）** | 一件事有 N 种都能跑通的写法时，一致性只能靠记忆维持。本项目有两个放大器：① **多个 AI 会话并行改同一工作树**（AGENTS.md 明载），每个会话只看局部、倾向就地手搓；② **成本不对称**——手搓零前期成本且完全贴合当下需求，找共享件要先理解接口。**没有任何机制惩罚手搓**，理性选择必然是手搓 |

**结论：根本原因不是「开发时没规范」，而是「规范没做成结构性约束」。**

规范现状核查：`docs/design-v4-obsidian-blue/` 全是 **token**（颜色/字号/间距，章节为「主色/字体排印/对比度」），`design-proposal.html` **没有一个章节讲组件**；`AGENTS.md` 无 UI 节；无 Storybook。**设计系统有词汇，没有语法。**

即：这是**「入口不唯一」导致的熵增**——同一件事没有唯一正确写法，系统就自发分化。

## 3. 对策：四层，强度递增

纯文档规范必然失效（依赖记忆）。必须让规范成为机器能判红的东西。

| 层 | 做法 |
|---|---|
| ① 补语法 | 建 `SearchInput` / `FacetChips` 两个控件，收窄 `FilterItem` |
| ② 让错误写法写不出来 | API 收窄到无自由度：不暴露 `children`/`size`/`prefix`，宽度只收 `'sm'\|'md'\|'lg'` |
| ③ 机器护栏 | 测试扫 `src/components/**`，断言不再出现手搓写法；串进 `npm run test`，CI 直接红（先例：`assetAlias.guardrails.test.ts`） |
| ④ 可发现 | AGENTS.md 加「UI 构件」节——AI 会话的入口在此，最该写的地方 |

本次落地 ①③④ + ②的 API 收窄；**存量 15 个文件不动**（存量豁免 + 增量强制）。

## 4. 构件规格

### 4.1 SearchInput（全应用唯一搜索框）

```tsx
<SearchInput
  label="搜索"            // 可选；冒号由组件补，调用方不写
  value={v}
  onChange={setV}
  width="md"             // 'sm' | 'md' | 'lg' → 映射到 token 宽度
  placeholder="搜索参数名、分组或参数值…"
  hint="支持换行搜索多个" // 可选；补在 placeholder 之后，不另起一行
/>
```

- 内部固定：`allowClear`、`prefix={<SearchOutlined className="text-3" />}`、`size="middle"`——**这些是规范的一部分，不是自由度**。
- 多值/换行搜索用 `multiline` 布尔（智能填报那种），而不是让调用方自选 `TextArea`——搜索框还是搜索框，形态由语义决定。
- 宽度三档常量取代 `240/320` 这类魔法数。

### 4.2 FacetChips（维度筛选 / 快捷筛选）

```tsx
<FacetChips
  label="状态"
  options={[{ value: 'anomaly', label: '发现异常', count: 18, tone: 'warning' }]}
  value={quick}
  onChange={setQuick}
  multiple={false}
/>
```

- 取代 `Tag.CheckableTag` / `Checkbox.Group` / 主按钮式快捷筛选三种既有编码，**统一为 chip**。
- `tone` 只收语义档（`'default' | 'warning' | 'danger'`），颜色不开放给调用方。
- chip 的尺寸/字号走 `.chip-md`（aux 档 12px）——与公告归档、资产池同档。

### 4.3 FilterItem 收窄

保留 `{ label, children }`（存量 3 个页面在用，不动），但**新代码一律用它包 `SearchInput` / `FacetChips`**，不再手搓控件。冒号由 `FilterItem` 统一补，调用方写 `label="搜索"`。

### 4.4 ListToolbar（列表页外壳，取代 FilterBar）

**它是本轮真正的收敛点。** 此前有两套结构做同一件事：

| | 形态 | 用在 |
|---|---|---|
| `FilterBar` | 无标题：筛选在左、操作按钮在右，同一行 | 数据体检 / 智能填报 / 结果对比 |
| `Card title extra` | 标题+按钮一行，筛选另起一行 | 公告归档 / 法规标准 |

二者只差一个标题，却长得不像。`ListToolbar` 合并为一套：标题行 / 筛选行按需出现，表格等作为 `children`。

```
┌────────────────────────────────────────────────────┐
│ 公告归档                    [导入][批量][迁移][刷新] │  ← title + actions（都省略则整行不渲染）
├────────────────────────────────────────────────────┤
│ [分组|平铺]  全部 有PDF 无PDF      [搜索____]        │  ← filters（省略则整行不渲染）
├────────────────────────────────────────────────────┤
│ children（表格等）                                  │
└────────────────────────────────────────────────────┘
```

- `padded={false}` 让表格贴边（列表页常用）。
- 分隔线只在「后面还有内容」时出现——否则末行拖一条悬空边框。
- 只传 `filters` 不传 `children` 时退化为一条筛选带，等价旧 `FilterBar`。
- **`FilterItem` 保留在原文件**（`common/FilterBar.tsx`），仍是合法的标签原语；被取代的只是 `FilterBar` 这个外壳。

### 4.5 护栏规则表（最终）

| 规则 | 禁项 | 正解 |
|---|---|---|
| R1 | `<Input.Search` | `SearchInput` |
| R2 | `prefix={<SearchOutlined` | `SearchInput` |
| R3 | `Tag.CheckableTag` | `FacetChips` |
| R4 | `label="…:"` / `label="…："` 自带冒号 | `FilterItem` 补冒号 |
| R5 | `<FilterBar`（旧外壳） | `ListToolbar` |

扫描前**剥注释**（规则讲解本身要能写出违规写法，否则护栏惩罚文档）；R2/R3 各有一处**唯一定义处**（构件自身），单独登记。R5 只匹配 JSX 用法、不匹配 import——按路径匹配会误伤仍在引用 `FilterItem` 的文件。

## 5. 护栏规格（`src/__tests__/uiConsistency.test.ts`）

用 `import.meta.glob('...', { query: '?raw', eager: true })` 读源文件（`tsconfig.app.json` 的 `types` 不含 node，不能引 `fs`）。

扫 `src/components/**/*.tsx`（排除 `__tests__`），对**非豁免文件**断言：

| # | 禁项 | 正解 |
|---|---|---|
| R1 | `<Input.Search` | `SearchInput` |
| R2 | `prefix={<SearchOutlined` | `SearchInput` |
| R3 | `Tag.CheckableTag` | `FacetChips` |
| R4 | `label="…:"` / `label="…："`（FilterItem 里自带冒号） | `FilterItem` 补冒号 |

**豁免机制**：`LEGACY_EXEMPT` 列出 15 个存量文件 + 每条的处数。护栏断言「豁免清单里的文件仍存在（防陈旧）」「豁免清单不新增（防被当成合法通道）」，并输出当前存量计数。存量清零后删表。
