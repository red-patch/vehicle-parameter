# 手机查看（移动端只读资产视图）— 设计方案

> 日期：2026-10-08 ｜ 状态：**设计已确认；P1（服务端 + 令牌 + 配对）已实施，P0（隧道）待人工执行**（决策记录见 §2，实施记录见 §13）
> 关联：`docs/adr/0004-read-only-remote-access-surface.md`（本文档的架构裁定）、`docs/adr/0002`（身份键与永不静默覆盖）、`docs/adr/0003`（每车最新版）。
> 术语：`CONTEXT.md`（资产 / 资产库 / 受控属性 / 身份键 / 每车最新版 / 公告比对）。

## 1. 背景与目标

### 1.1 现状

工具目前是纯本地单机 Tauri 桌面应用。文档全库（PRD / CONTEXT / 3 份 ADR / 48 份 plans）**零处提到**移动端、云端、账号或多用户——移动端不是被否决过，是从未被考虑。

数据离开本机的既有通道只有三条：文件系统、导出文件、系统剪贴板。**本仓库无任何网络能力**：`Cargo.toml` 无 `reqwest`/`hyper`/`ureq`，`tauri = { features = [] }`（连 `http` feature 都未开），`capabilities/default.json` 无 `http:*` 权限，`src/` 中 `fetch(`/axios/XHR/WebSocket 零命中。（`Cargo.lock` 里的 reqwest 只是 tauri 自身的传递依赖，应用代码够不着。）

已有可借用的产物：`src/utils/reportExport.ts` —— 自包含单文件 HTML 报告（曜蓝主题、内联 CSS、零外部依赖、自带打印样式），三份报告共用（`compareReport` / `diffReport` / `assetUpgradeReport`），**且已专门处理窄屏**（`.rp-table-scroll`，`reportExport.ts:204`）。

### 1.2 目标

1. **随时随地只读查看资产数据**：手机浏览器打开即用，可加到主屏；不要求与电脑同网。
2. **对比**：像汽车之家那样横向滑动、车列冻结地对照 2–5 台车的完整参数。
3. **轻量分享**：把对比结论做成可转发的东西。
4. 全程**不修改任何资产数据**。

### 1.3 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 手机端任何写操作（改名/标签/删除/填报） | ADR-0002「永不静默覆盖」；一旦能改，这条红线要在移动端重新发明一遍 |
| 离线缓存参数内容 | 需要 Service Worker；依赖安全上下文，且与「不缓存」的取舍已定（§2 Q16） |
| 多用户 / 账号体系 / 权限分级 | 单人自用 |
| 设备吊销与已配对设备列表 | Q15=a 明确不要（**已知代价见 §8.1**） |
| 推送 / 通知 | 无此场景 |
| WebRTC | 见 §3.3 |
| 公告比对进入第一版 | 领域上最契合（`CONTEXT.md:79`「以公告记录参数为基准、逐项核对……只读检查。公告为准」），但会扩大首版面，排第二版（§9） |

## 2. 决策记录（为什么是这样）

逐条来自质询会话。**被否的选项同样记录**，因为它们是这个设计最容易被误推翻的地方。

| # | 决策 | 被否的选项与理由 |
|---|---|---|
| 使用者 | 用户本人；手机是「第二屏」而非替代品 | 没有桌面端的同事 / 外部人 —— 涉及账号与收回控制，选 A 成立后再谈 |
| 场景 | 随时随地（公网可达），只要电脑端程序在跑 | 仅同局域网 / 仅可控网络 —— 按最贵的 a 做设计，覆盖其余 |
| 形态 | 手机浏览器 + 加到主屏；桌面端内置只读 HTTP 服务 | 真·云（与三个 ADR 的本地文件语义冲突）；Tauri 移动原生 app（打包不难，难的是「手机上那份数据从哪来」） |
| 观感 | 同一产品延续（同一主题、同一术语），**信息架构为窄屏重做** | 照搬桌面三栏 —— 那本来不是给窄屏设计的 |
| 列表单位 | **每车最新版**为默认，可展开看历史版本 | 单个资产 —— 同车可并存多版本，裸列会重复；车型组 —— 粒度太粗 |
| 首屏 | 最近看过 + 收藏（手机本地记录） | 按 `updatedAt` —— 那是**导入时间**，与「你现在关心哪几台」无关，首屏大概率是不关心的车 |
| 全库 | 可下钻（搜索 + 受控属性筛选），528 条 metadata 一次性下发 | 只给精选 —— 答不了「有没有这台车」；纯关键词搜索 —— 答不了「某厂商某电量段」 |
| 详情 | 受控属性摘要 → 点进看全部参数 | 只给受控属性 —— 横向对比需要完整参数才有意义；一屏 500 条在手机上不成立 |
| 对比入口 | 列表多选为主，详情页「加入对比」为辅 | —— |
| 对比交互 | 横向滑动、车列冻结、差异置顶、相同项默认折叠 | 复刻 DiffViewer —— 见 §3.5，它是死代码，且双栏设计不适合窄屏 |
| 认证 | **每设备一个长期 token**（Q14=C） | 网络层身份（§3.4 免费栈下不成立）；**共享长期码（明确反对）** —— 泄露后唯一补救是换码 = 全员重配，正是要躲的痛点；共享码无法单设备吊销 |
| 传输 | 隧道 + 本地明文 HTTP（TLS 在隧道边缘终止） | 明文 HTTP 走公网（长期 token 会明文出境）；**WebRTC**（§3.3） |
| 端到端加密 | **不加**，接受边缘可见内容 | **应用层 E2E（Alma `relay.alma.now` 路线）** —— 已评估并否决，三条理由见 `docs/adr/0004` 与 §8.4 |
| 服务绑定 | **只绑 `127.0.0.1`**，只从隧道出去 | 绑 `0.0.0.0` —— 会让同一 WiFi 下任何人读到全部车辆参数 |
| 服务开关 | app 启动即自动监听，但界面有**显眼状态指示 + 一键关** | 手动开（会忘）；静默开（你从不知道端口开着） |
| 配对 | 二维码（地址 + 一次性码 → 换长期 token） | 手输短码（隧道域名又长又难打）；桌面弹窗确认（慢一步） |
| 配对位置 | **接受「配对必须人在电脑旁」** | ——（已知限制，见 §8.2） |
| 离线 | 不缓存；连不上显示**一句话** | 浏览器默认错误页（在客户现场像坏了）；区分「电脑关了」与「隧道断了」（隧道断时技术上探测不出，做出来会撒谎） |
| 分享 | 能 `navigator.share` 就分享，否则退化为下载；只出**对比报告 HTML** | Markdown（桌面那两份是给 AI 读的，手机不需要）；单车参数报告（截图更快） |
| 复用边界 | 只复用**领域层**（零耦合的 stores + 纯函数） | 复用桌面组件（背 antd+xlsx 包体，且 `DataSourcePanel` 带写路径，见 §5.1） |
| 构建 | `src/mobile/` 独立入口、**独立构建** | 同构建第二入口（无法保证不带桌面依赖树） |
| 已取代/停用资产 | 默认隐藏 + 一个「显示历史版本」开关 | 完全不显示（「这台车怎么没了」无法自查）；灰掉混排（窄屏噪音） |
| 命名 | 界面上叫「**手机查看**」 | 「移动端」（设备分类，违反「文案不解释内部实现」）；按场景命名（把使用场合限窄了） |
| 落盘 | 本设计文档 + ADR-0004 | —— |

## 3. 架构

### 3.1 数据通路

```
手机浏览器 ──HTTPS──> 隧道边缘（TLS 终止，可信证书）──隧道──> cloudflared（笔记本，仅向外连）
                                                                    │
                                                                    v
                                                     Rust HTTP 服务（绑 127.0.0.1）
                                                          │ 读文件系统
                                                          v
                                                   资产库目录 ~/车型数据库
```

要点：

- **笔记本不开任何入站端口**。`cloudflared` 主动外连隧道边缘，本地服务只绑 `127.0.0.1`。
- **局域网内完全不可见**。这消灭了「喝咖啡时连着别人 WiFi」这类暴露面，也让「只绑回环」成为可能。
- **TLS 在边缘终止**。Rust 服务跑明文 HTTP，**无需管理任何证书**。
- 代价（如实记录）：**隧道边缘能看到 token**。缓解是「每设备 token + 无踢设备需求」，风险等级为「商业公司边缘」而非「某人的公共转发节点」（对照：公共 frp 的运营方免责声明明确列出窃听/中间人/篡改且无保密承诺）。

### 3.2 为什么由同一个服务托管移动端页面

移动端页面由该 Rust 服务**同源**托管（`/` 起），不单独托管。理由：

- 同源 → 无 CORS、无跨站点凭证问题（长期 token 走 cookie 时这点直接决定复杂度）。
- 桌面端服务与移动端页面**天生同生共死**——电脑没跑，页面也不该开。
- 单独托管（如 Cloudflare Pages）的唯一好处是页面可被 CDN 缓存，但数据比页面重，收益很小。

### 3.3 为什么不是 WebRTC

WebRTC 在**同局域网**场景是被支配的选项，且引入不可控风险：

| | WebRTC 数据通道 | 隧道 + HTTP |
|---|---|---|
| 内置信令 | **无**（SDP/ICE 必须带外交换，局域网里最后仍是个 HTTP 端点） | 不适用 |
| 穿 NAT | 不需要（且同网段时是退化情形） | 隧道负责 |
| 吞吐（局域网） | ~100 Mbit/s | ~300 Mbit/s（TCP 更快） |
| 加密 | DTLS —— **不比 TLS 多任何东西** | TLS（边缘终止） |
| 首字节 | ICE + DTLS 握手（~60–90 ms 惩罚） | 几乎无 |
| iOS 明文源 | **Safari 被广泛报告禁用**（规范与 MDN 均未禁，Apple/WebKit 无一手文档说明）；Google 公共 STUN 在中国大陆常年不可用 | 安全上下文成立 |

另：`*.ts.net` 之类依赖 Tailscale 控制面，在中国大陆可达性不稳定（有一手报告：2026 年某 China Mobile 线路因 ML-KEM ClientHello 被 ISP 静默丢弃而无法连控制面，`tailscale/tailscale#20777`），且 **Tailscale iOS app 不在中国区 App Store**。

结论：传输用「隧道 + 本地 HTTP」，把复杂度交给一条成熟的隧道；「数据层面在移动端按需重组」这一原则独立成立，与传输选型无关（§4.1）。

### 3.4 免费接入栈（Q18）

约束链：手机要访问 → 必须公网可达 → 长期 token 要过公网 → **必须可信 HTTPS** → 浏览器信任的证书 → 必须控制一个域名。

**中国大陆不存在「零第三方账号 + 零 VPS」且同时满足上述要求的方案**（家宽普遍 CGNAT、80/443 入站被封、部分运营商主动封停跑 TLS 的线路；自签证书过不了 iOS 安全上下文）。

选定栈：

| 环节 | 选择 | 关键事实 |
|---|---|---|
| 域名 | **DigitalPlat `.dpdns.org`**（免费） | 支持 NS 委派、已在 PSL 上（Cloudflare 接受为 zone）、**无需实名**；每账号默认 1 个；需 GitHub OAuth；**365 天手动续期，过期即删除且他人可注册** |
| 隧道 | **Cloudflare Tunnel（具名）** | 免费档一直免费；稳定主机名 + 浏览器信任的 HTTPS；`--protocol http2`（默认 QUIC/UDP 在大陆常被限速或丢包） |
| 认证 | **应用自带每设备 token** | 因此**不需要** Cloudflare Access，绕过其「免费档也要填支付信息」的条款 |

**未决事实（落地前必须实测，§10）**：Cloudflare 官方文档自相矛盾——Zero Trust 开通页称免费档也要填支付信息（不扣费），而**具名隧道的 CLI 流程页**（`cloudflared tunnel login` → `tunnel create` → `route dns` → `run`）通篇未提 Zero Trust 组织与支付信息。二者很可能是不同入口（CLI 走 Zero Trust 之前的老路径）。若实测要卡号，退路是 **zrok**（官方定价页明确 "No credit card required"，保留名 `myapp.share.zrok.io` 跨重启持久；代价：无卡账号给访客弹一次反钓鱼提示页，且大陆可达性与证书信任链未证实）。

> 已否决的免费选项（记录以免重走）：`trycloudflare` 临时隧道（**每次重启换网址** → 打回重新配对）；**serveo.net**（保留主机名属 Pro $60/年，免费档子域只是「通常重复」不保证）；ngrok 免费（有稳定 dev domain 但大陆可达性不可靠）；cpolar 免费（子域 24 小时内会变）；公共 frp 节点（运营方可见明文、节点随时消失）；国内穿透类（1 GB/月、多数要实名、部分只能 PC 端管理）；`eu.org`（申请队列失控：二级域名从两天到三年，有 2023 年申请 2026 年才批的案例）。

### 3.5 对比为什么不受 DiffViewer 约束

`DiffResultView.tsx`（517 行）**当前不可达**：`MainLayout.tsx:21-52` 的导航项是 `pool, compare, fill, purify, announcement, dict`，**无 `'diff'` 键**，`App.tsx:104` 那个分支永不显形（源码自注 "Hidden from Menu but logic kept for safety"）。它的两个输入是 store 里的两个**上传的 Excel**，不是两个资产。

项目里活着的比对模型只有三个：跨车型多列对照（`CompareView.tsx`）、导入差分（`ImportDiffModal`）、公告比对（`announcementCompare.ts`）。移动端对比**不复刻任何一者**，采用窄屏友好的形态（§5.2）。

## 4. 服务端设计

### 4.1 四个端点

| 端点 | 返回 | 量级（实测口径见 §11） |
|---|---|---|
| `GET /api/assets` | 全库 metadata（每资产 ~200 B） | 约 100 KB（520–530 个资产） |
| `GET /api/assets/:file` | 单个资产完整参数 | 约 200–230 KB（中位数 503 条，最多 706 条） |
| `GET /api/facets` | 受控属性（词表 + 组级/资产级取值） | 小 |
| `GET /api/tags` | 标签与标签组 | 小 |

设计要点：

- **`/api/assets` 返回 metadata-only**，直接对应既有的 `scan_asset_library`（`src-tauri/src/assets.rs:223`）——它本来就返回 `AssetFileInfo[]`（`fileName, productName, updatedAt, totalParams, filledParams, announceNos, vehicleModel, hasAdmissionInfo, approvalStatus, manufacturerRaw, batteryBrandRaw, capacityRaw, admissionLevelRaw, admissionNos`），**不含参数内容**。这是「按需调度」原则的落点：手机说要看什么，才送那一个资产。
- **`facets` 与 `tags` 独立成端点**，因为它们在领域上就是独立旁路数据（`assetFacets.ts` / `assetTagGroups.ts`）。打包进 `/api/assets` 会让每次列表请求都变重。手机首屏要显示受控属性摘要，必须单独取。
- 全库 107 MB **永不整体下发**；单次对比只涉及 2–5 台车（~1 MB）。
- 路径前缀 `/api` 为实现细节，端点划分不变。

### 4.2 认证：每设备长期 token

- 配对成功后，服务端签发一个**长期有效**的凭证，浏览器持久化（推荐 **HttpOnly + Secure + SameSite=Lax cookie**，由服务端在配对响应里 Set-Cookie；好处是 JS 读不到、免手写存储与过期逻辑）。
- 凭证名单落一个 **sidecar JSON：`_mobile_devices.json`**，放在资产库目录。命名沿用既有惯例（下划线前缀 = 被资产扫描谓词排除，同 `_asset_tags.json` / `_asset_meta.json` / `_facet_vocab.json`）。
- **不做**设备列表 UI、**不做**吊销操作（Q15=a）。**但名单仍然保留**——它是「泄露后能换码而不必全员重配」的唯一凭据（§8.1）。

### 4.3 配对流程（二维码）

1. 桌面端「手机查看」面板点「配对手机」→ 显示二维码。
2. 二维码内容 = 隧道地址 + **一次性配对码**（短时效）。
3. 手机扫码打开 → 自动带一次性码请求配对接口。
4. 服务端校验一次性码 → 签发长期凭证（Set-Cookie）→ 手机进入应用。
5. 一次性码立即失效。

**已知限制**：换手机、加第二台、二维码失效后重配，**都必须回到那台电脑前**。用户已明确接受（Q36）。

### 4.4 开关与状态指示

- app 启动即自动监听；面板显示**显眼的「正在对手机开放」状态**与**一键关断**。
- 理由：一个你不知道开着的服务，和「你知道自己开着一个服务」，在客户现场的安全感完全不同。这等于给资产库加了一个**网络暴露开关**，该事实已记入 ADR-0004。

## 5. 移动端设计

### 5.1 复用边界：只复用到领域层，不搬组件

Tauri 耦合**只汇聚在 3 个模块**：`src/utils/assetManager.ts`（815 行，文件头 `:1-2` 静态 fs import，唯一数据源）、`assetTagGroups.ts`、`assetFacets.ts`。19/112 个生产文件碰 `@tauri-apps`（17%），**零个 store 碰 Tauri**。

| 层 | 内容 | 处置 |
|---|---|---|
| **领域层（白拿）** | `vehicleStore`（612 行，纯）、`vehicleSelectors`、`comparator`、`facetFilters`、`assetTagFilters`、`vehicleInstance`、`vehicleStats`、`compareReport`、`reportExport`、`themeConfig` —— 均 0 Tauri 引用 | **直接复用** |
| **数据源（缝）** | `assetManager` / `assetTagGroups` / `assetFacets` | **换成 HTTP 客户端** |
| **桌面组件（不搬）** | `DataSourcePanel`（~1680 行）、`FileManager`（763 行）、`AssetFilterPanel`（399 行） | **重写** |

不搬组件的三条理由：

1. **包体**：桌面端带 antd + xlsx。经 §14 实测，此链路的瓶颈是**往返延迟（约 300–400 ms/次）而非带宽（约 9–13 Mbps）**——故该决定的真实理由是**避免移动端把大包下载完还要在手机上解析执行**（5 MB JS 即便按 9 Mbps 也要 ~4.4 s 传输 + 解析），而非"带宽不够"。
2. **写路径**：`DataSourcePanel` 的加载流程里带写盘动作——`saveAssetTags` / `saveAssetMeta`（`:184-188`）、`saveFacetVocab` / `saveFacetValues`（`:433` 附近）、`batchAddAssetTags`（`:773` 附近）。其中主文件→关键车型的迁移（ADR-0003）**有 `primaryFileNames.length > 0` 守卫**（`:175`），只对尚未迁移的存量库触发——**因此这是条件性风险而非必然风险**：在已迁移的库上不会写盘，但一个未迁移的库会让只读端一加载就写。对只读端而言，「不取决于库状态」比「通常不写」重要，故仍不搬。
3. **写动作面**：桌面组件的对象级动作（重命名 / 激活 / 删除 / 标签 / 公告关联）集中在 `useAssetActions.tsx`。搬组件等于把整个写动作面拖进只读端。

另有事实支撑「跑在浏览器里」可行：app 今天**在纯浏览器中即可启动并画出界面**——`invoke` 只在调用时 TypeError，模块求值不炸，所有读路径 catch 后返回 `{}` / `[]`；`main.tsx:22` 与 `sessionPersistence.ts:12` 均已有「非 Tauri / 纯浏览器 dev」的显式意图。

### 5.2 信息架构

**首屏** —— 最近看过（本地记录）+ 收藏入口；可下钻到全库（搜索 + 受控属性筛选：主机厂 / 电池品牌 / 电量 / 准入等级）。不复刻桌面 399 行筛选面板——它是为批量治理设计的，不是为找一台车。

**列表** —— 一行一台车（每车最新版）；每行带受控属性摘要；长按多选（复用既有 `src/hooks/useLongPress.ts`，101 行）。已取代/停用默认隐藏，一个「显示历史版本」开关放出来。

**详情** —— 首屏受控属性摘要（十几项）→「查看全部」进二级页看完整参数（~500 条，靠分组导航 + 搜索）。底部「加入对比」。

**对比** —— 横向滑动、**车列冻结**、**差异置顶**、**相同项默认折叠**（往下滑即完整横向表格）。选中 N 台后进入。不复刻 DiffViewer 双栏。

**分享** —— 对比结果生成自包含 HTML（复用 `reportExport.ts`），`navigator.share` 优先（安全上下文成立故可用），不能则退化为下载。

### 5.3 本地存储（只存指针）

存三类，**均不含参数内容**：浏览记录、收藏、对比选择。用 localStorage 即可，不需要服务端参与。

注意：手机浏览器的标签页会被系统回收（iOS/Android 常态），所以「选了 3 台车然后被清空」必须避免——这与「不缓存数据」（§1.3）不冲突：只存「选了哪些」，不存参数。

### 5.4 失败与降级

连不上时显示**一句**：「电脑端未运行或网络不可达」。

不区分「电脑关了」与「隧道断了」——隧道断开时**技术上无法探测出是哪一种**，做出来会撒谎。不用浏览器默认错误页（在客户现场像坏了）。

### 5.5 状态模型与路由

移动端**不需要路由**：桌面端本来就不是路由驱动（`App.tsx:44` 一个 `useState('pool')`，四个模块常驻挂载 + `display:none` 切换），这种「单页多视图」结构对移动端单页挂载天然友好。移动端用同样的视图状态切换即可，无 URL 路由，因此 `/api/*` 与页面路径不会冲突。

## 8. 风险与已接受项

### 8.1 已接受：无设备吊销（风险最高的一条）

Q15=a + 长期 token ⇒ **手机丢了就是个洞，且放弃了唯一的补救手段**。接受前提是「这台手机只归本人用、不装不干净的东西」。

缓解（已内建于设计，成本为零）：`_mobile_devices.json` 名单**仍然保留**——它让「万一要补救」时能**换码而不必全员重配**（这正是共享长期码做不到的）。

### 8.2 已接受：配对必须人在电脑旁

换手机、加第二台、二维码失效后重配，都需回到那台电脑前。典型「平时没事、真需要时才发现」的限制。

### 8.3 已接受：免费域名的失败模式

`.dpdns.org` 365 天、**手动续期**（窗口约提前 180 天开）。**过期即删除、他人可立即注册**。它掉了 = 地址变 = 所有手机重新配对（而 §8.2 说配对要人在电脑旁）。

**运维动作**：设一个日历提醒在续期窗口开时处理。纯运维，不需为它改设计。

### 8.4 已接受：隧道边缘可见 token 与全部参数

TLS 在边缘终止，故边缘能看到请求内容——**包括 token 与全部车辆参数**（不只是元数据）。对照 §3.1：这是商业公司边缘，不是无保密承诺的公共转发节点。

**这是远程面唯一的实质让渡**，后续任何加固的收益都必须相对它衡量。已评估并否决的加固路线（应用层 E2E）见 `docs/adr/0004` 的 Considered Options 与 `docs/research/2026-10-08-alma-relay-remote-access.md`——结论是：在浏览器客户端下，E2E 的保证被「谁发页面、谁控制页面」封顶，只防被动记录、不防主动攻击，收益边际而代价不小。

### 8.5 电脑在线性

方案的地基是「那台电脑在跑」。Q12：用户自行解决睡眠问题。需要记住的是——**app 进程、隧道客户端、机器本身三者必须在位**；机器睡着时前两者都不存在。

### 13.2 途中发现并修复的既有 bug（**非本方案引入**）

`src-tauri/src/assets.rs` 的 `AssetFile` 反序列化用 snake_case 字段名（`product_name` / `updated_at` / `created_at`），而真实资产文件是 camelCase，且无 `rename_all`/`alias`。**该 struct 自 `16826e5`（v4.9.0）引入起即如此**，后果：

| 字段 | 修复前 | 影响 |
|---|---|---|
| `productName` | 恒为 None → **回退成文件名** | 列表显示名可能不等于真实车型名 |
| `updatedAt` | 恒为 None | ① `latestOf`（`assetGovernance.ts:186`）第一排序键失效 ⇒ ADR-0003「每车最新版」实际按 `filledParams` 定链头；② 桌面列表排序比较器（`DataSourcePanel.tsx:186-188`）对 null 对称返回 1/-1，不自洽；③ 列表从未渲染过时间戳 |
| `createdAt` | 恒为 None | `updatedAt` 的兜底失效，进一步加剧上条 |

**JS 兜底路径（`assetManager.ts:285-286`）读的是 `parsed.productName` / `parsed.updatedAt`，一直是对的**——两条路径长期不一致。

**已在 `feat/mobile-viewer` 修复**（给 `AssetFile` 加 `#[serde(rename_all = "camelCase")]`），并得到真机判别性证据（`cargo test -- --ignored real_library_scan`）：

```
资产数=519  有更新时间=519   productName 与文件名不同=11
```

即 `updatedAt` 覆盖率从 **0/519 → 519/519**，修复前为 0 是判别性证据（同 struct 同受 `rename_all` 影响）。11 个「与文件名不同」的资产反过来证明取的是文件内容而非回退值。

> **该修复不依赖手机查看方案**，若 `feat/mobile-viewer` 迟迟不合并，值得单独摘一个提交回 `main`。

> **对 P1 的连带意义**：`/api/assets` 的元信息直接复用同一扫描函数，若不修，移动端首屏的「最近看过/每车最新版」排序会与桌面端同步出错。

## 14. P0 网络实测（2026-10-08/09）

### 14.1 环境与方法

- 桌面：macOS，`cloudflared 2026.10.0`，**Cloudflare 临时隧道**（`--protocol http2 --url http://127.0.0.1:8080`），本地服务为 `python3 -m http.server`。
- 客户端：用户手机 **4G**。
- 负载：随机十六进制 JSON（**不可压缩**，避免 CDN 压缩污染测量）。已核对响应无 `content-encoding`、`content-length` 与实体一致、`cf-cache-status: DYNAMIC`。
- 计时：页面内 `performance.now()` 包住 `fetch` + `await res.text()`。

### 14.2 结果

| 负载 | 大小 | 手机 4G 耗时 |
|---|---|---|
| 小请求 | 200 KB | **400 ms** |
| 中等 | 1 MB | **921 ms** |
| 较大 | 3 MB | （未测，按 1 MB 外推 ≈ 2 s） |

证书：`subject=CN=trycloudflare.com`、`issuer=Google Trust Services WE1` ⇒ **手机零安装、无警告**。本条同时证实了 §3.1「隧道使 HTTPS 证书成本消失」的预期。

### 14.3 结论（**推翻了一条原假设**）

**瓶颈是往返延迟，不是带宽。**

- 200 KB 用 400 ms ⇒ 其中约 300–400 ms 是固定开销（RTT + TLS），传输本身可忽略。
- 1 MB 用 921 ms ⇒ 扣掉固定开销后边际吞吐约 **9–13 Mbps**。

因此：

| 原假设 | 实测后的正确表述 |
|---|---|
| 「大陆走隧道本来就慢，首屏体积是能不能用的问题」 | 带宽**宽裕**；真正的代价是**每次请求约 400 ms 的固定开销**。体积仍要克制，但理由是**手机解析执行成本**，不是下载成本。 |
| （隐含）数据量要省着用 | 数据量不是约束：单资产 200 KB / 400 ms，全库元信息 100 KB 同量级。 |

**由此确立的实施要求**（对 P3/P4 有约束力）：

1. **按往返次数优化，而非按字节数**。任何"再加一个端点"都要按 +400 ms 计价。
2. **对比场景必须并行拉取**：N 台车串行约 N × 1 s，并行约 1 s。
3. **搜索/筛选一律本地做**（验证 §2 Q35：528 条元信息一次下发，而非每次输入问服务端）。
4. **验证 P1 未加 `/api/vehicles` 的决定**：按车分组在移动端做（复用领域层 `computeCarVersionGroups`），省掉一次往返。
