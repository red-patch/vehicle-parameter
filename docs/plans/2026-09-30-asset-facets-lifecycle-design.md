# 资产多维度筛选与全生命周期管理 — 设计方案

> 日期：2026-09-30 ｜ 状态：P1–P4 已实施（同日落地；实施备注见 §9 末尾）
> 领域术语见 `CONTEXT.md`，关键决策见 `docs/adr/0001`、`docs/adr/0002`。
> 前置文档：`2026-09-28-asset-governance-primary-design.md`（治理模型）、`2026-09-29-asset-grouped-view-design.md`（分组视图）。

## 1. 背景与目标

资产管理复杂度上升（现存量 255 资产/67 车型组，且持续导入新数据），需要：
1. **多维度筛选**：主机厂、车型族群、公告号、电池品牌、电量、准入等级自由组合横切，快速定位目标车型做对比；
2. **全生命周期闭环**：导入 → 存在性判断 → 更新/版本化 → 删除，规则明确，杜绝重复与覆盖事故；
3. **性能不降**：按 1 万资产设计，筛选即时响应（<50ms），不触发全量持久化。

## 2. 领域模型（摘要）

- **受控属性（Facet）** 与标签分离。标签只留自由观点（"关键车型"等）与来源标签。
- 两层粒度：
  - **组级**（一组一值，组内继承）：主机厂、车型族群；
  - **资产级**（组内可多值、可缺失）：公告号、电池品牌、电量、准入等级。
- **浏览主干**只用「主机厂 → 车型组」；其余维度一律横切（维度内 OR、维度间 AND）。车型族群**不是**树层级——它是组级属性，横切才能支撑"跨主机厂比同类族群"。
- **身份键**：有公告号 = 公告号；无公告号 = 车型组 + 产品名。文件名、内容哈希都不是身份。

## 3. 数据设计

### 3.1 词表文件 `_facet_vocab.json`（库目录内，人工维护）

```jsonc
{
  "manufacturer": [   // 主机厂（Q15 裁定 C：法人级为值 + 集团归属折叠）
    {
      "name": "上汽大通汽车有限公司",   // 法人级规范名（筛选值）
      "group": "上汽大通",             // 集团归属（面板按集团折叠多选；单法人集团与 name 相同）
      "aliases": ["上汽大通", "上汽大通汽车有限公司南京分公司", "上汽大通南京分公司"]
    }
  ],
  "batteryBrand": [   // 电池品牌，同构
    { "name": "宁德时代新能源科技股份有限公司", "group": "宁德时代", "aliases": ["宁德时代", "宁德"] }
  ],
  "vehicleFamily": ["大面", "中面", "小卡", "微卡", "轻卡", "无人车"],  // 车型族群
  "admissionLevel": ["Ⅰ", "Ⅱ", "Ⅲ", "Ⅲ1", "Ⅲ2", "Ⅲ3", "Ⅳ"]          // 准入等级
}
```

- 主机厂粒度：**法人级为值 + 集团归属折叠**（ADR-0001）；同集团不同法人不合并（"时代上汽"与"上汽时代"仅标同集团）。
- 电量、公告号是开放数值/编码，不进词表。

### 3.2 取值与人工修正 `_facet_values.json`（库目录内）

- 资产级取值**自动派生为默认**（§4），人工修正以覆盖层落盘（与 `_asset_meta.json` 的 groupName 别名同构）：
  `assetLevel: { [fileName]: { manufacturer?, batteryBrand?, capacityKwh?, admissionLevel?, announceNos? } }`
- 组级取值：`groupLevel: { [groupKey]: { manufacturer, vehicleFamily } }`（约 67 行起步，持续增长）。
- 缺失 = 不写键，语义为"无"（合法状态，非错误）。

### 3.3 既有旁路文件职责不变

`_asset_tags.json`（自由标签）、`_asset_meta.json`（groupName 别名/主文件/status/note）。厂商、准入等级两个互斥标签组**退役**（值迁入受控属性），"车型族群"标签迁为组级属性后退役。

## 4. 自动派生与归一化

派生字段加在 `src-tauri/src/assets.rs`（`scan_one` / `AssetFileInfo`）+ `assetManager.ts` 双端对齐。

| 维度 | 主源 | 回退源 | 覆盖率（全量 255 实测） |
|---|---|---|---|
| 公告号 | 参数（已有） | 文件名 token（校验） | 已实现 |
| 电量 | 参数 `动力电池包电量（kWh）` | 文件名数字 | 合并 97.6% |
| 电池品牌 | 参数 `动力电池包厂商` | 文件名 token / `动力电池单体生产企业` | 96.5% |
| 准入等级 | 参数 `产品等级标准` | 文件名尾部罗马数字（两源零矛盾） | 79%（标签仅 29%，迁出后自动回填） |
| 主机厂 | 参数 `整车生产企业` → `公告申报企业` → `企业名称` | 词表别名归一 | ~93%（空串 18、`/` 3 待清洗） |

**归一化一次性裁定**（已确认，写入规则不再反复）：
1. 电量双值 `100.07;120.27` → 取首值，原文保留在派生备注；
2. 电量括号注记 `15.456（1/3C）` → 剥离注记；
3. 文件名与参数电量冲突（43 vs 43.534）→ **以参数为准**；
4. 等级 `VI`（ASCII，1 例）→ 修正为 `Ⅳ`；
5. `时代上汽` / `上汽时代` 不合并，词表标同集团；
6. 等级词表补 `Ⅲ`（独立值，不归入 Ⅲ1/Ⅲ3）。

通用归一：小数位补齐（55.7 → 55.70 口径统一）、`kWh` 后缀与裸数统一、主机厂/电池品牌按词表别名归一到规范短名、尾部空白/`\t`/`\r\n` 复合串清洗。

**词表外新写法**：不猜测归并，进治理体检"待归类"清单，人工确认后入表（错别字如"重创新航""瑞普兰均"、旧名"中航锂电"都走这条）。

## 5. 筛选交互

- **面板**：DataSourcePanel 筛选区扩展现有标签筛选栏（`tagGroupRows` 模式），新增受控属性 facet 列：主机厂（按集团折叠）、车型族群、公告号、电池品牌、电量（数值区间 ≥/≤ 双输入，单位 kWh）、准入等级。
- **语义**：维度内 OR、维度间 AND；每个 facet 带「(无)」虚拟值（可显式勾选，勾具体值才收敛，缺值资产默认不被过滤——无人车永不莫名消失）。
- **级联收敛**：非本列收敛 + 本列保持全量带命中计数（Facet 标准做法）。
- **公告号粘贴框保留并融合**：粘贴解析后自动勾选 facet 对应值，共享同一份筛选状态（"从 Excel 复制一列公告号"是真实工作流）。
- **分组维度切换**：结果列表 `按主机厂 / 按车型族群 / 平铺` 三选（扩展现有「车型|平铺」Segmented），筛选状态只有一份，只换组织方式。不开放按公告号/电量分组。
- **搜索框**（现有关键字搜索增强）：匹配文件名/产品名/公告号/主机厂/标签，作快捷通道。
- **落点**：筛选逻辑独立 hook/store，AssetListDrawer 与 DataSourcePanel 两处复用；支持"筛选结果批量选中/新增到工作区"（现有按钮保留）。
- **状态生命周期**：筛选状态只活在会话内，重启清空；不做预设方案。

## 6. 生命周期管理

### 6.1 状态机

```
工作区数据 ──保存至资产库──▶ active（在库）
                             │ 同身份键新数据被接受
                             ▼
                          superseded（旧版本，保留可追溯，常规视图降权）
active / superseded ──用户删除──▶ deprecated（软删除，可恢复）
deprecated ──显式清理──▶ 归档子目录 / 物理删除（走回收站）
```

### 6.2 导入三分类（查重在导入预览时发生）

每条导入数据经身份键查内存索引（身份键 → 资产 Map，扫描时建，O(1)）：

| 判定 | 依据 | 默认动作 |
|---|---|---|
| **新增** | 身份键未命中 | 直接入库 |
| **更新已有** | 身份键确定命中 | 并存为新版本 + 旧标 superseded；交互式导入弹参数 diff 三选（替换/并存/放弃） |
| **疑似重复** | 公告号同而产品名不同；产品名同而公告号空/不同；关键参数集（车型+电量+电池品牌）高度重合 | 进人工裁定清单，不自动合并 |

> 例外（2026-10-01 裁定）：公告号相同但**准入编号（ZR）或准入等级不同** → 判定为不同车型（verdict=new，理由注明"同公告号但准入不同"），不进重复裁定；准入编号相同而等级不同 = 同车数据修正，仍按重复判定走。

- 批量导入走默认（B：自动并存+标旧），单条/交互导入走 diff 确认（C）。**任何路径不静默覆盖**（ADR-0002）。
- 事后兜底：治理体检保留重复簇检测（同公告号并查集），抓人工拷贝文件进目录这类旁路。

### 6.3 删除

- 默认软删除（deprecated + 常规视图隐藏，可一键恢复）；
- "清理归档"显式操作才物理删除（优先移入归档子目录，符合治理文档规划）；
- 外部直接删文件：扫描对账自动清台账。

## 7. 性能路线

- 筛选全走内存索引：扫描时一次构建（身份键索引、facet 倒排 Map、分组索引），筛选=集合运算，1 万资产以内 O(1)~O(n) 线性且 n 小；
- 索引缓存模式沿用 `vehicleSelectors.ts` 的 WeakMap 按引用失效思路；
- **筛选/标注状态变化不触发 zustand 全量 persist**（历史头号瓶颈）；词表/取值旁路文件走既有批量读写（`batchAddAssetTags` 模式）；
- 资产面板渲染超过 ~200 可见行再引入虚拟化（现有 DataTable `virtual` prop 可复用），当前 255 量级不做；
- 文件扫描继续下沉 Rust（`scan_asset_library` 线程池），派生字段增量放 `scan_one`；
- **批量导入落盘下沉 Rust**（`save_assets_batch`，2026-10-01）：整批一次 IPC 完成"批内唯一名解析 + N 个文件写盘"（参数 serde_json::Value 原样透传，保留 rowCheck 等字段）；前端逐文件 writeTextFile 的 N 次 IPC + 主线程序列化是导入 275+ 行时的主要耗时。标签/治理元数据仍由前端一次性合并写（各 1~2 次 IO）。

## 8. 存量迁移（一次性）

1. 组级属性初值：67 组逐组填 主机厂 + 车型族群（从现有"车型族群"标签回填，标签退役）；
2. 厂商标签组（10 短名）→ 主机厂词表起点；准入等级标签组 → 受控属性词表（补 Ⅲ），回填到 202 个（参数源）；
3. 脏值清洗清单（全量核查已定位）：空串 18、`/` 占位 3、误填非主机厂 2（Ample Forwarding、深圳佑驾）、复合串 2、错别字 3、`CB320` 型号误填 1；
4. 存量同公告号重复簇（11 簇）按新版本语义人工裁决：选主、其余标 superseded；
5. 6 个无电量、9 个无电池品牌、53 个无等级条目进"待补全"清单人工补录（多为九识/白犀牛/新石器自建数据）。

## 9. 实施顺序（生命周期优先，导入在持续发生，越晚拦脏数据越多）

| 阶段 | 内容 | 交付判据 |
|---|---|---|
| **P1 生命周期骨架** | 身份键索引、导入三分类预览、版本/退役流转、软删除+清理归档、扫描对账 | 再导入已存在数据 100% 不静默覆盖；删除可恢复 |
| **P2 组级属性** | 词表、组级取值、组头编辑、分组维度切换、主机厂/族群 facet + 级联计数 | "跨厂比同类族群关键车型"三步完成 |
| **P3 资产级派生 + 筛选全量** | 四维派生 + 归一化（§4）、facet 面板全量（含「(无)」、电量区间）、粘贴融合、搜索增强 | 六维任意组合筛选 <50ms |
| **P4 补录闭环** | 资产级批量编辑表格、治理体检"待补全/待归类/待裁定"跳转、存量迁移 §8 全部收口 | 迁移清单清零 |

每阶段独立可验收，沿用 lint + test + build 三关；P1/P3 涉及 Rust 侧需双端字段对齐测试。

**实施备注（2026-09-30，P1–P4 全部落地）**：
- 存量迁移（§8.1/8.2）采用**活回退**而非物化写入：`resolveAssetFacets` 的标签兜底（厂商/车型族群/准入等级标签组）持续生效，锁定值走组属性编辑或批量补录落 `_facet_values.json`；不自动批量写 67 行，避免错误种子固化。
- 公告号粘贴框已与 facet 共享筛选状态（粘贴即勾选对应值，旧的独立过滤块移除）。
- 导入预览（P1）落在 FileManager 批量保存口；**单资产入口（SaveAssetModal）的查重提示尚未收口**，列为后续项。
- 词表种子含 2026-09-30 全量核查的别名归并（含错别字/旧名），词表外写法在治理体检「待归类」清单人工裁定。

## 10. 已知假设

- 导入量级：**批量几十条/次**（已确认）。导入预览按"一页列表 + 分类徽章 + 批量操作栏"设计（AssetBatchTagBar 模式），无需虚拟化；策略偏重批量默认（更新已有→自动并存+标旧），每行提供"查看 diff"入口但不强制弹窗逐条确认；
- 词表由用户在库目录内维护，暂不做词表编辑 UI（文本编辑 + 体检收词即可，量级为几十条）；
- "关键车型"维持自由标签（一个组可多个），不进受控属性。

## 11. 治理模型修订（2026-10-01，ADR-0003）

主文件概念**废除**（每组一个代表 = 在数据层替用户做业务选择；"参数最全"≠权威）。替代：
- **每车最新版**（自动）：同身份键（公告号+准入编号，无公告号则组+产品名）下 updatedAt 最新的活跃版本，⚡激活与对比的默认入口；同车多活跃版本 = 版本链未收敛，体检一键收敛（旧的标 superseded）。
- **关键车型**（人工标签）：主推/对比偏好，替代原主文件；存量 isPrimary 一次性自动迁移为该标签（打开资产面板即触发）。
- **数据级别（公告/准入级 vs 开发/配置级）概念撤除**（只是 Excel 模板差异痕迹）；派生字段 审批状态/准入编号/准入等级 独立保留。
- 组头计数改为「N 辆车」；组头 ⚡ = 激活组内每车最新版。
