# 列表页表头固定（法规标准 / 公告归档）— 设计方案

> 日期：2026-10-23 ｜ 状态：**已实施**
> 来源：2026-10-23 用户真机截图反馈——「表头能不能锁定？数据量多的时候；公告那个模块问题更大：
> 前面占了很大的空间，表头又不锁定；如果锁定的话可用空间又很小」。
> 前置文档：`2026-10-17-列表区统一设计语言-design.md`（列表外壳 / 密度 / 工具条）、
> `2026-10-15-announcement-regulation-layout-consistency-design.md`（这两页上一轮的一致性修）、
> `2026-10-01-asset-panel-layout-redesign.md`（视口钉高的范式来源）。

## 1. 现象与根因

| # | 现象 | 实测 |
|---|---|---|
| 1 | 表头随页面滚走 | 两页都是**整页滚动**：外壳 `MainLayout` 的 `min-h-screen` 让高度链在 `Content` 处断开，表格没有确定的可视高度，`scroll.y` 无处可取 |
| 2 | 公告中心首屏被顶部吃掉四成 | `Steps`（三步说明）+「查询公告号」「粘贴导入」两张 Card 常驻，约 290px；800px 高的窗口里归档列表只剩半屏 |
| 3 | 表头锁了但空间更小 | 上一轮为「看到更多行」做了滚动收起（`useScrollCollapse`，滚过 120px 把顶部压成一条摘要）——它治的是「顶部占地」，没治「表头不跟」；而它本身还带来一个副作用：内容塌陷导致滚动量被浏览器夹紧，只能在「几乎回顶」时才展开（`EXPAND_THRESHOLD = 16`），用起来是「收下去就回不来」 |

根因是**同一个**：这两个页面没有「页面级的高度契约」，于是任何一行内容都只能用「整页滚动」处理，
表头和顶部区都没有「谁固定、谁滚动」的分工。

## 2. 机制：把「钉高 + 表体滚动」做成构件能力

不新造布局，复用仓里已有的两件东西：

### 2.1 页面钉视口

`useViewportPaneHeight(ref, bottomPadding?)`（原为资产池 PoolPane 专用）：按「视口高 − 页面顶 −
Footer 高 − 底部内边距」算出可用高度。本页把它用到法规标准与公告中心。

**隐藏页签的问题（本次踩到）**：模块是 `display:none` 保活的（App 里所有页面常驻挂载），
隐藏期间 `offsetParent` 为 null、所有矩形为 0；而切到该页时浏览器**不发 `resize`**，
`ResizeObserver` 在 `display:none → visible` 上**也不补报**（实测没有）。于是「挂载时量一次」
的页面一旦在后台挂载就再也量不出来——表现为「切到法规标准，表格还是整页滚」。
修法：新增 `hooks/useModuleActive.ts`（`ModuleActiveContext`），App 在每页的包装层显式传
「本页是否可见」，两个取高度的 hook 都把它纳入依赖，切页即重量一次。

### 2.2 表格撑满 + 表体滚动

- `ListToolbar fill`：外壳变 `flex flex-col flex-1 min-h-0 overflow-hidden`，主体层同样
  `flex-1 min-h-0 overflow-hidden`——高度只能从外层流进来，内容再长也撑不破外壳。
- `DataTable fill`：包裹层 `flex-1 min-h-0 overflow-hidden`，`hooks/useTableBodyHeight`
  量出「包裹层高 − 表头 − 分页」，交给 antd 的 `scroll.y`。antd 收到 `scroll.y` 就把表头拆成
  独立节点（`.ant-table-header`）、给表体加 `max-height`——**表头固定、只有表体滚动**就是这一步的结果。
  显式传 `scrollY` 时以 `scrollY` 为准（存量调用点行为不变）。
- 高度是**从外向内**量的：包裹层高度由 flex 链决定，与表格内容无关。CompareView 注释里那种
  「表体高度 → 卡片高度 → 包裹层高度」的环形测量在这里不成立。

**量高度的两个坑（都实测踩过）**：

1. **不能在每次渲染后都量**：量到的新值改 `scroll.y` → 改布局 → 又触发渲染，React 直接
   `Maximum update depth exceeded`。只在挂载、`resize`、`ResizeObserver`、切页时量。
2. **不要用 `requestAnimationFrame` 排首量**：页签在后台时 rAF 可能完全不触发，表现为
   「整页静默不更新，只剩挂载那一次的旧值」。改为直接量 + 一个 `setTimeout(…, 0)` 的补量。

## 3. 公告中心顶部区：压成一行，低频动作进抽屉

grilling 收口时给了三个方向（压成一行 / 保留两卡默认折叠 / 顶部不动只吸表头），用户选前者。

```
┌──────────────────────────────────────────────────────────────┐
│ 查询公告号 [____________] 查询  示例 DNC… CA…  [数据预览][粘贴导入][提取工具] │
├──────────────────────────────────────────────────────────────┤
│ 公告归档 25                          [导入▾] [刷新]          │
│ [分组|平铺] 全部 有PDF 无PDF …                    [搜索____]  │
├──────────────────────────────────────────────────────────────┤
│ 车型名   公告号   批次  PDF  参数数  关联资产  导入时间  操作 │ ← 固定
│ ─────────────────────────────────────────────────────────── │
│ …                                            ↕ 表体内部滚动  │
└──────────────────────────────────────────────────────────────┘
```

- `Steps` 与两张 Card 删除；三步流程说明搬进「粘贴导入」抽屉，需要时能看到。
- 「粘贴导入」由常驻 Card 改为抽屉（粘贴是低频动作，与「提取工具」「数据预览」同族）。
- 查询保留在行内：它是本页主入口，也是「本地优先」的判定点，收进抽屉会多一次点击。
- 上一轮的 `useScrollCollapse` / `scrollCollapse` 随之退役（顶部已不再占版面，收起逻辑没有对象了）。
