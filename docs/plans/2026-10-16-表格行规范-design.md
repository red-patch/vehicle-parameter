# 表格行规范：行距与单元格纪律 — 设计方案

> 日期：2026-10-16 ｜ 状态：**已实施**
> 来源：2026-10-16 用户反馈「智能填报这个列表也太丑了，各个模块列表行距布局都不太一样，参考数据体检挺舒服的，是不是都要统一一下」
> 关联：`2026-10-15-ui-构件规范-design.md`（同一根因的第三次出现）、`2026-10-01-asset-panel-layout-redesign.md`
> 视觉基准：曜蓝 v4.1

## 1. 现象（用户给了正反例）

| 维度 | 数据体检（用户判「舒服」） | 智能填报（用户判「太丑」） |
|---|---|---|
| 实测行高 | ~44px，**恒定** | ~90–126px，**随内容浮动** |
| 单元格内容 | 一个控件；编辑时才换成输入框（`editingCell` 状态） | 输入框 + 开关 + 推荐标签 + 重复值，**四层常驻** |
| 值重复 | 无 | 输入框显示 `1475`，下方又出现 `1475` |
| `virtual` | `false` | `true`（`scrollY=600`） |

## 2. 根本原因：第三次同一个模式

依赖关系实测：

```
DataPurify/DataPurifyView.tsx    → common/DataTable   size=small  virtual=0   ← 舒服
SmartFiller/MatchResultTable.tsx → common/DataTable   size=small  virtual=1   ← 丑
```

**两者用的是同一个 `common/DataTable`，却还是不一样。**

这与前两轮完全同构：

| 轮次 | 领域 | 归因 |
|---|---|---|
| 1（10-15） | 搜索栏 | 都用了 `FilterBar`，但它只封容器、不封控件 |
| 2（10-15） | 工具条 | `FilterBar` 与 `Card+extra` 双轨做同一件事 |
| 3（10-16） | **表格行** | **都用了 `DataTable`，但它只封分页/滚动，不封「行里放什么」** |

`DataTable` 的注释自述解决「分页配置散落、scroll 高度计算不一致」——它封的是**表格的壳**。于是每个模块在单元格里自由发挥，行高不可能一致。

**结论：行高不齐是症状，单元格纪律缺失才是病。** 只调行高是修表不修因。

### 2.1 附带发现的硬冲突：virtual 与多行单元格互斥

antd 虚拟滚动按固定值估位（`rc-virtual-list` 的 `listItemHeight`），实测基准 13px 下：

| size | 估算行高 |
|---|---|
| `small` | **37px** |
| `middle` | 45px |
| `default` | 53px |

智能填报传 `size="small"`（估 37px）却实际渲染 ~126px——**差 3.4 倍**。这不只是丑：虚拟滚动的定位、滚动条长度、跳转都是错的。

**规范：`virtual` 仅用于「行高确定」的表**。单元格含可变高度内容（多行、标签换行）时不得开 `virtual`。

### 2.2 「行距不一样」的两个独立来源（必须分开治）

**来源 A：`size` 三档混用**（跨模块差异的主因）

antd 的 `size` 决定单元格竖直 padding：

| size | paddingBlock | 单行文本行高 | 用在 |
|---|---|---|---|
| `small` | `paddingXS` = 8px | ~37px | 21 个表格（绝大多数） |
| `middle` | `paddingSM` = 12px | ~45px | `DiffViewer/ParametersTable`、`DiffResultView` |
| `large` | `padding` = 16px | ~53px | `CompareView`、`ConfigManagerView` |

同一种「数据表格」三种行高 → 这是跨模块行距不一致的直接来源。

**来源 B：单元格内的「文本格 vs 控件格」高度不等**（表内差异）

同一张表里，纯文本格高度 = `8 + 20 + 8 = 36px`，含控件格 = `8 + 24 + 8 = 40px`。
两种格混排时行高不一，视觉上「行距忽紧忽松」。

> 注意（本方案初稿曾判错，此处更正）：数据体检与智能填报**都是 `size="small"`、padding 完全相同**。
> 两者行高差异（44px vs 126px）**不来自 padding**，纯粹来自单元格内容多少。因此
> 「统一 padding」是修表不修因，真正的第一刀是 §3.2 的单元格纪律。

## 3. 对策

### 3.1 行高契约（CSS 层，一次覆盖全仓）

不做「逐个文件改 padding」这种表功，而是**把文本格补到与控件格等高**，消除来源 B：

```css
/* 表内文本格与行内控件等高（控件 controlHeightSM = 24px），
   否则纯文本行 36px、含控件行 40px，同表混排时行距忽紧忽松 */
.ant-table-wrapper .ant-table-tbody .cell-edit-text,
.ant-table-wrapper .ant-table-tbody .cell-plain {
  min-height: 24px;
  display: flex;
  align-items: center;
}
```

来源 A 由 §3.3 的 `size` 收敛解决，同样一次覆盖全仓。

### 3.2 单元格纪律（构件层）

数据体检那个「舒服」的范式已经有 CSS 支撑（`cell-edit-text`：只读态是文本 + 悬停弱底，点开才变输入框）。把它提升为**命名构件** `CellText`，让「一格一行」成为可复用的默认：

```
只读：<span class="cell-edit-text">右侧滑门</span>   ← 悬停显示可点
编辑：<Input size="small" />                          ← 点击后
```

**纪律：一个单元格只放一个「主控件」。** 次要信息（推荐值、异常提示、开关）移到：
- 行内联动的次要列（如「匹配库参数」已有该列）
- 单元格的 hover tooltip
- 行的展开区（antd `expandable`，不撑高主行）

### 3.3 `size` 收敛

数据表格统一 `size="small"`。`middle`/`large` 只留给非表格用途（按钮、Descriptions）。

`DataTable` 已默认 `small`，所以**走 `DataTable` 的表天然一致**；要改的是**裸用 antd `Table`
且显式传 `middle`/`large` 的那几处**（`ParametersTable`、`DiffResultView`、`CompareView` 的数据表）。

### 3.4 智能填报改造（样板页）

| 现状 | 改为 |
|---|---|
| 「填报值」单元格四层堆叠 | 单行：值控件 + 模式切换图标；推荐值/异常提示移入 tooltip 或展开区 |
| 同一值显示两次（输入框 + 下方 `RepairableValue`） | 只显示一次 |
| `virtual` + `scrollY={600}` | 去掉 `virtual`（单元格含可变内容），保留 `scrollY` |

## 4. 护栏

新增到 `src/__tests__/uiConsistency.test.ts`：

| 规则 | 禁项 | 理由 |
|---|---|---|
| R6 | 表格渲染文件里的 `<Switch` | 开关几乎必然撑高行；改用图标按钮或移出单元格 |

**不设**的规则及原因：
- 禁 `flex-col`：实测 7 个文件用到，**多数是页面级布局**（`CompareView` 5 处全是布局壳），文本级无法区分单元格内外，禁了会大面积误伤。
- 禁 `virtual`：误报风险高（合法用法存在），改为文档纪律。
