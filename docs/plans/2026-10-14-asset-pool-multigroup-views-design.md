## 1. 背景与需求

### 1.1 需求原话

> 「分组跟筛选过滤排序 可以单独保存一个视图」
> 「支持多层分组」（例：某主机厂 → 其下不同族群 → 其下不同等级）

### 1.2 现状缺口

| 能力 | 现状 | 缺口 |
|---|---|---|
| 分组 | 单维度（迭代 4 `buildAssetGroups(rows, dim, ctx)` 一次一个维度） | 无法「族群 → 等级」嵌套展开 |
| 视图 | 各设置（排序/分组/列数）散存 localStorage，只能记住"最近状态" | 无法命名保存、无法一键切换、无内置预设 |
| 筛选 | 会话内，重启清空（既定决策） | 无法随视图一起保存复用 |

│  │  │  │ 车卡 │ │ 车卡 │ │ 车卡 │                      ││ │

一句话：**分组可叠最多 3 层（下拉里逐级加）；筛选 + 分组维数组 + 排序 + 列数打包成"视图"，可命名保存、一键切换、并有内置预设。**

## 3. 详细设计

### 3.1 多层分组（最多 3 层）

- **数据结构**：`groupDims: AssetGroupDim[]`（长度 0-3；`[]` 或 `['none']` = 不分组）。UI 上是一个**有序数组**：主分组 → 副分组 → 三级。
- **分组下拉 UI**：点开后面板里
  - 顶部显示当前层级链（如 `主机厂 › 族群 › 准入等级`），每级可单独移除；
  - 「+ 添加分组层级」按钮（< 3 时可用）；
  - 每级一个维度选择（复用现有 7 维度枚举，同级不重复选）。
- **分组算法**：`buildAssetGroupsMulti(rows, dims, ctx)`——对 dims 逐层分桶（第 1 层全量分，第 2 层在第 1 层每个桶内再分，第 3 层同理），产出嵌套树：
  ```ts
  interface AssetGroupNode {
      key: string;            // 层级路径键（父键 + '/' + 本键），用于折叠记忆
      dim: AssetGroupDim;
      label: string;
      rows?: AssetSortRow[];  // 叶子节点才有行
      children?: AssetGroupNode[];
      vehicleGroupKey?: string;
  }
  ```
- **组序**：每层沿用迭代 4 的组序规则（数量降序 / 等级序 / 状态优先级；缺值「（无）」垫底）。
- **组内排序**：叶子节点内按全局 `sortSpec` 排（与迭代 3 一致）。
- **组头**：每层一个组头（迭代 4 的 `AssetGroupHeader` 递归使用），**缩进随层级递增**（第 2 层 +16px，第 3 层 +32px），首层字号略大。
- **折叠记忆**：键用**层级路径**（`吉利/大面/Ⅲ`），存 `localStorage['asset-pool-collapsed-<key>']`（按路径，与维度组合无关，换维度后旧键自然失效）。展开/折叠独立于每一层。
- **仅车型维度**：组头挂 ⚡ 激活最新版 / 右键重命名车型（其他维度无"组实体"）。

### 3.2 视图库（完整）

**视图 = 一份完整面板状态快照**：

```ts
interface AssetView {
    id: string;              // 稳定 id（时间戳/uuid）
    name: string;            // 用户命名（如「吉利大面待办」）
    builtin?: boolean;       // 内置视图（不可删，可"另存"）
    // —— 状态 ——
    filters: {
        searchKeyword: string;
        facetSelection: FacetSelection;   // 含公告号/电量/主机厂/族群/等级/品牌
        selectedTags: string[];
        statusSelection: StatusFilter[];
        governanceView: string | null;    // 治理视角（关键车型/命名问题…）
    };
    groupDims: AssetGroupDim[];           // 多层分组（§3.1）
    sortSpec: AssetSortSpec;
    columnMode: ColumnMode;
}
```

- **保存**：列表头「视图」旁「＋ 保存当前视图」→ 弹小窗输入名字 → 落盘。
- **切换**：视图下拉列出全部视图（内置在前 + 用户视图），点选即套用（覆盖当前所有筛选/分组/排序/列数）。
- **管理**：下拉里每个用户视图行尾有「⋯」→ 重命名 / 删除 / 另存为。内置视图仅"另存为"。
- **当前视图标记**：切换后下拉显示视图名；用户手改了任一设置 → 标记为「（已修改）」，提示可"保存"或"另存"。
- **内置默认视图**（3 个，开箱即用）：
  | 名称 | 内容 |
  |---|---|
  | 全部资产 | 无筛选、不分组、时间倒序、自动列 |
  | 关键车型 ⭐ | 筛选 `关键车型` 标签、按主机厂 › 族群分组、完成率降序 |
  | 待治理 | 筛选状态=历史/废弃 + 命名问题、按状态 › 主机厂分组 |
- **持久化位置**：**库级旁路文件 `_asset_views.json`**（与 `_asset_tags.json` / `_asset_meta.json` 同族，`_` 前缀天然被扫描跳过）。理由：视图是"这个资产库怎么组织"的元数据，应随库走、可随库备份；换机器/换目录后仍可用。读写复用 `assetManager` 的旁路文件模式。
- **不落盘的东西**：折叠态（`asset-pool-collapsed-*`）、当前选中视图 id（`asset-pool-active-view`）——前者是会话性细节，后者可 localStorage。

### 3.3 快捷键（含冲突处理）

**冲突说明**：本会话用户已指定 **⌘S = 隐藏/显示边栏**（迭代 2 已实现），故视图保存**不能**用 ⌘S。

新增/调整：

| 快捷键 | 动作 | 备注 |
|---|---|---|
| ⌘S（⌘B） | 隐藏/显示左栏 | **保持**（用户指定，不动） |
| ⌘⇧S | **保存当前视图** | 与"保存"语义关联（⌘S 被占，退到 ⌘⇧S） |
| ⌘1 / ⌘2 / ⌘3 | 切换到第 1/2/3 个视图 | 视图下拉前三个（内置在前）的快速切换 |
| ⌘⇧C | 已选工作集开关 | 保持 |
| ⌘/ | 速查表 | 速查表补充以上新键 |

### 3.4 与既有机制的关系

- **筛选仍是 AND 叠加**，只是现在可被视图整体保存/还原。
- **左栏导航**保持筛选语义（迭代 4 决策不变）；与视图叠加——左栏改动 = 视图"已修改"。
- **分组取代聚拢**（迭代 4 决策不变）；多层分组是它的超集（单层 = 多层长度 1）。
- **列数/排序**（迭代 3/5）纳入视图状态。

## 4. 决策一览

| # | 决策 | 要点 |
|---|---|---|
| 1 | 多层分组最多 3 层 | `groupDims: AssetGroupDim[]`，逐层嵌套，层级路径折叠键 |
| 2 | 完整视图库 | 保存/切换/重命名/删除/另存 + 3 个内置预设 |
| 3 | 视图内容 | 筛选 + 分组维数组 + 排序 + 列数（四件套快照） |
| 4 | 视图落盘 | 库级 `_asset_views.json`（随库走，可备份） |
| 5 | 快捷键 | ⌘⇧S 保存视图；⌘S 保持"隐藏边栏"；⌘1/2/3 快切视图 |
| 6 | 兼容 | 单层分组 = 多层退化；旧 localStorage 键迁移进"全部资产"视图 |

## 5. 实施顺序

> 每步跑 lint + typecheck + test + build。

- **M1 多层分组纯函数**：`buildAssetGroupsMulti(rows, dims, ctx)` → 嵌套 `AssetGroupNode` 树 + 单测（1/2/3 层、层级路径键、组序、缺值垫底、dims 去重）。
  验收：三层嵌套结构正确；单层等价迭代 4；空 dims = 平铺。
- **M2 嵌套组头渲染**：`AssetGroupHeader` 支持缩进层级；递归渲染树；层级路径折叠记忆；车型维度 ⚡ 只在一级出现（或任一层车型维度）。
- **M3 分组下拉升级**：层级链显示 + 逐级增删 + 每级维度选择（≤3）。
- **M4 视图数据层**：`AssetView` 类型 + `_asset_views.json` 读写（`assetManager` 新增 `loadAssetViews`/`saveAssetViews`）+ 内置预设常量 + 单测（序列化往返）。
- **M5 视图 UI**：列表头「视图」下拉（列表 + 保存 + ⋯ 管理）+ 保存弹窗 + 「（已修改）」标记 + 套用逻辑（写入各状态）。
- **M6 快捷键**：⌘⇧S 保存视图、⌘1/2/3 快切；速查表更新。
- **M7 回归**：四条验证命令全绿；真机核对（三层分组 + 视图切换 + 重启保留）。

## 6. 约束与注意

- **曜蓝 v4.1**：嵌套组头只用缩进 + 字号区分层级，不引入新底色；分隔线 `--border-default`。
- **性能**：三层分组 = 三次分桶，O(3n)；几百资产无压力。嵌套树不要每帧重建（useMemo 依赖稳定）。
- **状态收敛**：现在筛选/分组/排序/列数散在多个 useState——视图套用时需**批量写入**，避免中间态闪烁（考虑收敛为一个 `panelState` 对象 + reducer，或批量 setState 后再触发一次派生）。**实施时评估是否值得收敛**（文档倾向收敛，但列为可选）。
- **读库失败**：`_asset_views.json` 不存在/损坏 → 回退到内置预设，不阻断面板。
- **视图 id 稳定性**：用 `crypto.randomUUID()`（WebView 支持）或时间戳+随机后缀。
- **迁移**：现有 `asset-pool-sort` / `asset-pool-group-dim` / `asset-pool-column-mode` 三个键——首启若无 `_asset_views.json`，用它们初始化"全部资产"视图的当前态，之后以视图为准（或保留它们作为"未保存的临时态"）。实施时定：**倾向保留为临时态，视图是显式保存**。

## 7. 评审提示

1. **3 层够不够**：用户举例是「主机厂→族群→等级」正好 3 层。若将来要 4 层，前端结构支持（数组长度放开即可），但 UI 会拥挤——先做 3 层封顶。
2. **视图 vs 临时态**：切到视图后又手改设置，是"临时偏离视图"还是"自动存回视图"？本文档取**临时偏离**（显示"已修改"，需显式保存），避免误改视图。若用户要自动存回，改一处。
3. **内置视图能否改**：取"不可删、可另存"，避免用户改坏预设无从恢复。
4. **⌘1/2/3 与数字输入**：仅在面板可见且非输入态生效（沿用现有快捷键守卫）；若用户觉得冲突可去掉。
5. **状态收敛**：§6 提到是否把散状态收敛成 reducer——这是**重构**，有回归风险。实施 M5 时评估：若批量 setState 已够用就不收敛。

## 8. 明确挂起

| 挂起项 | 原因 / 去向 |
|---|---|
| 视图导出/导入（团队共享） | 本轮做库内库；跨库分享另议 |
| 视图排序（用户调整下拉顺序） | 按创建时间即可 |
| 4 层以上分组 | UI 拥挤，先封 3 层 |
| 视图级快捷键自定义 | 固定 ⌘1/2/3 |
| 暗色模式走查 | 沿用挂起项，单独立项 |
