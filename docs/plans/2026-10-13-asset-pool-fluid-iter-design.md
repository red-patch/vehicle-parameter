### 1.2 两项反馈的根因（2026-10-14）

**反馈 1「检查器按钮太多，能否进右键菜单」**：检查器操作区现有 **17 个动作按钮**（激活/送去对比/标签选择器/重命名/设置别名/关键车型/历史版本/废弃/复制公告号/公告 PDF/公告对比/导出 CSV/升级导入/Finder/打开文件/删除/彻底删除），而右键菜单只有 6 项。**高频动作要点开抽屉才能触达**，路径长、实用性低。

**反馈 2「指标放卡片上，隐藏太深」**：参数总数/完成率/空值（`AssetStatsBadge` 现成组件，V1 卡片用过）现在只在检查器抽屉里，**列表上看不到哪份参数更全**——而"同车型多条资产选参数更全的那份"正是挑选时的高频判断。

**共同根因**：V2 把 V1 的卡片内动作/指标一并收进抽屉，过度"减负"导致关键信息与高频动作被藏深。

### 3.7 右键菜单全动作化（U12；检查器瘦身）

**原则**：所有**对象级动作**（对一个资产做的写操作）从检查器下沉到右键菜单——右键是"就地操作"，检查器是"看内容"。用户在列表上右键即可完成一切，不必开抽屉。

**右键菜单结构**（分组 + 二级子菜单，`ContextMenuItem` 需扩展 `children` 支持）：

```
激活进工作集 / 移出工作集        ← 高频，第一项
复制公告号
────────────────────────────
标签            ▸   [标签选择器 / 常用标签快捷项]
重命名
设置别名…
关键车型        ▸   [标记/取消关键车型]
状态            ▸   [标记历史版本 / 标记废弃 / 清除标记]
────────────────────────────
公告            ▸   [查看公告 PDF / 与公告对比]
导出 CSV
升级导入
────────────────────────────
在 Finder 中显示
打开文件
批量选择
────────────────────────────
删除（可恢复）
彻底删除（归档）           ← 仅 deprecated 时出现，danger
────────────────────────────
打开检查器…
```

- **一级保留高频**：激活/移出、复制公告号、重命名、Finder、批量选择、打开检查器（V2 现状 6 项不动）。
- **二级收纳低频**：标签、关键车型、状态、公告、导出/升级 —— 用子菜单，一级不膨胀。
- **删除类**：置于最底部、与 `打开检查器…` 用分隔线隔开（防误触）；`彻底删除` 仅对 deprecated 资产可见。
- **检查器瘦身**：操作区**只保留**「激活/移出」+「送去对比」两个高频按钮（V2 实施备注里就已保留激活），其余动作按钮**移除**（改由右键触达）。检查器定位变为「详情/数据视图」：事实头 + 完成度 + 必填缺失 + 分组完成度 + 参数预览 + 标签编辑（标签是"看到即编辑"的视图内操作，保留）。
- **实现落点**：`useContextMenu.tsx` 的 `ContextMenuItem` 增加 `children?: ContextMenuItem[]`，渲染层支持 hover 展开子菜单；`buildAssetContextMenu`（AssetPoolLayout）重建为上述结构。子菜单渲染需处理视口边缘翻转（现有 clamp 逻辑扩展到子菜单）。

## 3. 各区块规格

### 3.1 左栏（导航浮窗）— 2026-10-16 修订

> **本节已于 2026-10-16 修订**：原方案是「可折叠细条：240px ↔ 24px，挤压主区」。
> 实施后的迭代改为**浮窗**——理由是细条仍占 24px 且切换时主区跳动，浮窗覆盖式
> 不挤压布局、关闭后主区全宽更彻底地达成「左栏不该常驻占死 240px」的原始意图。

- **形态**：**浮窗**（`fixed` 覆盖在列表上，`surface-container` + 圆角 + `shadow-popover`），
  **不挤压主区**（主区恒为全宽）。
- **开关**：筛选条左缘的图标钮（筛选条左侧，`MenuFold/MenuUnfold`）；另有 ⌘B。
- **收起时机**：点浮窗外部、Esc、或在浮窗内完成一次「选择/动作」（`onAction`）。
- **默认态**：**收起**（不默认遮挡列表）。
- **持久化**：`localStorage['asset-pool-nav-open']`（`'1'` = 展开），重启保留。
- **不丢失信息**：收起态下当前筛选状态在筛选条与列表头继续显示（共 N 个资产·已选 M + 清空按钮），不会忘记自己筛了什么。

### 3.2 流体多列卡片网格（用户明确拒绝固定断点）

- **CSS Grid**：`grid-template-columns: repeat(auto-fill, minmax(260px, 1fr))`，`gap: 10px`。
- **无固定断点、无列数上限**：容器多宽就塞多少列（1 → 2 → 3 → 4 → 5…），浏览器按 260px 最小列宽自动计算；拉窄到 <260px 自然退回单列。**不写 media query**。
- 卡片 `height: 100%`（同一行卡片等高对齐）。
- 反向定位（scrollIntoView）与 `data-asset-file` 查询逻辑不变。

### 3.3 卡片信息层级重排（体系级迭代 #7 + 标签恢复 #2 + 指标带上卡片 U13）

四行结构（窄卡多列下自动换行；行3/行4 可合并简化）：

| 行 | 内容 | 依据 |
|---|---|---|
| 行1 | 状态点（**最新版 = 品牌色圆点** + tooltip「最新版」）+ 车型显示名（truncate）+ 信号图标（⭐关键=StarOutlined/黄、命名问题=WarningOutlined/黄字、驳回=CloseCircleOutlined/红字、历史=HistoryOutlined/灰、废弃=StopOutlined/灰，均带 tooltip）+ 激活按钮（＋/✓） | 「色彩是信号不是填充」——最新版从整块 Tag 降为点；状态用图标+tooltip 表达，不再堆 Tag |
| 行2 | **指标带（U13）**：参数总数 · 完成率 · 空值（复用 `AssetStatsBadge` 口径）+ **缺必填 chip（danger 前置）** | 用户反馈「指标隐藏太深」——完成率/空值/缺必填是挑选判断依据，必须列表可见 |
| 行3 | 更新日期（caption，右对齐，`tabular-nums`） | 时间的描述性信息，退居末位 |
| 行4 | **标签 chips**（surface-inset 小 Tag，最多 3 个 + `+N`；「关键车型」标签不再重复出现，由行1 星标表达） | 标签是治理体系核心抓手（用户反馈 #2），恢复但控制密度 |

**指标带的窄卡简化（呼应「放不下就做简单点」）**：卡片靠 `@container` 自适应——
- 宽卡（≥ 360px）：`参数 128 · 完成率 46% · 空值 69` 全标签文字；
- 中卡（240–360px）：去文字标签，只留 `128 · 46% · 69`（数字 + 完成率按档着色：≥95 绿 / ≥60 黄 / <60 红，沿用 `AssetStatsBadge` 的 `fillRateTone`）；
- 窄卡（< 240px，实际列最少 260px 不会触发，仅容错）：只留 `缺必填` chip + 完成率百分比。

**取舍**：不再单独做「行3 日期 + 行4 标签」，若窄卡空间紧张，日期与标签行可折叠合并为一行（标签优先）。实施时以真机截图定夺。

- 选中态：左缘 3px 品牌条 + surface-inset 底（v4.1 信号纪律）。
- 已激活弱信号：右缘 3px success 条（仅未聚焦时显示，聚焦态与选中条正交）。
- 批量模式：行1 左侧追加 Checkbox（现有逻辑）。
- displayName prop 兼容 asset-alias 别名解析（`resolveAssetDisplayName`），缺省回退 `getAssetDisplayName`。

### 3.4 浮动购物车（用户方案：没内容时不存在，有内容时显示全一点）

替代 V2 固定 300px 右栏，三态：

| 态 | 触发 | 形态 |
|---|---|---|
| **空态** | 已选 = 0 | **不存在**（零占位），中间区全宽 |
| **胶囊** | 已选 ≥ 1，默认态 | 右下角浮动胶囊：`● N 台车 · 去对比 →`（品牌实色填充圆角按钮，shadow-lg，hover opacity 90） |
| **浮层** | 点胶囊 | 320px 浮层面板（surface-container + border-popover + shadow-popover，`max-height: 70vh` 内部滚动）+ **透明点击层**（点面板外收起）。**不用深色遮罩**：遮罩会盖住列表，与"浮动仍可见列表"的本意冲突 |

浮层内容（AssetCart 复用）：
- 头部「已选工作集」+ 计数 + 清空按钮 + 关闭按钮；
- 车卡：**短名主显**（口径固定为 `resolveAssetDisplayName`——别名 > 组名 > 派生名，与列表卡片完全一致；同产品名多实例时叠 `buildVehicleDisplayLabels` 的 `(n)` 编号消歧）+ 完整产品名放 `title` tooltip（不再占行）+ 完成率 + 缺必填（红字）+ × 移出；
- 底部「去对比 →」CTA（跳转前先收浮层）。

交互细节：
- 点遮罩 / 关闭按钮 = 收回胶囊；
- 点车卡 = 反向定位（左栏列表 scrollIntoView + 短暂高亮，沿用 V2 逻辑）+ 不自动收起；
- 胶囊上「· 去对比 →」后缀可直接点击 = 不展开直接跳对比（快捷路径）；
- 购物车其余能力（清空工作区、移出）全部保留，语义与 V2 一致。

### 3.5 筛选 chip 箭头（体系级迭代 #6）

- ChipShell 下拉指示从文本字符「▾」换 `CaretDownOutlined`（antd 图标，`text-[10px] opacity-60`）。
- 其余 chip 视觉（激活态 brand-weak + brand 边）不动。

### 3.6 快捷键体系（2026-10-14 补充）

**作用域守卫**：仅「车型资产」tab 可见时生效（PoolPane display:none 时静默）；输入框/文本域聚焦时**一律不拦截**，唯一例外 Esc（退出当前态）。所有快捷键 `preventDefault` 仅限自身命中时。

| 快捷键 | 动作 | 备注 |
|---|---|---|
| ⌘S | **保存当前视图** | 2026-10-16 修订：⌘S 在 macOS 是系统保留键，改由**原生菜单**消费并转发（`lib.rs SAVE_VIEW_MENU_ID`，见 §3.1 修订说明）；输入框内不拦截 |
| ⌘B | 隐藏/显示左栏（toggle） | 由 ⌘S 改为 ⌘B（VS Code 惯用别名）；⌘⇧S 保留 JS 绑定作为跨平台兜底（Windows 无应用菜单） |
| ⌘K | 聚焦搜索框 | 再按置焦不清空；Esc 从搜索框退回列表 |

## 7. 约束与注意

- **曜蓝 v4.1 纪律**（违规即返工）：三层表面（surface-1/2/3）；色彩是信号不是填充（语义色只上文字/线/点）；文字四级 + 字号阶梯（caption/aux/body/title）；动效统一 `--ease-ui` + transition-colors（**不用** translateY/scale/自定义阴影）；暗色下抬升靠表面亮度+描边。
- **并行会话在制品不修**：asset-alias、批量字段维护、attributeEnums 等工作树改动是其他会话的（部分已入库），失败先分诊归属再决定动不动。
- **displayName 兼容**：AssetCard/AssetCartCard 的 displayName prop 由 asset-alias 接入，别名只影响显示、不参与身份键（设计 §5）。
- **localStorage 新 key**：`asset-panel-sidebar-collapsed`（旧 key `asset-panel-view-mode` / `asset-panel-expanded-groups` 不动）。
- **反向定位依赖 data-asset-file**：Grid 化后每个卡片外层不再包 div，把 `data-asset-file` 移到卡片根元素上。
- **快捷键作用域**：`useAssetPoolHotkeys` 挂在 PoolPane，PoolPane 不可见（display:none）时 `document.visibilityState` 不足以判断，须用元素级判断（如检查 pane 是否在 offsetParent 中）或由 ParameterWorkbench 传入 activeTab 判断；输入框守卫用 `e.target` 的 tagName/contentEditable 检查。
- **检查器动作下沉的连带**：移除检查器按钮后，确保 `actions.*` 每个方法仍在右键菜单有唯一入口（有测试覆盖更好）；`actions.modals`（重命名/别名/升级导入/公告 PDF 选择等弹层）挂载点不变。

## 8. 评审提示

1. **胶囊上直接「去对比」**：点击胶囊右侧后缀 = 不展开直接跳对比。若误触率高可退化为仅展开（实施后看使用情况）。
2. **标签行上限 3+N**：多标签资产在窄卡下只露 3 个；若用户需要更多，可在后续迭代加 hover 展开。
3. **列数不设上限**：超宽屏（>2000px）会出现 5+ 列、卡片过窄；届时再议 `minmax` 最小列宽调大（如 280px），本轮不预设。
4. **右键菜单子菜单的视口翻转**：现有 `useContextMenu` 只 clamp 一级菜单；子菜单向右展开要判断右缘空间、必要时向左展开——实施时补这段逻辑（否则靠右的卡片子菜单会被切）。
5. **检查器保留标签编辑**：标签是"看得见就想改"的视图内操作，留在检查器；其余写操作全走右键——若用户仍觉不便，下一轮再把标签选择器也做进右键子菜单（结构已留位）。
6. **指标带数值口径**：`AssetStatsBadge` 的分母是该资产自身参数行数（与待分析列表一致），不是必填项全集；缺必填是另一个口径（`isFieldRequired`）——两者并排展示时用 tooltip 说明避免混淆。
