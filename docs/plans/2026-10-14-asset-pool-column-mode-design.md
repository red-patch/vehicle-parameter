# 资产池迭代 5：列数模式（自动 / 固定）— 设计方案

> 日期：2026-10-14 ｜ 状态：**待实施**
> 来源：迭代 2/4 真机试用反馈——宽窗口下 `minmax(260px,1fr)` 自动铺满，5 列过密、卡片信息挤成一团。
> 前置文档：`2026-10-13-asset-pool-fluid-iter-design.md`（迭代 2 流体多列）、`2026-10-14-asset-pool-grouping-design.md`（迭代 4 分组）。
> 视觉基准：曜蓝 v4.1。

## 1. 背景与问题

迭代 2 引入的流体网格 `repeat(auto-fill, minmax(260px, 1fr))` 在窄窗表现良好（2-3 列），但**宽窗口（~2000px）下会铺满 5-6 列**：
- 卡片被压到 260px 出头，名称/指标/标签三行信息挤在一起，可读性差；
- 没有"我想要几列"的控制权——完全由窗口宽度决定。

**根因**：最小列宽 260px 偏小 + 缺少用户对列数的显式控制。

## 2. 目标形态

列表头新增「列」下拉，紧邻「分组」「排序」：

```
共 83 个资产 · 已选 5   [分组: 车型 ▾] [排序: 时间 ↓] [列: 自动 ▾]   将筛选结果加入工作区 →
                                                       ├─ 自动（按窗口宽度）
                                                       ├─ 1 列（横向列表行）
                                                       ├─ 2 列
                                                       ├─ 3 列
                                                       └─ 4 列
```

- **自动（默认）**：`repeat(auto-fill, minmax(320px, 1fr))`——最小列宽从 260 提到 **320px**，宽屏不再无脑塞 5 列，自然落在 3-4 列。
- **固定 1/2/3/4**：`repeat(N, 1fr)`，锁死列数，与窗口宽度无关。
- **1 列 = 横向列表行**：卡片切换为**横向布局**（信息一行排完：状态点 + 名称 + 指标 + 缺必填 + 标签 + 激活按钮），不是"一张窄卡占满宽度"。

## 3. 详细设计

### 3.1 列数模式枚举

```ts
type ColumnMode = 'auto' | 1 | 2 | 3 | 4;
```

- 存 `localStorage['asset-pool-column-mode']`，默认 `'auto'`。
- 网格样式映射：
  | 模式 | grid-template-columns |
  |---|---|
  | auto | `repeat(auto-fill, minmax(320px, 1fr))` |
  | N (1-4) | `repeat(N, minmax(0, 1fr))` |

- **1 列特例**：列数=1 时，卡片走横向列表行布局（见 §3.2），网格仍是 1 列。

### 3.2 AssetCard 横向列表行变体（仅 1 列模式）

新增 `layout?: 'card' | 'row'`（默认 `'card'`）。`'row'` 时：

```
┌───────────────────────────────────────────────────────────────────────────┐
│ ● 远程V6E  宁德时代新能源科技…   ⭐ 参数 478 · 完成率 50% · 空值 241  ⚠缺必填 12  中面 吉利  2026/9/21  [＋]│
└───────────────────────────────────────────────────────────────────────────┘
```

- 状态点 + 名称（固定宽或 min-w）+ 来源/公告简短信息 + 指标带 + 缺必填 chip + 标签 + 日期 + 激活按钮，**单行横向排列**；
- 名称过长 `truncate`，指标/标签在窄屏用 `@container` 渐进隐藏；
- 与卡片态共享全部数据与交互（点选/激活/双击/右键/批量），只换布局。

### 3.3 与分组 / 排序的关系

- **列数与分组正交**：分组定"切成几段"，列数定"每段里每行几张"。
- 分组开启时，**组内网格**用同一列数设置；组头横跨整宽（不受列数影响）。
- 排序不变。

### 3.4 卡片原有布局保留

`layout='card'`（默认）= 迭代 2 的四行竖排卡片，**不动**。仅当列数=1 时用 `'row'`。

## 4. 决策一览

| # | 决策 | 要点 |
|---|---|---|
| 1 | 列数模式 | 自动（默认）/ 1 / 2 / 3 / 4；存 localStorage |
| 2 | 自动最小列宽 | 260px → **320px**（治本：宽屏不再 5 列） |
| 3 | 1 列 = 横向列表行 | AssetCard 新增 `layout='row'` 变体 |
| 4 | 正交性 | 列数与分组/排序互不干扰；组内同列数 |

## 5. 实施顺序

> 每步跑 lint + typecheck + test + build。

- **M1 列数状态 + 网格映射**：`ColumnMode` type + localStorage + `gridTemplateColumns` 计算；自动模式最小列宽 320。
  验收：切列数即时生效；自动模式宽屏落在 3-4 列；记忆正确。
- **M2 列数下拉 UI**：列表头「列」下拉（与分组/排序同款 Popover）。
- **M3 AssetCard 横向行变体**：`layout` prop + row 布局（单行信息）。
  验收：1 列时卡片变横向行；其余列数仍是竖排卡片。
- **M4 回归**：四条验证命令全绿；真机核对。

## 6. 约束与注意

- **曜蓝 v4.1**：横向行不引入新色；复用现有状态点/指标/徽标样式。
- **方向键导航**：`moveFocus` 的列数推算（`columnsInGrid`）须跟随列数模式——固定列数时直接用该数，自动模式仍按容器宽推算。
- **横向行的 memo**：AssetCard 是纯函数组件，新增 prop 不破坏现有渲染。
- **`@container`**：横向行也用容器查询做窄屏渐进隐藏（复用现有 `@[300px]` 断点）。

## 7. 评审提示

1. **自动模式 320px 是否够**：可能与用户的显示器尺寸/DPI 有关；若仍嫌密，可再提到 340-360，或让"自动"记住用户改过的值。
2. **横向行的信息取舍**：行内信息多，窄窗需隐藏次要项（标签→日期→指标）。隐藏顺序实施时可调。
3. **列数与分组组合**：4 列 + 某分组只有 1 条时，该组内只有 1 张卡（不拉伸占满）——这是预期（列表网格语义）。

## 8. 明确挂起

| 挂起项 | 原因 / 去向 |
|---|---|
| 「自动」最小列宽用户可调 | 先固定 320，看反馈 |
| 列宽拖拽调整 | 列数模式已够；拖拽另议 |
| 卡片密度档位（紧凑/舒适） | 与列数部分重叠，先做列数 |
| 暗色模式走查 | 沿用挂起项，单独立项 |
