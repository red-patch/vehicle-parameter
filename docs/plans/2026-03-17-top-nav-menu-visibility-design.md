# 顶部菜单可见性修复设计

**背景**

主界面顶部导航已经收纳了 7 个一级入口，右侧还保留了主题切换、资产库设置和缓存清理按钮。当前头部使用左右两端对齐布局，左侧标题不收缩，中间菜单还带有固定最小宽度，窗口变窄时末尾菜单项会被挤出可见区域，导致“系统配置”看起来像是消失了。

**问题根因**

- 头部采用 `justify-between`，右侧菜单与按钮整体宽度不足时缺少收缩策略。
- 菜单使用固定 `min-w-[480px]`，无法随容器宽度自适应。
- 标题文本没有截断能力，会持续占用头部横向空间。

**目标**

- 顶部菜单在窄窗口下仍然保持可访问。
- “系统配置”不再因为头部拥挤而被直接挤没。
- 保持现有菜单结构和入口位置不变，不引入新的导航模式。

**方案**

采用“标题可收缩 + 菜单容器横向滚动”的最小修复方案。

- 将头部布局改为可收缩的三段式：标题区、菜单区、操作区。
- 标题区增加 `truncate` 和最大宽度限制，优先让出空间给导航。
- 菜单外层增加 `overflow-x-auto` 的滚动容器，菜单自身使用 `min-w-max` 保持完整宽度。
- 右侧操作按钮保持紧凑，不参与菜单滚动。

**取舍**

- 优点：实现简单，保留现有信息架构，不影响用户心智。
- 缺点：极窄窗口下需要横向滚动菜单，而不是始终全部铺开。

**验证标准**

- 头部标题具备可收缩/截断能力。
- 顶部菜单存在独立的横向滚动容器。
- “系统配置”菜单项仍会正常渲染并可交互。
