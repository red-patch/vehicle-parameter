# 车型选择标签文案优化设计

**背景**

为了解决不同文件中同名车型被错误合并的问题，工作台内部已经切换到“车型实例键”作为唯一身份。当前对比车型选择器的已选标签直接复用了下拉选项文案，格式是 `车型名 · 文件名`。这虽然能区分来源，但在已选区域里过于冗长，且当两个实例车型名相同时，会让用户误以为重复渲染了车型名称。

**问题根因**

- 已选标签和下拉选项共用同一套显示文案。
- “区分来源”的需要被直接用“完整文件名可见”来满足，信息密度过高。
- 已选区域更强调快速浏览，而不是完整来源信息。

**目标**

- 已选标签默认只展示车型名。
- 当已选车型中存在同名实例时，标签仍可区分，但不展示完整文件名。
- 完整文件名仍可通过悬浮提示查看。

**方案**

采用“已选标签短文案 + Tooltip 完整来源”的方案。

- 若车型名唯一，标签文案只显示 `车型名`。
- 若同名实例同时被选中，则标签文案显示 `车型名（1）`、`车型名（2）` 这类短标识。
- 标签的悬浮提示展示完整来源文案 `车型名 · 文件名`。
- 下拉选项仍保留 `车型名 · 文件名`，避免选择时丢失区分能力。

**取舍**

- 优点：已选区域显著更清爽，且不会重新引入同名实例混淆。
- 缺点：数字序号本身不表达来源含义，需要结合悬浮提示查看完整文件名。

**验证标准**

- 单个车型被选中时，标签不包含文件名。
- 两个同名车型实例被选中时，标签显示短序号区分。
- 完整文件名不直接出现在标签正文中。
