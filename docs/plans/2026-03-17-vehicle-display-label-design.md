# 车型显示命名简化设计

**背景**

为了解决同名车型串数据的问题，当前工作台内部已经使用“实例键”做唯一身份。但显示层直接复用了 `车型名 · 文件名` 这种完整来源文案，导致下拉列表、已选标签和部分工作区标题过长，也容易让用户误以为同一车型名称被重复展示。

**目标**

- 默认情况下只显示车型名。
- 当同名车型实例同时出现时，自动追加稳定序号，例如 `车型A（1）`、`车型A（2）`。
- 完整来源 `车型名 · 文件名` 仅作为辅助信息保留，不再成为主显示文案。

**方案**

建立统一的显示命名工具，按“同一上下文内的实例集合”计算稳定显示名。

- 唯一车型：显示 `车型名`
- 同名车型：按稳定排序规则编号
- 稳定排序规则：先按来源类型，再按文件名，再按实例键排序，确保刷新后序号不乱跳
- 完整来源名继续可用于 Tooltip、日志或导出说明

**影响范围**

- 对比/智能填报/多车型的车型下拉列表
- 已选标签区
- 待分析车型工作区卡片标题
- 对比表头与修复页中的车型显示文本

**不采用的方案**

- 激活时强制弹窗要求用户重命名：会打断流程，而且“显示啰嗦”本质上是展示层问题，不应强制转成数据编辑动作。

**验证标准**

- 下拉列表默认不再展示完整文件名。
- 同名车型在同一上下文下会显示稳定序号。
- 序号在刷新与重渲染后保持稳定。
