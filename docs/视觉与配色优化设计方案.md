## 一、产品定位与用户

### 1.1 定位（依据 PRD §1）

> 面向**车辆工程与投标场景**的整车参数数据工作台：版本对比、智能填报、资产管理、数据体检、公告号查询。

它不是内容型产品，也不是营销型网站，而是工程师的**生产资料加工仪器**——输入参数表，输出可信的配置数据。PRD 的两大核心价值承诺都是关于"快"和"准"的：秒级识别差异、降低错填风险（投标场景错填 = 废标）。

### 1.2 用户画像（依据 PRD 场景与 docs/ 测试数据）

| 用户 | 典型动作 | 关键诉求 |
|---|---|---|
| 投标专员 | 拿到招标方参数表 → 智能填报 → 审核置信度 → 导出 | 截止期压力下不出错；低置信度项一眼筛出 |
| 车辆工程师 / 公告申报员 | 维护车型参数库 → 版本对比 → 公告号校验 | 参数命名规范、版本间差异不漏判 |
| 数据管理员 | 资产入库、打标签、数据体检与修复 | 批量操作高效；异常数据可扫读 |

**共同特征**（决定视觉方案的四个事实）：

1. **长会话**：每天 6-8 小时面对密集参数表格——视觉疲劳管理是刚需，不是加分项
2. **Excel 母语**：专家用户，数据就是界面本身，装饰性元素全是干扰
3. **高压零错**：废标风险场景——状态信号必须"不可能看漏"，且不允许误报抢占注意力
4. **暗色并行**：V2.0 起暗色模式是正式需求，两套配色必须同一语义、同等可读

### 1.3 由此推导的设计立场

- 给专家用户的工具做**减法**：每个像素要么承载数据、要么服务操作，否则删除
- 状态信号按"**漏看的代价**"分配注意力权重，而不是按"功能的重要程度"
- 长会话要求：中性面占比 ≥95%、彩色只做小面积信号、明度不跳变、无高饱和残影

## 二、设计概念：「精密量具」

把这套软件当作工程师桌上的**量具**（游标卡尺 / 激光测距仪），而不是 App：

- 量具的本体是**哑光金属灰**——界面 95% 的面积是三层中性表面
- 量具的**刻度和读数**是仅有的着色——彩色只出现在文字、细线（边框 / 3px 状态条）、点（≤8px）上
- 读数原则：**界面上每一处彩色都能翻译成一句业务事实**（"这车已在工作集里""这行必填没填""这值是改过的"）。翻译不出来的彩色，删

三条纪律（V0-V2，评审确认版）：

| # | 原则 | 含义 |
|---|------|------|
| V0 | **色彩是信号，不是填充** | 语义色禁止一切常驻背景填充；唯一例外是瞬态反馈（hover / focus / 拖拽悬停）可用 ≤14% weak 底色——它是操作的回声，移开即消失 |
| V1 | **色彩即语义** | 蓝=可交互/焦点，绿=健康/已激活，暖色=警示/变更，红=错误/缺失，灰=其余一切。同屏一色一义 |
| V2 | **状态分层** | 常驻状态用弱信号（条/点），瞬时状态（聚焦）用强反馈（边框）；常驻状态大面积着色 = 让半数列表永远在尖叫 |

延续不动的好资产：**"石墨工作台"三层表面体系**（layout → container → inset，层间 1px 分隔，阴影只给浮层）——问题从来不是体系，是组件没遵守。

## 三、配色方案

### 3.1 中性基座（石墨，冻结现值）

中性面占 ≥95% 面积，是"量具本体"。现有 slate 阶梯冷灰、明度阶梯完整，**值全部冻结**，避免高风险低收益的全局换色：

| 层 | Token | 亮色 | 暗色 | 用途 |
|---|---|---|---|---|
| layout | `--surface-1` | #F8FAFC | #0F172A | 页面底 |
| container | `--surface-2` | #FFFFFF | #1E293B | 卡片 / 容器 |
| inset | `--surface-3` | #F1F5F9 | #334155 | 表头 / 标签底 / hover |
| 分隔 | `--border-default` | #E2E8F0 | #475569 | 层间 1px 线 |
| 正文 | `--text-1` | #0F172A | #F1F5F9 | 17:1 |
| 次级 | `--text-2` | #475569 | #CBD5E1 | 7.6:1 |
| 辅助 | `--text-3` | #94A3B8 | #94A3B8 | 3.4:1（仅限辅助信息） |

### 3.2 信号色（含文字级变体）

长会话 + 读数场景要求：**用作文字的彩色必须达 WCAG AA（≥4.5:1 正文 / ≥3:1 辅助）**。现有语义色原值直接做文字在亮色下不达标（#10B981 对白仅 2.3:1），因此信号色分两档——**原值做线与点，深档做文字**：

| 语义 | 线 / 点（亮 / 暗） | 文字（亮 / 暗） | 白底对比 | 可翻译为 |
|---|---|---|---|---|
| 品牌蓝 | #2563EB / #60A5FA | #2563EB / #60A5FA | 5.2:1 ✓ | "这里可以点 / 你在这" |
| 激活绿 | #10B981 / #34D399 | **#047857** / #34D399 | 6.5:1 ✓ | "已激活 / 健康 / 校验通过" |
| 警示橙 | #F59E0B / #FBBF24 | **#B45309** / #FBBF24 | 5.0:1 ✓ | "建议处理 / 有变更 / 中置信度" |
| 危险红 | #EF4444 / #F87171 | **#DC2626** / #F87171 | 4.5:1 ✓ | "错误 / 必填缺失 / 低置信度" |

> 落地方式：`index.css` 增补 `--success-text` / `--warning-text` / `--danger-text` 三枚变量（亮暗各一档），组件文字用 `text-*-text`，线条与点用原值 token。暗色沿用现有亮档值，无需新增。

### 3.3 业务状态色规范（色值 × 业务事实的对照表）

这是本方案区别于"通用配色"的部分——每个业务状态给出唯一的色彩表达，全 app 不得出现第二种画法：

| 业务状态 | 出现位置 | 色彩表达（符合 V0） |
|---|---|---|
| 资产已激活（在工作集） | 资产列表 | 白卡不变 + **左缘 3px 绿条** + 图标块右下 8px 绿点 |
| 当前聚焦的资产 | 资产列表 | **2px 品牌蓝边框**（全列表唯一）+ 图标块蓝底 |
| 对比·新增 | DiffResultView | 左缘 3px 绿条 + 值 `text-success-text` |
| 对比·移除 | DiffResultView | 左缘 3px 红条 + 值 `text-danger-text` + 删除线 |
| 对比·变更 | DiffResultView | 左缘 3px 橙条 + 旧值删除线 `text-3`、新值 `text-1` |
| 对比·未变 | DiffResultView | 无信号（中性即"无需关注"） |
| 填报置信度·高 / 中 / 低 | MatchResultTable | 百分比数字分别 `text-success-text` / `text-warning-text` / `text-danger-text`，仅文字着色 |
| 必填缺失 | 参数表格 | 左缘 3px 红条（hover 叠 `danger-weak` 瞬态提示），**取消整行红填充** |
| 枚举异常 | 智能填报 | 值 `text-danger-text` + ⚠ 图标 |
| 命名不规范 / 建议 | 资产卡 | 中性底标签 + `text-warning-text` ⚠ / `text-3` 文字 |
| 命名可一键修复 | 资产卡 | `var(--warning)` ✓ 图标（替换硬编码 #D97706） |
| 交互动作 | 全部 | 品牌蓝（含现存误用绿色的"新增到工作区"链接） |

灰度自检：把上表全部临摹成灰度——新增/移除仍有左条与文字色差、移除仍有删除线、缺失仍有左条。**色彩全部是冗余编码，灰度下信息不丢**。

### 3.4 标签：全中性

分类信息靠文字区分，不靠颜色（颜色区分在类别 >4 时必然失效，且是纯装饰）：

- 来源标签（公告数据 / 数据体检 / 工作区导入 / 人工维护）与分组标签（吉利 / 中面 / 客运版）：同一款式 `surface-inset` 底 + `text-2` 12px——`assetSourceTags.ts` 的四色字段停用
- 单卡色彩预算：**零彩色标签 + ≤1 暖色警示徽标 + 1 绿色激活信号**；标题永远是对比度最高的元素

## 四、文字与数字（v4.1 字体方案，已落地）

- **字体族**：系统栈零加载（Tauri 原生观感）。`--font-sans` 显式补齐中文链（PingFang SC / Hiragino Sans GB / Microsoft YaHei / Noto Sans CJK SC）；`--font-mono`（SF Mono / ui-monospace / Menlo…）专用于**公告号 / VIN / 文件路径 / 版本号 / 导出文件名**——标识符用等宽防 0/O、1/I 混淆
- **字号阶梯（8 档，禁止阶梯外字号）**：caption 11（徽章/标签）/ aux 12（表头/辅助）/ body 13（正文基准）/ title 14（模块标题·600）/ section 16（分区标题·600）/ page 20（页面标题·700）/ stat 26（统计大数·700+tabular-nums）/ hero 32（空态主视觉·不进业务界面）。tailwind 侧为 `text-caption…text-hero` 命名类（自带行高与字重）
- **行高三档**：1.25（≥16px 标题）/ 1.5（12-14 正文控件）/ 1.75（长文阅读）
- **数字等宽**：数值、计数、时间戳、置信度一律 `tabular-nums`（工具类已有）
- **存量收敛策略**：存量 `text-[NNpx]` 中凡与阶梯同值的（12/13/14）暂保留写法、值即合规；阶梯外字号（10/24/28/30/32）已收敛到最近档位（数据洞察页与车型抽屉的大数统一 26 `text-stat`、页面/抽屉标题统一 20 `text-page`）。新代码一律用命名类

## 六、组件应用规范

### 6.1 资产卡四态（逐级只变一个变量）

| 状态 | 规格 |
|---|---|
| 默认 | 白卡 + `border-default` 1px |

| 聚焦 | 2px 蓝边框 + 图标块蓝底白图标（全列表唯一） |
| 编辑中 | 白卡 + 蓝边 + 聚焦输入（现状保留） |

### 6.2 顶栏

- 隐藏导航区横向滚动条（`MainLayout.tsx:164`）
- 主题切换 Switch → `type="text"` 图标按钮（视觉降权）
- 版本号降为 `text-3` 12px 跟随标题；菜单激活项 `fontWeight 600` + 圆头 2px 指示条

### 6.3 空态

右栏空白改"灰度 Empty + 一句人话 + 主按钮"（配合交互方案 §3.2 ②），不引入彩色插画——空态也是中性的。

### 6.4 硬编码色清理（155 处 → 0）

映射表：`bg-white`→`surface-container`、`bg-slate-50`→`surface-inset/layout`、`text-gray-700`→`text-1/2`、`text-gray-400`→`text-3`、`border-gray-200`→`border-default`、`text-blue-*`→`text-brand`、`text-green-*`→`text-success(-text)`、彩色淡底→按语义改状态条或瞬态 `*-weak`。顺序：DiffResultView(56) → ConfigManagerView(36) → AssetUpgradeModal(16) → 其余；每完成一个文件跑暗色回归。

> **DiffResultView 豁免说明（v2.2 实施时确认）**：该文件 56 处硬编码全部位于 PDF 导出报告的离屏渲染模板（html2canvas + jsPDF 消费）。导出物是打印介质，必须固定亮色白底、不跟随应用暗色模式——这些硬编码是正确的，**保留不改**。语义变量化的对象是"界面"，不含导出产物。
>
> **已落地（2026-09-16，P2）**：除上述豁免外，硬编码色类已全部替换为语义 token/变量（`tailwind.config.js` 同步新增 `line`/`line-strong` 边框键以支持 `hover:` 变体）。antd token 同源化说明：`themeConfig.ts` 的色值为 CSS 变量的同值十六进制快照——antd 需要对主色做派生计算（hover/active 阶），无法直接消费 `var()` 字符串，双写同值即为该约束下的"同源"。

### 6.5 暗色模式实现（已落地，2026-09-16；v4.1 校正并入）

**机制**：暗色 = antd 双模式 token 显式分叉 + CSS 变量翻转，两层同源。

- `themeConfig.ts` 导出 `getThemeConfig(isDark)`：亮/暗两套 Palette 显式给出（暗色主色抬阶 #8DA1F7、三层表面 #0E1116/#161B23/#202734、边框、四级文字、语义色降纯档）。原因：antd 中**显式 token 值优先于 darkAlgorithm 推导**——此前亮色值写死导致切暗色后 antd 组件（表格/弹窗/抽屉/输入框）残留亮底；历史上靠 index.css 200 行 `.dark !important` 硬撑，语义化重构删除后即暴露
- 组件级 token 同步分叉：`Table.headerBg`（#F7F8FA / #202734）、`Layout.headerBg`（#FFFFFF / #161B23）、`Tabs` 选中色（#2F44D8 / #8DA1F7）
- CSS 侧（`index.css` `.dark`）本就正确，未动：所有 `surface-*`/`text-*`/`--diff-*` 类随变量自动翻转
- 运行时硬编码 hex 全部替换为 `var(--*)`（含 Progress strokeColor、Statistic valueStyle、ExcelPreviewDialog 预览表格），内联样式中的 var() 随主题实时解析；导出模板（CompareView / DiffResultView）按打印介质豁免保留
- antd Tag 静态预设色（blue/green/orange/red/cyan/volcano 的固定色板不随算法翻转）全部换为算法驱动语义键：`success`/`warning`/`error`/`processing` 或中性 `default`——纯计数与分类信息一律中性

**v4.1 校正（专家缺口清单 D-01~D-08 落地记录，2026-09-16）**：

- **D-01（浅色 text-3 对比度）— 采纳改值**：`--text-3` #8A91A0 → **#6F7787**（3.2:1 → 4.5:1）。备选方案"约束 text-3 仅用于 ≥18px"不采纳——本产品没有 18px 辅助文字的空间，12px 小字全靠它，改值是唯一现实解。影响：全 app 辅助文字加深一档
- **D-02（暗色控件描边）— 采纳**：新增 `--border-control`，暗色 #5B6684（3:1）；antd 侧 `colorBorder` = 控件描边（浅 #CCD1D9 / 暗 #5B6684），`colorBorderSecondary` = 装饰分隔（#E4E7EC / #2C3442）
- **D-03/D-04（暗色 text-3/4 不达标）— 采纳**：#8A93A5（5.6:1）、#5E6675（3.0:1）
- **D-05（品牌同色两名拆分）— 采纳，antd 落法为组件级 token**：暗色 `colorPrimary` #8DA1F7 作填充时白字仅 1.9:1。`components.Button` 覆盖 `colorPrimary: #4D64E9`（= --brand-fill，白字 4.9:1）、hover #5569EB。全局 colorPrimary 继续管文字/链接/选中
- **D-06（六组功能件 24 对 token）— 已入库**：`--surface-elevated`/`--border-control`/`--border-popover`/`--mask`/`--shadow-popover`/`--skeleton-*`/`--scrollbar-*`/`--selection-bg`/`--code-*`/`--toast-*`/`--diff-*-chip-bg`/`--table-*`/`--chart-*` 明暗成对进 index.css；滚动条/`::selection`/`.popover-surface`/`.skeleton` 全局件 CSS 已接变量；antd 遮罩经 `colorBgMask` 接入
- **D-07（图表序列）— token 入库待接**：`--chart-1..6` 与 tailwind tokens 的 `chart.seriesLight/Dark` 已备好（JS 图表库读不到 CSS 变量时用）；当前项目无独立图表库（柱状图为 CSS 自绘），后续接入时取数组
- **专家建议④"不开 darkAlgorithm"— 不采纳**：antd 合并顺序为 seed → 算法派生 → 用户显式值覆盖，显式值不会被算法二次加工；去掉算法反而使所有未显式指定的派生色（hover/active/fill 阶）失去暗色适配。保留 `darkAlgorithm + 显式覆盖` 组合

## 七、分期落地

## 八、验收清单

1. **灰度稿检验**：任意页面临摹成灰度，彩色只剩文字/线/点，且状态信息不丢（§3.3 自检表）
2. **一色一义走查**：蓝只在可交互/焦点；绿只在激活/健康；暖色只在警示/变更；标签零彩色
3. **激活压力测试**：激活 ≥50% 资产后列表可扫读，聚焦卡仍是唯一强视觉
4. **对比度**：语义色文字按 §3.2 表达标（≥4.5:1 正文 / ≥3:1 辅助）
5. **连续性**：状态切换每次只变一个视觉变量；跨页面同款；切 tab 无底色闪烁
6. **暗色回归**：两套配色同语义同可读，无亮色残留
7. **形制**：圆角仅 8/6/4；字号仅 12/13/14/16；数字列全部 `tabular-nums`
8. **强调色预算**：单屏可见强调色 ≤2 种（v2.1 采纳，源自 Linear 实践）；色彩不作为状态的唯一编码（红/绿必配线条、图标或删除线，WCAG 1.4.1）

## 九、行业对标与借鉴（v2.1）

### 9.1 垂直领域（车辆公告/参数）：无视觉标杆，只有差异化机会

同类工具确实存在——卡车之家公告查询、司机宝、王力汽车公告查询、商用车联盟、BestECV，以及工信部官方查询平台。但它们全是**传统查询门户**（表单进、列表出，无工作台、无状态体系），没有可借鉴的视觉实践。这意味着：本产品做"工作台化 + 数据质量信号体系"在垂直领域就是差异化本身，参照系应该取自通用数据工具。

### 9.2 通用赛道对标

| 赛道 | 代表工具 | 验证/可借鉴的实践 | 采纳到本方案 |
|---|---|---|---|
| 代码/文件 diff | GitHub、VS Code、Beyond Compare | 绿=增/红=删/橙=改的 git 心智用户已熟悉；色彩仅作冗余编码（色盲模式下换蓝橙仍可读）；"只看差异"默认过滤 | §3.3 diff 四态沿用同套语义；"只看差异"PRD V4.1 已做，保留 |
| 表格对比 | Microsoft Spreadsheet Compare、xlCompare | 结果页**常驻色彩图例**（颜色含义显式可查，不靠猜）；变更按严重度分层；一键导出对比报告 | **图例补进 P1**（对比结果页头部小图例：绿条=新增…）；PDF 报告 PRD 已有 |
| 数据库 GUI（长会话表格的黄金标准） | DataGrip、TablePlus、Navicat | 空值斜体灰弱化；数字右对齐等宽；行状态用左缘色条；暗色模式一等公民 | §4 `tabular-nums`、§3.3 左条状态语言、§1.3 暗色并行 |
| 现代效率工具（气质标杆） | Linear | 近单色中性面 + **单强调色**；"单屏超过两种强调色就是噪音而非信号" | V0/V4 总纲的直接背书；验收第 8 条 |
| 表格 SaaS | 飞书多维表格、Airtable | 标签默认低饱和、字段类型用图标不用色块 | §3.4 标签全中性（比它更严一档） |
| 数据清洗 | OpenRefine、Excel Power Query | 质检结果先汇总成"报告"（N 项异常按严重度分组），再定位到行——不把表格染成花脸 | 数据体检页的汇总卡方向；与交互方案 §3.4 必填汇总条互援 |

### 9.3 对标结论

v2.0 的"信号不填充"不是个人口味，而是 GitHub / Linear / DataGrip 这类以"长时间读数"为核心场景的工具的共同方向。唯一比它们更严的点：GitHub/VS Code 的 diff 仍用淡底填充，本方案改用左缘色条——取舍理由是参数表格单屏行数与连续阅读时长都超过代码 diff，填充在 40+ 行表格里的视觉疲劳代价更高。参考链接：

## 十、《曜蓝 Obsidian Blue v4.0》评审与合并（v2.2）

专家提案：`docs/design-v4-obsidian-blue/`（design-proposal.html + tokens.css + tailwind.tokens.js）。

### 10.1 评审结论：采纳为色彩底座

这套提案与本方案是互补关系而非竞争关系——它交付的是**色彩 token 层**，本方案交付**状态/组件/落地层**。质量判断：

- **语义色"三件套"体系优于本方案 §3.2**：每个语义族统一定义 文字（600/700 阶）/ 图形（500 阶）/ 背景（50 阶），比我们的"`-text` 后缀变量"更完整、更可执行。直接采纳
- **业务状态 token 层是本方案 §3.3 的制度化落地**：`--diff-added/removed/modified-*`、`--conf-*`、`--req-*`、`--src-*` 把"每个业务状态唯一画法"变成了有名字的 token。采纳，并补一枚遗漏的 `--asset-active-*`（资产已激活态，提案业务层未覆盖，仍按 §3.3 绿条+绿点执行）
- **对比度宣称经抽查验算属实**：#2F44D8 on #FFF ≈ 7.1:1 AAA；#0A7A52 / #9A5806 / #C92A2A 均 ≥4.5:1。文字档/图形档分离与 §3.2 的初衷一致且更严格
- **暗色"非简单反色"策略正确**：底色拉蓝灰去纯黑、主色抬至 300-400 阶、语义降纯，符合长会话抗疲劳目标
- **变量名兼容声明属实**：tokens.css 是现有 `index.css` 变量的严格超集（同名替换 + 新增），tailwind.config 的 var 映射无需改动
- **"必填缺失 = 虚线描边（待办）≠ diff 红（错误）"** 是本方案没有的语义细分，采纳

### 10.2 三个与既定原则的冲突点（建议决议）

| # | 冲突 | 建议决议 |
|---|---|---|
| 1 | diff 状态行用 50 阶**整行底色**，触碰 V0"不填充" | **作为 V0 唯一明文例外采纳**：常驻填充仅限"差异结果表"一个场景（50 阶底 + 3px 左条 + 图标标签三重编码，单屏语义色面积 ≤10%——提案自带的面积法则）。理由：diff 表里行状态就是内容本身，GitHub / Spreadsheet Compare 同款惯例；列表、卡片、表单等其余场景维持线/点/文字，不放宽 |
| 2 | 通用"选中 = brand-50 底 + 2px 左指示条" | **表格行选中采纳**（与 antd 习惯一致）；**资产卡聚焦维持 §3.3 的 2px 边框方案**（卡片是导航对象不是数据行，边框足够且更安静） |
| 3 | 来源标签用 青碧/紫/灰 三色（--src-*），触碰 v1.1"标签全中性" | **采纳 --src-* 替代"全中性"**：它有图标双编码、色相克制（绝不占用绿/红/橙语义色）、且只是把早期四种随机 antd 色收敛为 token 管辖的三种灰调色。**用户自定义分组标签仍保持全中性**（§3.4 不变）——色彩预算留给状态 |

### 10.3 两个必须说清的边界

1. **"组件代码零改动"仅指 token 替换这层**。截图里的绿色大卡是 **class 用法问题**（`DataSourcePanel.tsx:646` 写了 `surface-success`）——换 token 后它只会从亮绿变成 `#0C9A68` 的深绿，依然是饱和色块。§3.3 资产卡四态的组件修复仍然必须执行
2. **提案未覆盖的部分由本方案补齐**：资产激活态、顶栏（滚动条/主题切换）、右栏空态、155 处硬编码清理、P0-P2 分期与验收清单。两份文档合并后即为完整方案

### 10.4 合并后落地顺序

1. 替换 `index.css` 的 `:root` / `.dark` 变量值为 tokens.css（新增 `--asset-active-*`；`--info` 进 antd token）+ `tailwind.config.js` 接入色阶 + `themeConfig.ts` 同步 colorPrimary 等
2. 原 P0 组件止血（激活卡状态化、顶栏滚动条、标签收敛、动作链接改蓝）在**新色值上执行**
3. 原 P1/P2 不变；硬编码清理映射表中 slate 系替换目标值同步换为岩灰系（色差极小，迁移期混用无感知）
