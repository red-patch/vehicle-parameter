现状方案的三个问题

  • 1通用蓝，无识别度 —— 直接使用 Tailwind 默认 blue-600 #2563EB，与千万个 SaaS 后台撞色，缺乏工具软件应有的专业气质。
  • 2语义色对比度不达标 —— 变更色 #F59E0B 作文字时对比度仅 2.5:1，小字号下几乎不可读；成功色 #10B981 仅 3.1:1。
  • 3业务状态无统一 token —— diff 四态、置信度、必填缺失等颜色散落在各组件中硬编码，改版和暗色适配成本高。

状态色面积法则
语义色在单屏内的渲染面积 ≤ 10%。整行染色仅允许出现在「差异列表」这一核心业务场景中；其余场景语义色只落在圆点、图标、标签、3px 侧条上。背景层与文字层必须成对使用本族 token，禁止跨族混搭。
06

暗色模式 · 另一套光照条件

暗色不是把浅色反相，而是换一套光照假设重新取色。顶栏右侧的主题开关可把整个提案页切到暗色——本章节所有色值都是真实 token 实时渲染，不是截图；下方深色面板则是在浅色页里就地预览暗色组件。全部数值经 WCAG 2.x 相对亮度公式实测，四舍五入到一位小数。

三条铁律 · 量化到数值

① 底不用纯黑，且明暗方向相反

用 #0E1116 而不是 #000：纯黑与容器层的亮度差在 OLED 屏上会出现"灰块漂移"，暗色残像也更重。

更关键的是方向：浅色靠"越内层越深"表达凹陷，暗色必须反过来——越上层越亮。表头、hover、弹层都靠提亮成立。

② 主色抬阶，并且一色两名

文字/链接/描边用 300-400 阶 #8DA1F7（对容器底 7.1:1）；实色填充必须另开一个 token #4D64E9（白字 4.9:1）。

这是暗色最容易踩的坑：同一个"品牌蓝"既要当文字又要当按钮底，暗色下这两个角色需要的明度是相反的。故拆为 --brand 与 --brand-fill。

③ 语义色降纯抬明

图形层明度 ΔL +9 ~ +18、饱和 ΔS -4 ~ -35（红是唯一例外：需微增饱和才不发灰）；文字层一律落 L 68-77 区间。

禁止直接把 500 阶语义色搬到深底——那是"霓虹感"的来源。具体迁移量见下表。

暗色六禁

✕纯黑底 + 纯白字
  • #000 底 + #FFF 字 = 21:1，过亮会加剧眩光与暗色残像，且与容器层失去层次
  • ✓ 底 #0E1116、正文 #E6E9EF（14.2:1），留出"还能更亮"的余量
✕把 500 阶语义色直接搬过来
  • 浅色 #0C9A68 在深底上既不够亮又过饱和，成片出现即"霓虹感"
  • ✓ 图形层降钝抬明（#3DBD8A），文字层再抬一档（#5BD0A2）
✕一个品牌色同时当文字和按钮底
  • 文字要"亮"（深底可读）、填充要"暗"（白字可读），暗色下这对需求是相反的
  • ✓ 拆名：--brand #8DA1F7 走文字，--brand-fill #4D64E9 走填充
✕用投影表达层级
  • 深底上阴影几乎不可见，弹层会"糊"在背景里；加大阴影只会做出脏边
  • ✓ 抬升改由「+1 层表面亮度 + 1px 提亮描边」承担，阴影仅作补充
✕用 1px 深色线区分可编辑区
  • 暗色没有"白底填充差"可用，沿用浅色的 #3A4354 描边（1.7:1）等于没画
  • ✓ 控件描边单列 token 并提到 3:1（#5B6684），装饰性分隔线才允许低对比
✕暗色里给每个组件单独"打补丁"
  • 组件内写 dark:bg-[#1a1a1a] 之类的一次性值，改色时必然漏改、两套模式失同步
  • ✓ 暗色只允许在 .dark 下翻转变量；组件里出现的颜色必须能追溯到一个 token

接入时必须知道的四件事
  • ① AntD 的 colorPrimary 同时管"文字强调"和"实色填充"。暗色下 #8DA1F7 作填充时白字只有 1.9:1 —— 主按钮必须用 Button 的 classNames 覆盖为 --brand-fill，不能只配一个 token 了事。
  • ② colorBorder 只承担"装饰性分隔"，控件描边要靠组件级 colorBorder 之外的单点覆盖（Input / Select / Checkbox 各一处），值用 #5B6684。
  • ③ 表格 headerBg 暗色用 #202734（比容器亮），这与浅色 #F1F3F6（比容器暗）方向相反，是刻意为之。
  • ④ 暗色不要开 darkAlgorithm 让它自己推导——它会把已显式指定的值再次加工，出现难排查的偏色。显式给全两套值。
落地顺序建议：① 先把 tokens.css 的 :root / .dark 两段整体替换进 src/index.css（新增 token 不改变任何现有渲染）；② 再单独评审 D-01、D-02、D-05 三项会改变观感的修正；③ 最后按 D-07 给图表配置接上 chart.seriesDark，并把 themeConfig.ts 的 DARK 分支按上表校正。验收方式：顶栏主题开关切一遍本页，再跑 版本对比 / 智能填报 / 数据体检 三个页面的明暗两色。

交互规范

桌面工具软件，不是营销网站——动效克制、反馈即时、键盘可达。

动效 · 三档克制
  • 微反馈 120ms：hover、勾选
  • 状态切换 180ms：展开、Tab
  • 结构变化 240ms：弹层、行增删

  • 尊重 prefers-reduced-motion
状态 · 三态规则
  • Hover：surface-3 底色，120ms
  • 选中：brand-50 底 + 2px 左指示条
  • 聚焦：2px brand-400 环，仅键盘触发
  • 禁用：text-4 + 透明度 60%，不删元素
  • 加载：骨架屏，禁整页 Spin
密度 · 数据优先
  • 表格行高 36px（标准）/ 32px（紧凑）
  • 单元格水平 padding 14px
  • 数值列一律 tabular-nums 防抖动
  • 表头 12px / 正文 13px / 统计大数 26px
  • 间距基于 4px 网格

可辨别 · 双编码
  • 差异：＋ − ≠ ＝ 图标 + 色彩

  • 必填缺失：虚线描边 + ✕ 图标

  • 通过 deuteranopia 模拟验证

  • 空状态给下一步动作，不只说"暂无数据"
