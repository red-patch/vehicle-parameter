# 前端交互优化设计方案

> 版本：v1.0 · 2026-07-17 · 基于代码现状调研（证据见文末附录）
> 范围：DST 车型参数管理工具（Tauri 桌面端），仅前端交互层，不动技术栈、不动数据结构

---

## 一、设计原则

| # | 原则 | 含义 |
|---|------|------|
| P1 | **效率优先** | 这是桌面生产力工具，不是展示页。高频操作路径 ≤2 次点击，键盘可达 |
| P2 | **状态可见** | 任何异步操作必须有明确的加载/成功/失败表达；用户永远知道"现在发生了什么" |
| P3 | **操作可逆** | 破坏性操作（删除/覆盖/清除）要么可撤销，要么有明确确认；绝不静默执行 |
| P4 | **就地反馈** | 反馈出现在操作发生的位置附近；只有跨上下文的重要事件才用全局通知 |
| P5 | **一套语言** | 同类交互用同一种模式（编辑、删除、选择、筛选），不发明第二种做法 |

## 二、信息架构

### 2.1 现状问题
- 顶部 Menu 7 项是平铺的，但 `App.tsx` 里还躺着 **diff（Excel 上传对比流）和 search（SmartLayout）两个不在菜单里的页面**——不可达死代码，纯维护负担
- 「版本对比」一词二义：菜单 compare（资产内车型对比）与 diff 页（Excel 文件对比）是两回事，用户无从分辨
- pool 页双栏（DataSourcePanel + VehicleListPanel）信息层级平级，但两者是"选资产 → 看车型"的主从关系

### 2.2 调整方案
```
现状 7 项平铺  →  分组为 3 区：

工作区（日常高频）
  ├─ 资产管理      (pool)     ← 默认页
  ├─ 版本对比      (compare)
  ├─ 智能填报      (fill)
  └─ 多车型管理    (multi)

数据质量（低频维护）
  └─ 数据体检与修复 (purify)

系统（极少进入）
  ├─ 公告号查询    (announcement)
  └─ 系统配置      (dict)
```

- **删除 diff / search 死代码**（连同 `ExcelUploader`、`ParametersTable`、`DiffResultView` 懒加载块），`App.tsx` 从 243 行降到 ~120 行
- Menu 加分组标题或分隔线；低频项视觉降权（小一号 / 置灰）
- pool 页双栏改 **主从布局**：左侧资产列表固定 320px，右侧车型面板自适应。当前 `flex-1` 对半分让资产长文件名被截断（证据：`VehicleListPanel.tsx:292` 有 truncate + title 兜底）

## 三、核心流程交互改进

### 3.1 资产管理（DataSourcePanel，920 行）
**断点**：22 处 message 满天飞，但上传/刷新等关键动作反而缺进度表达；右键菜单只有这里用，发现性为零。

| 改进 | 说明 |
|------|------|
| 资产列表加行内状态列 | 解析中（Spin）/ 已激活（绿点）/ 异常（红点+原因 Tooltip），替代 message 轮播 |
| 上传改就地进度 | 上传按钮旁出现进度条行，完成后该行高亮闪烁一次——不动用全局 message |
| 右键菜单加可见入口 | 行尾加 `⋯` 按钮展开同一菜单，右键保留作为快捷方式 |
| 标签筛选加结果计数 | 选中标签后立即显示"N 个资产匹配"，无结果时 Empty 态给"清除筛选"按钮 |

### 3.2 车型选择与工作集（VehicleListPanel，499 行）
**断点**：0 处 message、0 处加载态——点车型后有没有反应全靠猜。

| 改进 | 说明 |
|------|------|
| 工作集持久可视化 | 面板顶部加"工作集（N）"胶囊条，选中车型即时飞入（微动画），可单个移除 |
| 加载骨架 | 资产切换时车型区域显示 Skeleton（当前完全没有） |
| 空态引导 | 无资产时 Empty + 主按钮"去添加资产"（跳 pool 左栏并高亮上传区）；已选资产但无车型时提示"该资产未解析出车型" |
| 详情 Drawer 加操作组 | 「加入对比」「加入填报」主按钮常驻底部，当前只有"快速对比"一个出口（`VehicleListPanel.tsx:488`） |

### 3.3 版本对比（CompareView）
**断点**：选完两个车型才开始，但入口散落在各处。

- 工作集 ≥2 个车型时，全局悬浮「开始对比（2）」按钮，一键进 compare 并自动填充
- 对比结果页加「导出差异报告」主操作（当前对比完没有出口）
- 差异项支持行内「以左为准 / 以右为准」快捷修复，接入修复流而非只展示

### 3.4 智能填报（SmartFillView）
- 必填项缺失从"整行标红"升级为**顶部汇总条**："还有 3 项必填未填 [定位到第一项]"，点击滚动定位
- 自动填充来源加 Tooltip 说明"该值来自 XX 资产"（数据可溯源）
- 保存前校验失败时，错误清单用 notification（跨上下文重要事件），不用 message 连发

### 3.5 多车型管理（MultiVehicleView）
- 批量操作加**二次确认 + 结果回执**："已对 5 个车型应用修改 [撤销]"——撤销走 P3 原则的可逆机制
- 表格空列折叠：默认隐藏全空参数列，用户可展开

## 四、交互规范层

### 4.1 反馈决策树（全项目统一）
```
操作产生了反馈需求
├─ 结果是否就地可见？（列表项变化/值变化）
│   ├─ 是 → 就地反馈：行高亮/值更新/微动画，不发任何全局提示
│   └─ 否 ↓
├─ 是否需要用户后续行动？
│   ├─ 是 → notification（如"填报完成，是否导出 [去导出]"）
│   └─ 否 ↓
├─ 是否跨页面产生的影响？
│   ├─ 是 → notification.info
│   └─ 否 → message.success（一句话，≤1.5s）
错误一律：就地红色 inline 文案为主；系统性失败才 notification.error
```
依据：现状 notification 全项目 0 使用，message 分布 22/5/5/3/1/0/0/0 严重失衡。

### 4.2 加载 / 空态 / 错误态模式
| 场景 | 统一模式 |
|------|----------|
| 区域加载 | Skeleton（保持布局骨架，不用整页 Spin） |
| 按钮动作 | 按钮自身 `loading`，禁用重复提交 |
| 空列表 | Empty + 一句人话说明 + 一个引导按钮（不说"暂无数据"） |
| 加载失败 | 就地错误卡片 + [重试] 按钮，不清空已有内容 |

### 4.3 快捷键体系（重写）
现状是 DOM querySelector hack（`MainLayout.tsx:108-146`：Cmd+S 点"第一个 primary 按钮"，必然误触发）。

**方案**：建立 `ShortcutContext`——各视图注册自己的处理器，全局监听器按焦点上下文分发，不再碰 DOM。

| 快捷键 | 上下文 | 行为 |
|--------|--------|------|
| ⌘S | 有未保存更改的视图 | 保存当前视图（视图自己注册） |
| ⌘F | 全局 | 聚焦当前页面主搜索框（页面注册） |
| ⌘Z / ⌘⇧Z | 表格编辑 | 撤销/重做 |
| ⌘Enter | 模态框 | 确认主按钮 |
| Esc | 顶层浮层 | 关闭（antd 自带，不再重复实现） |
| ? | 全局 | 快捷键速查面板（发现性） |

### 4.4 可逆性策略
| 操作类型 | 策略 |
|----------|------|
| 删除资产 / 清除工作集 | Modal 确认（现状已有，保留） |
| 批量修改参数 | 执行后 message 带 [撤销]，5s 内可回滚（store 快照） |
| 表格单元格编辑 | ⌘Z 撤销栈（store 层实现，编辑动作入栈） |
| 覆盖性导入 | 导入前预览对话框（现状 ExcelPreviewDialog 已有，补"将覆盖 N 项"警示） |

## 五、暗色模式治理（根治，非打补丁）

**现状三件套**：antd `darkAlgorithm` + `.dark` 类 + index.css 约 200 行 `!important` 覆盖——**连 `.bg-white`、`.text-gray-700` 这类 Tailwind 工具类都被强行覆盖**，新组件写 `bg-white` 反而对、写 `bg-slate-200/50`（pool 页已有实例）就漏。

**根治路线**：
1. 定义语义 CSS 变量：`--surface-1/2/3`、`--text-1/2/3`、`--border-1`、`--accent`，亮暗两套值挂在 `:root` / `.dark`
2. Tailwind 配置映射：`surface: 'var(--surface-1)'` 等语义色名，组件只写 `bg-surface text-1 border-1`
3. 组件改造：全局搜索替换硬编码色类（`bg-white`→`bg-surface`，`bg-slate-*`、`text-slate-*`→语义类）
4. **删除 index.css 里全部 Tailwind 工具类覆盖**（保留 antd 组件覆盖作为过渡，逐步移交 antd token）
5. antd ConfigProvider 的 token 同步改为引用同一组变量，双体系同源

收益：新组件默认正确，不再依赖开发者记得"这个类有没有被覆盖"。

## 六、优先级与分期

### P0 —— 反馈兜底（1 周内，成本低感知强）
- ① 反馈决策树落地：VehicleListPanel / DataPreview / SheetPickerModal 补加载态与操作反馈
- ② 空态统一：Empty + 引导按钮模式铺到所有列表
- ③ 快捷键 hack 重写为注册分发式
- ④ 删除 diff/search 死代码
> 为什么先做：都是局部改动，不动布局不动样式体系，当天见效。

### P1 —— 结构提效（2-3 周）
- ⑤ 菜单分组 + pool 主从布局
- ⑥ 工作集胶囊条 + 对比/填报出口串联（全局「开始对比」按钮）
- ⑦ 批量操作确认 + 撤销机制（store 快照）
- ⑧ DataSourcePanel 拆分（920 行 → 列表/标签/上传三组件）

### P2 —— 体系根治（3-4 周）
- ⑨ 暗色模式 CSS 变量化（风险最高，需全页面回归）
- ⑩ 表格编辑撤销栈
- ⑪ 拖拽（资产分组拖入、工作集拖排序）
- ⑫ ⌘Z 编辑撤销 + 快捷键速查面板

## 七、验收方式

**关键路径走查清单**（每期完成后全量过一遍）：
1. 添加资产 → 解析 → 选车型 → 对比 → 导出：每步都有明确反馈，无"静默期"
2. 暗色模式切换：全页面无亮色残留、无文字不可读
3. 仅键盘完成：搜索 → 选择 → 保存
4. 破坏性操作：删除资产有确认；批量修改可撤销
5. 空态：清空资产库后每个页面都有引导而非白屏
