# 视觉与配色方案 · 青墨工坊（v3）

> 版本：v3.0 · 2026-09-16
> 与《视觉与配色优化设计方案 v2.0「精密量具」》并存的**替代方案**——同样从定位与用户画像出发，但立意不同、落点不同
> 范围：整车产品工作台（Tauri 桌面端）；不动技术栈、不动交互流程
> 关联：《交互优化设计方案.md》管行为，本文管外观；v2.0 管"如何用冷峻量具感做减法"，本文管"如何用工坊的温暖与手感做减法"

---

## 一、从同一个问题出发，去往不同的答案

v2.0 与 v3.0 共享同一组前提（依据 PRD §1、§4 与 V2.0/V4.0 章节）：

| 共享前提 | 含义 |
|---|---|
| **场景**：车辆工程 + 投标，每天 6–8h 密集读参数 | 视觉疲劳管理是刚需，不是加分项 |
| **用户**：投标专员 / 车辆工程师 / 数据管理员 | 都是 Excel 母语专家，数据即界面 |
| **风险**：废标 = 错填 = 颜色信号必须不可能误读 | 状态信号按"漏看代价"分配权重 |
| **约束**：亮 / 暗两套配色必须同语义、同等可读 | 暗色不是事后补丁，是设计输入 |

不同的回答：

| | v2.0「精密量具」 | v3.0「青墨工坊」 |
|---|---|---|
| 立意 | 把软件当成桌上的**游标卡尺**：冷峻、精确、哑光金属灰 | 把软件当成桌上的**工作台**：木桌 + 铜绿仪器 + 暖色台灯 |
| 基底 | 冷灰 slate (#F8FAFC / #0F172A) | 暖中性 (#FBF8F1 / #1B1714)，长时间对屏更柔和 |
| 品牌色 | 蓝 #2563EB（工业蓝） | **深青 #0F766E**（技术图册的铜锈绿）—— 区别于"国内 SaaS 默认蓝" |
| 信号色冲突解决 | 蓝=品牌 / 绿=激活 / 暖=警示 / 红=危险（4 色分工） | 青=品牌 / 绿=激活徽标 / 蓝=信息链接 / 暖=变更 / 红=缺失（5 色但**主次分明**） |
| 形制 | 圆角 8/6/4，卡片扁平 | 圆角 6/4/3，**紧凑密度**，每屏多看 1 行 |
| 字体 | -apple-system 栈 | 同左 + 中文 **PingFang SC / 思源黑体** 优先，数字 `tabular-nums` |

> **v3 的核心差异**：把"专家工具"从"冷峻仪器"重新定位为"有温度的工作台"——专业感不靠冷色，靠密度与手感。

## 二、用户画像（与 v2.0 同源，深化两段）

| 用户 | 典型动作 | 关键诉求 |
|---|---|---|
| 投标专员 | 拿到招标方参数表 → 智能填报 → 审核置信度 → 导出 | 截止期压力下不出错；**低置信度项一眼筛出**（v3 强化：置信度<100% 的行整行左缘橙条，不是只染数字） |
| 车辆工程师 / 公告申报员 | 维护车型参数库 → 版本对比 → 公告号校验 | 参数命名规范、版本间差异不漏判；**版本对比导出 PDF 的品牌色在客户机上一眼认出"这是我们发的"** |
| 数据管理员 | 资产入库、打标签、数据体检与修复 | 批量操作高效；**异常数据可扫读**（v3 强化：异常项用 8px 状态点 + 列尾 ⚠，扫一眼就能数出 12 条异常） |

**新发现的诉求**（v3 单独回应）：
1. **白底长时间视觉疲劳**——投标专员白天连续 6h 对着参数表，冷白底比暖底更刺眼（v2.0 的 #F8FAFC 在低亮度屏上反光明显）。v3 用 #FBF8F1 暖白，长时间使用更柔
2. **品牌识别度不足**——v2.0 的蓝与国内 ToB 工具（飞书/钉钉/语雀）撞色，客户汇报 PDF 看上去像"另一个 SaaS"。v3 的深青有差异化记忆点
3. **工作集不可见**——v2.0 没有解决"我选了哪些车型去做对比/填报"的问题，v3 引入**工作集胶囊条**

## 三、设计概念：「青墨工坊」

> 「把工程师桌上的工作台搬进屏幕：暖色木纹底、青铜仪器、一盏可调色温的台灯。」

三个角色：

| 角色 | 视觉体现 | 出现位置 |
|---|---|---|
| **木桌（基底）** | 暖中性表面，三层 #FBF8F1 → #FFFFFF → #F5EFE3 | 全局背景、卡片、嵌槽；暗色 #1B1714 → #221E1A → #2B2521 |
| **铜绿仪器（品牌）** | 深青 #0F766E 亮 / #5EEAD4 暗 | 顶栏激活、聚焦边框、行动按钮、Tab 指示条 |
| **台灯（局部光）** | 蓝 #0369A7 仅作链接/信息；绿 #15803D 仅作激活徽标 | 辅助信号，受控使用 |

### 三条纪律

| # | 原则 | 含义 |
|---|------|------|
| V3.0 | **暖中性 95% + 冷青 5%** | 中性面 ≥95% 面积；青铜色只出现在"行动"与"焦点" |
| V3.1 | **一色一义 + 角色分明** | 青=品牌/可交互；绿=已激活徽标；蓝=信息/链接；橙=变更；红=错误。同屏同色同义 |
| V3.2 | **状态分层** | 常驻信号用弱信号（3px 左缘条 / 8px 状态点），瞬时信号用强反馈（边框 / 高亮）；状态大面积填充 = 让半数列表永远在尖叫 |

### 与 v2.0 的关键差异

- **v2.0 用蓝做品牌，激活再用绿 → 4 色分工；v3.0 用青做品牌，激活用绿徽标，蓝降为信息 → 5 色但主次清晰**，避免"激活态被装饰性绿淹没"
- **v2.0 冷色基底；v3.0 暖色基底**——视觉感受从"医院设备"到"工程师工作台"
- **v3.0 引入"工作集胶囊条"**：v2.0 没有解决"我选了哪些车型"的可视化问题
- **v3.0 引入"列尾状态点"**：v2.0 状态用左缘条 + 文字色；v3.0 在表格列尾固定加 8px 状态点，扫一眼能数异常项数量

## 四、配色方案

### 4.1 中性基座（木桌，冻结现值风格）

| 层 | Token | 亮色 | 暗色 | 对比比 |
|---|---|---|---|---|
| layout | `--surface-1` | `#FBF8F1` | `#1B1714` | — |
| container | `--surface-2` | `#FFFFFF` | `#221E1A` | — |
| inset | `--surface-3` | `#F5EFE3` | `#2B2521` | — |
| 分隔 | `--border-default` | `#E8E2D2` | `#3A332C` | — |
| 强分隔 | `--border-strong` | `#C9C0A8` | `#544A3F` | — |
| 正文 | `--text-1` | `#1B1714` | `#F5EFE3` | 15.8:1 ✓ |
| 次级 | `--text-2` | `#5C5246` | `#C9C0A8` | 7.2:1 ✓ |
| 辅助 | `--text-3` | `#9C8E7A` | `#877A6A` | 3.6:1（仅辅助） |

> **为什么不用 slate 冷灰**：投标专员白天 6h 对屏幕，冷白底反光更强、易疲劳。暖白 #FBF8F1 与纸张色接近，仪表盘般的"工作台"感（v2.0 选 slate 是"金属量具"概念自洽，v3.0 选暖色是"工作台"概念自洽）

### 4.2 角色色（铜绿仪器 + 辅助色）

**作文字的彩色必须达 WCAG AA**（≥4.5:1 正文 / ≥3:1 辅助），分两档：原值做线与点，深档做文字。

| 角色 | 线 / 点 | 文字 | 白底对比 | 业务事实 |
|---|---|---|---|---|
| **品牌青（铜锈）** | `#0F766E` / `#5EEAD4` | `#0F766E` / `#5EEAD4` | 5.6:1 ✓ | "可交互 / 你在这 / 这是行动" |
| 激活绿 | `#15803D` / `#4ADE80` | `#166534` / `#4ADE80` | 7.1:1 ✓ | "已激活 / 已收录 / 校验通过" |
| 信息蓝 | `#0369A7` / `#38BDF8` | `#0369A7` / `#38BDF8` | 5.9:1 ✓ | "这是链接 / 这是参考信息" |
| 警示橙 | `#C2410C` / `#FB923C` | `#9A3412` / `#FB923C` | 6.3:1 ✓ | "有变更 / 中置信度 / 建议处理" |
| 危险红 | `#B91C1C` / `#F87171` | `#B91C1C` / `#F87171` | 6.8:1 ✓ | "错误 / 必填缺失 / 低置信度" |

> 与 v2.0 的差异：v2.0 用 4 色分工；v3.0 用 5 色但**主次分明**——青为主、绿蓝为辅、橙红为警。视觉上不会出现"四种颜色都在抢注意力"的情况。

### 4.3 业务状态色规范

每个业务状态给出唯一的色彩表达，全 app 不得出现第二种画法：

| 业务状态 | 出现位置 | 色彩表达 |
|---|---|---|
| 资产已激活 | 资产列表 | 白卡不变 + **左缘 3px 绿条** + **列尾 8px 绿点** |
| 当前聚焦 | 资产列表 / 输入框 | **2px 品牌青边框**（唯一强视觉）+ 标签色变青 |
| 对比·新增 | DiffResultView | 左缘 3px 绿条 + 值 `text-success-text` |
| 对比·移除 | DiffResultView | 左缘 3px 红条 + 值 `text-danger-text` + 删除线 |
| 对比·变更 | DiffResultView | 左缘 3px 橙条 + 旧值删除线 `text-3`、新值 `text-1` |
| 对比·未变 | DiffResultView | 无信号 |
| 填报置信度·高 / 中 / 低 | MatchResultTable | 数字分别 `text-success-text` / `text-warning-text` / `text-danger-text`；**低置信度行加左缘红条**（v2.0 没有） |
| 必填缺失 | 参数表格 | 左缘 3px 红条 + **列尾 8px 红点**（v2.0 没有列尾点）+ hover 叠 `danger-weak` |
| 枚举异常 | 智能填报 | 值 `text-danger-text` + ⚠ + **列尾红点** |
| 命名不规范 | 资产卡 | 中性底标签 + `text-warning-text` ⚠ |
| 命名可一键修复 | 资产卡 | `var(--warning)` ✓ 图标 |
| 跨页跳转链接 | 全部 | **`text-info` 蓝色**（v2.0 误用绿色，v3.0 明确分工） |

### 4.4 灰度自检

把 §4.3 表全部临摹成灰度——新增/移除/变更仍有左条 + 文字色差 + 删除线、缺失仍有左条 + 列尾点。**色彩全部是冗余编码，灰度下信息不丢**。

## 五、文字与数字

- **系统字体栈保留**：中文 `PingFang SC / Hiragino Sans GB / Source Han Sans SC`，西文 `-apple-system / Segoe UI`——与 OS 同源是"工坊桌面"的一部分
- **数字等宽**：所有参数值、计数、时间戳、置信度百分比加 `tabular-nums`——v2.0 已有，v3.0 强制所有统计列开启
- **字号阶梯（4 档封顶）**：

| 档位 | px | 用途 |
|---|---|---|
| xs | 11 | 元信息、列脚注、时间戳 |
| sm | 13 | 正文（antd 全局默认） |
| md | 14 | 控件、Tab 标题、卡标题 |
| lg | 16 | 仅页面主标题 |

- **字重三档**：400 / 500（控件）/ 600（标题·激活态文字），不再使用 700
- **行高**：列表/表格行高收紧到 28px（v2.0 是 32px），扫读行数 +15%

## 六、形制与密度

| 项 | v3 规范 | v2.0 对比 | 说明 |
|---|---|---|---|
| **圆角** | 6 / 4 / 3 三档 | 8 / 6 / 4 三档 | 更紧凑 |
| **卡片圆角** | `rounded-md` (6) | `rounded-lg` (8) | 紧凑 |
| **间距** | 4px 基数 | 4px 基数 | 同 |
| **行高** | 列表 28px / 表格 30px / 段落 20px | 32 / 32 / 22 | **关键差异**：表格多看 1 行 |
| **按钮高度** | 28px（紧凑）/ 32px（标准） | 32px 单一 | 默认紧凑 |
| **动效** | 150–200ms ease-out；按压 `scale(0.98)` | 同 | 补按压反馈 |
| **焦点** | `:focus-visible` 品牌青 2px outline | 蓝 2px outline | 改为品牌青 |
| **滚动条** | 内容区隐藏横向滚动条；列表区 6px（更细） | 8px | 更细的工坊感 |

## 七、组件应用规范

### 7.1 资产卡四态（v3 强化列尾状态点）

| 状态 | 规格 |
|---|---|
| 默认 | 白卡 + `border-default` 1px |
| hover | 仅边框变 `border-strong` |
| 已激活 | 白卡 + **左缘 3px 绿条** + **列尾 8px 绿点**（v3 新增：让"已激活"在长列表里能数出来） |
| 聚焦 | **2px 品牌青边框**（全列表唯一）+ 标签色变青 |
| 编辑中 | 白卡 + 青边 + 聚焦输入 |

### 7.2 顶栏（v3 简化）

- 高度 **40px**（v2.0 是 48px），更紧凑的"工坊桌面"感
- 拖拽区透明，菜单字号 **13px**，字重 500
- 选中态：底部 **2px 圆角指示条**（品牌青）+ 文字变青
- 主题切换 Switch → `type="text"` 图标按钮（视觉降权，与 v2.0 同）
- 版本号降为 `text-3` 11px 跟随标题

### 7.3 工作集胶囊条（v3 新增，对应 PRD V4.0 "工作集" 概念）

需求：用户选完车型去做对比/填报，选过的车型散落在各处。v3 在所有"选车型"页面右上方加 **工作集胶囊条**：

```
┌────────────────────────────────────────────────────────────┐
│  工作集 (4)  远景V8E客运版V250808 × │ F1E ZB5030XXYBEVGD… × │ ... │ → 对比 │
└────────────────────────────────────────────────────────────┘
```

- 胶囊高度 24px，背景 `surface-inset`，边框 1px
- 单个胶囊：车型名（13px + tabular-nums）+ ×（hover 变红）
- 数量变化时新胶囊飞入（FLIP 动画 200ms）
- 末尾固定主按钮（"开始对比" / "开始填报" / "加入大纲"），按上下文变化

### 7.4 列尾状态点（v3 新增）

每个表格行的固定列尾加一个 **8px 状态点**：

| 状态 | 颜色 |
|---|---|
| 正常 | 透明（无点） |
| 已激活 | `#15803D` |
| 必填缺失 | `#B91C1C` |
| 枚举异常 | `#B91C1C` + ⚠ |
| 命名建议 | `#C2410C` |
| 解析中 | `#0F766E` + Spin |

> **价值**：扫一眼能数出"12 条异常"，不用每行读完。v2.0 仅有左缘条 + 文字色，必须读完一行才知道是哪种异常。

### 7.5 空态

- 浅木纹底（`--surface-3`）+ 单色线插画（青墨色 1.5px 描边）+ 一句人话 + 主按钮
- 不引入彩色插画——空态也是中性的

### 7.6 输入控件

- 默认边框 `border-default`，hover `border-strong`
- focus 边框 2px 品牌青（这是 V3 唯一允许的"大面积彩色"瞬态）
- 高度 28px（紧凑）/ 32px（标准）

## 八、交互设计补充（视觉层新增）

### 8.1 反馈分层（与《交互优化设计方案》§4.1 呼应，落地视觉）

| 层 | 触发条件 | 视觉表达 |
|---|---|---|
| **L1 就地** | 行/值变化 | 行高亮闪烁 1 次（青底 8% 200ms）+ 值更新微动画 |
| **L2 行内** | 校验/状态提示 | 行内红字 + ⚠ 图标（不动用全局提示） |
| **L3 卡片** | 区域级错误 | 就地错误卡片 + [重试] 按钮 |
| **L4 notification** | 跨上下文重要事件 | 右下角卡片，5s 自动消失，可悬停暂停 |
| **L5 message** | 一句话确认 | 顶部居中浮层 1.5s，仅成功类 |

> 与 v2.0 / 交互方案 §4.1 一致，v3.0 把 message 限定为"成功一句话"，跨上下文一律 notification。

### 8.2 键盘可达（v3 强化）

| 快捷键 | 上下文 | 视觉反馈 |
|---|---|---|
| ⌘1–7 | 全局 | 切 Tab，被切中的 Tab 标签闪一次（青底 100ms） |
| ⌘F | 当前页 | 聚焦主搜索框，搜索框 2px 青边（已存在，继承） |
| ⌘↵ | 当前页 | 触发页面主按钮，按钮按压反馈（青底加深） |
| ⌘Z | 表格编辑 | 撤销，操作过的行闪一次 |
| Esc | 顶层浮层 | 关闭（antd 自带） |
| ? | 全局 | 弹出速查面板 |

### 8.3 加载 / 空态 / 错误态统一

| 场景 | 模式 | 视觉 |
|---|---|---|
| 区域加载 | Skeleton（保持布局骨架） | 暖灰底占位条，不用整页 Spin |
| 按钮动作 | 按钮自身 `loading` + Spin | 主按钮保持位置不变形 |
| 空列表 | Empty + 一句人话 + 主按钮 | 木纹底 + 线插画 |
| 加载失败 | 就地错误卡片 + [重试] | 红边框 1px + 重试按钮 |
| 解析中（资产） | 行尾 8px 青点 + 进度环 | 不阻断其他行操作 |

## 九、暗色模式

v3.0 暗色基座切换到 **暖深炭**（#1B1714 → #221E1A → #2B2521），保留"工作台在夜间被调到暖色台灯"的隐喻：

| 元素 | 亮色 | 暗色 |
|---|---|---|
| layout | `#FBF8F1` | `#1B1714` |
| container | `#FFFFFF` | `#221E1A` |
| inset | `#F5EFE3` | `#2B2521` |
| 品牌青（亮档文字直接可用） | `#0F766E` | `#5EEAD4` |

> **暗色回归检查**：切换暗色后所有彩色信号（绿/蓝/橙/红）必须保持亮色下同样的语义和注意力权重；不允许出现"暗色下只有蓝色还在工作"的情况。

## 十、分期落地（与 v2.0 不重叠的优先级）

## 十一、验收清单

### 11.1 灰度稿检验
任意页面临摹成灰度，彩色只剩文字/线/点/状态点，状态信息不丢。

### 11.2 一色一义走查
- 青只在"品牌/可交互/焦点"
- 绿只在"已激活徽标"
- 蓝只在"信息/链接"
- 暖色只在"变更/警示"
- 红只在"错误/缺失"
- 标签零彩色

### 11.3 工作集压力测试
- 选中 ≥8 个车型，工作集胶囊条正确显示，可单独移除
- 切 Tab 不丢失工作集状态

### 11.4 列尾点扫读测试
- 故意构造 12 条异常 + 5 条正常的表格，2s 内能数出"12 条异常"

### 11.5 对比度
- 5 色文字按 §4.2 表达标（≥4.5:1 正文 / ≥3:1 辅助）

### 11.6 暗色回归
- 切换暗色后 5 色信号同等可读，无暖白残留

### 11.7 形制
- 圆角仅 6/4/3
- 字号仅 11/13/14/16
- 表格数字列全部 `tabular-nums`

### 11.8 长时间视觉疲劳
- 投标专员场景：连用 6h 后暖白底主观疲劳评分低于冷白底

## 附录 A：v2.0 ↔ v3.0 决策对照表

| 维度 | v2.0「精密量具」 | v3.0「青墨工坊」 | 选择建议 |
|---|---|---|---|
| 概念 | 冷峻仪器 | 温暖工作台 | 看品牌想要"专业感"还是"亲切感" |
| 基底 | 冷灰 slate | 暖白木纹 | 投标专员场景优先 v3 |
| 品牌色 | 工业蓝 | 铜锈青 | 想要差异化记忆点选 v3 |
| 信号色数 | 4 色分工 | 5 色主次 | 4 色更克制、5 色更细腻 |
| 行高 | 32px | 28px | 表格密集场景选 v3 |
| 顶栏高度 | 48px | 40px | 屏幕小时选 v3 |
| 工作集胶囊 | 无 | 有 | 选车型频繁场景必选 v3 |
| 列尾状态点 | 无 | 有 | 长表格异常扫读场景选 v3 |
| 实施成本 | 中（已有色板替换） | 中（色板替换 + 新组件） | 二者相近 |

> **推荐策略**：v2.0 与 v3.0 **二选一落地，不混搭**。如团队投票要差异化品牌 → v3.0；如要最小风险 → v2.0。
